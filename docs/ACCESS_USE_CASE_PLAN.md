# 超声数据访问用例规划

状态：已按 ADR-0011 同步业务访问规划；UC 均非产品运行证据，本次不修改或执行旧代码/测试，具体 API 与实现继续待定。文档职责按 [设计维护原则](DESIGN.md#integration-policy)划分，本文件不新增规范、函数签名、HDF5 路径或性能指标。

需求理由见 [DESIGN.md](DESIGN.md)，样例、独立期望及执行状态统一在 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。下文是访问能力的规划视图，不维护第二套 U 规则或 UC 执行记录。

## 1. 规划范围与追踪

产品访问范围按 [ACCESS-01](DATA_SPEC.md#access-01)、[SNAP-01](DATA_SPEC.md#snap-01)、[MEAS-01](DATA_SPEC.md#meas-01)：原始波形及必要解释、顶层代表/底层来源、规范子集、C 扫快照和文件输入的基础窗口取值。SDK 不提供额外导出或完整分析。以下 Core I/O、Frame/Batch、poll/push 是保留的原始波形工程路径，不等同于整个产品访问模型；新增能力的具体接口及承载待 D-16～D-18。

布局与访问优先级按实际业务确认（D-03/D-17），不把旧 Frame/Batch 优先顺序直接套到全部内容；优先布局不排除其它布局。既有原始 Core 单 Frame 不分块，采用同步读写。按 [ADR-0006](decisions/0006-core-io-and-selection-layer.md)，Core I/O 只按 Scan、Frame/Batch 与流组交付，帧内的流/声束/Tx/Rx/样本选择与 A-Scan 是作用于其结果的纯选择层，下表中这些维度的语义只需验证选择层与 Core I/O 结果的等价。poll 返回 SDK 管理的只读借用视图，push 复制到调用者指定缓冲。分析结果随元信息返回；Batch 可用于 GPU 上传，这两种用途不与 poll/push 绑定。波形按 STA-01 随单一有效性位图交付，无效槽位零填充；失败机制、Batch/位图布局及错误码仍待 D-05/D-08/D-10。

### 业务访问与原始 Core 的区别

浏览已有 C 扫快照、选点取 A 波形、区域批量读波形/基础取值、B/D/S 等布局批量读取、分批遍历整次扫描均已列为重点场景；不作相互排序或同等速度承诺，见 ACCESS-01/D-03。这是业务用途，不是具体存储布局方案。

| 业务场景 | 已确认行为及边界 | 后续追踪 |
|---|---|---|
| 三种保留模式重开 | 按实际保留内容提供能力；仅特征不虚构波形，有来源关系不等于保留来源波形 | RET-01；UC-20 |
| 无位置或位置失败 | 不造零坐标，位置异常保全有效波形，位置状态不冒充波形无效 | POS-01；UC-21 |
| 模式及曲面解释 | 参数与必要几何解释已有数据，不恢复扫描工程，不加载激光点云 | REL-01；UC-22，D-09/D-11 |
| 选点取波形 | 底层实际保留 0～N 条及来源；顶层限已选定同类观测且只选有效波形，无有效候选不兜底 | ACCESS-01；UC-23，到达环节及最终顺序待 D-17 |
| 快照读取与写入 | 读取不重算，新增/指定替换及另目标写入；原始不变，失败保留旧成果 | SNAP-01；UC-24，D-16 |
| 区域基础取值 | 文件输入、逐点数值/状态；前沿成对返回同一点的位置/时间与幅值，不做转换或隐式保存 | MEAS-01；UC-25，判据等待用户算法参考 |
| 区域与复检来源 | 扫描关联目标区域，复检/局部重扫可指向原扫描具体区域；区域信息的具体范围暂缓 | REL-01/SCAN-02；UC-18，D-11 |
| 规范数据子集 | 扫描、空间区域、通道/声束/收发组合及样本窗口；保留必要解释与来源，不附带额外导出 | ACCESS-01；UC-26，具体选择待 D-17 |

顶层/底层是业务访问分层，不与 Core I/O/纯选择层一一对应；基础取值不开放任意内存波形输入。当前只更新规划，未定义上述新接口或宣称实现完成。

## 2. 公共请求与结果的逻辑契约入口

一次 Core I/O 请求由明确的 Scan、单 Frame 或 Batch 的 Frame 选择及流组构成，帧内输出与样本选择在其结果上进行；目录、固定定义和元信息可独立访问。这是概念组成，不是正式 request 类型，Batch 起点/数量或离散选择语法未冻结。

先明确选择 Scan，不默认“最新”或第一个扫描。Batch 在同一 Scan 内读取多个 Frame，不拼接不同 Scan、不重采样或筛除旧数据；各自身份和解释保持独立。用途/区域及跨 Scan 映射待 D-11；Scan 枚举接口仍见 D-10。

| 选择维度 | 公共含义 | 契约入口 |
|---|---|---|
| Scan | 文件内枚举/明确选择；区域/来源/坐标映射能力待决策 | SCAN-01、READ-01；待定 SCAN-02/D-11 |
| Frame | 单索引或一次 Batch 读取多个 Frame；具体批次选择语法待定 | CORE-01、READ-01/03 |
| 流组 | Core I/O 的交付单位；组内稠密 `[B,K_g,S_g]` 样本及 `[B,K_g]` 位图，跨组容器待 D-10 | 逻辑模型、READ-03 |
| 波形流（选择层） | 组内指定流或流清单，事件与接收输出静态可追溯 | 逻辑模型、WAV-01 |
| PA 声束 | 束身份映射到正确事件/输出，关联唯一帧位置与固定几何/法则 | PA-01 |
| FMC Tx/Rx | 全矩阵、行、列、有序交叉子矩阵或显式配对 | FMC-01/02 |
| Sample | 全波形、样本范围/有序清单，或给定逐流/逐对选样；清单保序保重复 | READ-02 |
| 有效性与位置 | 波形附带对应有效性位，无效槽位零填充、不跳过；绑定读带适用的位置及状态，无位置记录不伪造坐标；独立读取仍可核对来源 | STA-01、POS-01、READ-01 |
| 元信息与帧级附加记录 | 公共描述＋带类型/版本内容；位置描述 Scan 内固定，每帧一份值；时间戳、来源 ID、额外坐标等以帧级附加记录按帧关联 | META-01、POS-02；具体返回容器待 D-10 |

结果必须足以识别所选 Frame、流或束/Tx/Rx 轴、状态及必要固定定义来源。并不要求每个结果逐份复制定义内容；可交付可核对引用。异构返回有身份的数组集合/波形矩阵或分组结果，不能用单一 ndarray 作为全部模式的强制结果类型。

单 Frame 内样本半开区间、有序输出/样本清单及逐流边界引用 [READ-02](DATA_SPEC.md#read-02)。Batch 须保留声明的帧顺序，不从已有样本清单语法反推任意 Frame 清单已支持。输入校验报告、空选择及负索引等细节待 D-10；每次 Core I/O 调用失败须遵守 IO-01，不能以逐项错误交付部分成功。

### 两种关联交付

| 方式 | 用途与已定边界 | 仍需细化 |
|---|---|---|
| 分析读取 | 数据随关联元信息、位置/状态返回，便于常规分析；结果只读 | 元信息选择、容器和共享引用形式 |
| Batch 消费 | 一次同步读取同一 Scan 的 B 个 Frame，可借用 poll 视图或 push 到调用者缓冲供上传 GPU；样本＋有效性位图，无效零填充，保留范围/类型/布局及身份说明 | Batch 选择、同构排列、异构缓冲/偏移、位图布局 |

内容交付与内存所有权是两个维度：分析/Batch 均不限定为某一种缓冲模型。相同选择通过 poll/push、分析/Batch 或单 Frame/A-Scan 读取须数值和关联一致，不创建第二份可修改事实。

### poll/push 缓冲模型

| 模型 | 同步操作及所有权 | 失效/复用边界 |
|---|---|---|
| poll | 消费者发起读取，SDK 从文件读取/必要时解码到 SDK 内存，返回只读借用视图 | 同一 Reader 下次样本读取开始（poll 或 push，包括失败与参数被拒绝）或 Reader 关闭时旧视图失效；目录/元信息/容量查询不影响；调用者不释放它 |
| push | SDK 将结果同步复制到调用者指定指针及容量内 | 调用者管理缓冲；关闭 Reader 不释放它，对其他缓冲读取不影响它，复用同一目标会覆盖内容 |

poll 不是直接解引用磁盘偏移或轮询状态，push 不是后台推送。主机指针不承诺 mmap、固定页、零拷贝或 GPU 解压。GPU 异步上传结束前，poll 不得在同一 Reader 上发起下次样本读取或关闭 Reader，push 不得复用/释放目标；双缓冲流水线用 push 或两个 Reader。生命周期以 [BUF-01](DATA_SPEC.md#buf-01) 为准。

## 4. TFM 与其他离线算法的消费边界

TFM 可消费单 Frame 或 Batch 的完整矩阵输入，再按 Tx/Rx 和调用者给定的逐对选样表取样。访问层提供可追溯数据，不负责传播时间、声速模型、定位或重建；Batch 读取不引入算法级跨帧配准。

- 优先规划输入块读取、块内选样及重复消费，而非“每个像素一次磁盘 I/O”。
- 稠密数值视图不代表共同物理时间轴；采样解释不同必须保留差别。
- 样本与有效性位图一起消费；无效槽位的零填充不是真实零信号，算法处理策略由消费者明确，不依赖已被忽略的无效输入内容。
- Tx/Rx 不是工件空间网格，派生图像不能替代或覆盖原始波形。
- 实时显示走采集内存；本规划面向封存文件，异常文件仅显式只读恢复。

本轮仅规划 Q 选样表的已知结果，不验证 TFM 算法或性能。

## 5. 读取结果与错误的待定边界

矩阵读取不得以全扫描驻内存为前提。调用者以 Batch 大小控制容量，但单 Frame 不分块。分析/Batch/单帧等价选择须保持结果与关联；小样例只验证正确性，不证明资源或上传性能。

push 的目标归调用者，I/O 失败保持样本、有效性位图及关联目标逐字节不变；poll 的 SDK 缓冲属于借用，失败不发布部分新结果，先前视图也不因本次失败而延长有效期。两者整个调用失败均报告原因/错误码。已知无效槽位正常交付零填充和无效位；不能把 I/O 错误转换为无效位或仅返回零数组。

| 情况 | 规划中的处理 | 不允许的处理 |
|---|---|---|
| 选中流样本越界 | 明确指出越界流与范围；请求级或逐项错误形式待 D-10 | 静默截断、补零或伪装完整成功 |
| `valid=1`，包括真实全 0 | 返回原始样本和有效位，接受调用者声明 | 因全 0 改成无效，或增加业务合法性判断 |
| `valid=0` | 返回零填充和无效位，不要求保留输入样本，不跳过槽位 | 把填充值当真实测量、丢弃槽位，或用波形位抹去其它内容状态 |
| 必要引用/结构损坏 | 报告结构或关联错误 | 缩短正常扫描或改成无效位 |
| 未支持编码/filter/选择 | 报告不支持及可用受限范围 | 返回错误数值或计为 PASS |
| 解码/I/O 失败 | 整个调用失败给原因/错误码；push 目标不变，poll 无部分新视图且旧借用已到期 | 部分成功、改写 push 目标、使用到期 poll 视图或转成无效位 |

有效性位图的具体容器/打包、Batch 布局及错误码见 D-08/D-10；单一有效性和零填充语义已定，不恢复旧双维状态。写入无取消、普通写入不立即落盘、Flush 的成功后条件已定（WRT-03，只覆盖进程崩溃），机制见 D-05。poll SDK 缓冲及 push 两阶段读暂存均计入有界资源预算，不承诺全链路零拷贝。
