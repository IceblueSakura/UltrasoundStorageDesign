## 1. 当前可核对的证据

现存[常规结果](../archive/benchmarks/ultrasound_storage_baseline/benchmark_results/results.json)有 56 个候选配置，[10× 结果](../archive/benchmarks/ultrasound_storage_baseline/benchmark_results_10x/results.json)有 32 个候选配置。两组 CSV 与 JSON 的写入吞吐、压缩比、批读/全读/gate 中位延迟已逐项核对一致。它们都是合成输入、C=4、u16、S=2048/8192，并不覆盖产品的完整参数范围。

脚本和结果统一位于 `archive/benchmarks/ultrasound_storage_baseline/`。原始 JSON 中的 `args.out` 等路径保留历史运行时值，不随归档改写；目录移动不补足历史环境证据。

JSON 记录 Linux x86_64、Python 3.13.15、h5py 3.16.0、hdf5plugin 7.1.0，时间分别为 2026-10-06T09:53:51Z 和 2026-10-06T10:12:23Z。历史报告另曾标注 Xeon Platinum 8573C、HDF5 2.2.0、c-blosc2 2.23.1、python-blosc2 4.1.2，但当前 JSON 没有记录这些实际运行信息，不能仅凭开发环境配置补证。

### 1.1 参数与统计口径

| 参数 | 常规结果 | 10× 结果 |
|---|---|---|
| T / C / dtype | 1024 / 4 / u16 | 10240 / 4 / u16 |
| S | 2048、8192 | 2048、8192 |
| 目标 chunk | 512 KiB | 5120 KiB |
| 写入 / 读取批量 | 64 / 64 | 640 / 640 |
| 波形缓存总预算 | 16 MiB | 128 MiB |
| codec 集合 | 包含 Zstd 默认 level 2、Delta、无压缩等 | 包含 Zstd level 1、BloscLZ；无无压缩对照 |
| 写入重复 | 3 次 | 3 次 |
| 读取采样 | 批读 32 次，全读/gate 各 4 次，遍历 3 次 | 同左 |

这是多项参数同时改变的实验，不是只将数据量扩大十倍的单变量实验。“3 轮中位数”适用于写入和遍历，不能描述为所有读取均独立执行了三轮。

### 1.2 已核对的关键对照

以下数值直接对应当前 JSON/CSV，写入单位 MiB/s，读取单位 ms：

| 结果组 | S | 布局 / chunk / codec | 写入 | 单通道全读 | gate |
|---|---:|---|---:|---:|---:|
| 常规 | 2048 | CTS / full / bitshuffle_lz4 | 1470.0 | 0.107 | 0.021 |
| 常规 | 2048 | SPLIT / full / bitshuffle_lz4 | 959.9 | 0.106 | 0.020 |
| 10× | 2048 | CTS / full / blosc2_lz4 | 635.2 | 2.753 | 12.068 |
| 10× | 2048 | SPLIT / full / blosc2_lz4 | 682.6 | 7.975 | 6.348 |
| 10× | 8192 | SPLIT / full / blosc2_lz4 | 1047.6 | 62.208 | 57.588 |
| 10× | 8192 | SPLIT / sample / blosc2_lz4 | 378.2 | 53.758 | 5.917 |

可以得出：

- SPLIT 可作参考实现，但不能声称与 CTS 始终只差 1%～2%。上表一个全读对照的延迟相差约 2.90 倍，原因仍需隔离实验。
- 样本轴切块有利于该窄门场景，但同时使该写入对照只保留约 36% 的吞吐；不等于应该一律采用样本切块。
- Bitshuffle 类组合值得验证，但没有冻结 codec、级别、chunk 或生产吞吐的证据。

常规历史表中的 Bitshuffle + LZ4 写入 1123.4/1212.8 与现存 1470.0/959.9 不一致；历史表还列出常规 Zstd level 1，而常规结果保存的是默认 level 2。对应的其他运行记录当前不可追溯，不能将历史表和现存数据当成同一轮结果。

旧六布局 `benchmark.py` 的原始结果目录当前缺失，故本轮不重新确认其历史性能数字。新旧脚本的输出目标不同，不能直接拼接成同一组布局排名。

## 3. 方法限制与尚未验证的结论

### 3.1 缓存、chunk 与批量互相影响

校验在同一读取句柄上先完整读取波形，性能测试已受预热影响；未清除 OS 缓存。10×、S=2048 时每通道 40 MiB，CTS 单 dataset 缓存为 128 MiB，SPLIT 每通道仅 32 MiB；总预算相等不等于活跃通道可用缓存相等。

10×、S=8192 的 SPLIT LZ4 full/sample 对照分别是 `[320,8192]` 和 `[2560,1024]`，写入批量均为 640。样本切块也改变 trigger 轴长度和填满 chunk 前的 flush 次数，因此写入差异不能全部归因于样本轴切块。

新基准候选顺序固定；全读/gate 样本少；不保存读取原始计时和请求序列。部分候选三次写入的最大/最小耗时之比超过 3，不能用中位数掩盖波动或声称 p95 已代表生产尾延迟。

### 3.2 数据、压缩与环境不能外推

- 输入是合成 RF，不是实际设备波形。u32 代码路径和 512～32768 的更广范围不是现存结果的验证范围。
- Bitshuffle 重排比特以改善编码器对规律的利用，不降低原始信息熵。Delta 在该输入上的劣势不是对所有真实 RF 的结论。
- 当前代码与现存结果未提供 Delta + Bitshuffle 组合实验，旧报告的 1.44× 比较不可追溯。
- `hdf5plugin.Bitshuffle` 是第三方 filter 路径，不是“零依赖”。GPU 支持某 codec 也不等于可解码完整 HDF5 filter 封装。
- 压缩比以逻辑波形字节除以整个文件大小计算，含元数据等开销，不是纯编码器压缩率。
- 写入计时含重排、resize、两次每批 flush 和 close，不含 fsync；读取含分配、选择及缓存影响。二者都不是单独的磁盘或 codec 测量。
- 当前 JSON 缺脚本哈希、实际 HDF5/codec 运行版本、线程参数、文件系统与磁盘信息，无法严格绑定代码和运行环境。

### 3.3 正确性与生产能力缺口

旧 `benchmark.py` 包含严格输入负例、提交计数/配置检查及逐请求比对。新压缩基准只做完整波形和状态回读，没有等价的输入拒绝、提交计数、配置或批读/gate 逐请求校验；全部状态为 3。不能把旧基准检查结果转移给新脚本。

两者都没有实现共享位置绑定、完整参数快照、封存约束、异常只读恢复、真实设备持续输入或超 RAM 流式处理。新脚本的 `--overwrite` 未用于覆盖保护，是已知工具风险；本轮只记录，未修复。

因此当前证据不证明超过 100 GB 的生产可用性、端到端不丢数据、持久化或 GPU 解压。在线文件读取已明确不属于首版目标，不再把并发 writer-reader 性能当成首版冻结条件。

后续先补可追溯性、契约正确性和流式测试，再开展真实数据、控制变量、持续写入及故障注入。范围与理由见 [DESIGN.md](DESIGN.md)，待定项见 [Spec 登记表](DATA_SPEC.md#open-items)，规则覆盖与执行状态见 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。历史微基准通过不等于这些测试已执行。

## 4. 手动复跑现存 10× 参数的命令

脚本为[归档压缩基准](../archive/benchmarks/ultrasound_storage_baseline/benchmark_single_channel_compressed.py)。以下从仓库根目录运行，补齐原结果的 640 写/读批量；不是生产默认配置，也不保证重现旧环境。输出放到 `experiments/runs/` 的新专用目录，不写回归档。必须先确认目标不存在，因为当前脚本不执行覆盖保护。本轮未运行此命令。

```bash
# 手动复跑；结果目录必须不存在，不能覆盖已有实验或真实数据
nix develop --command python3 archive/benchmarks/ultrasound_storage_baseline/benchmark_single_channel_compressed.py \
  --samples 2048,8192 \
  --triggers 10240 \
  --channels 4 \
  --dtype u16 \
  --write-batch 640 \
  --read-batch 640 \
  --target-chunk-kib 5120 \
  --cache-mib 128 \
  --codecs blosc2_lz4,blosc2_zstd_l1,blosc2_blosclz,bitshuffle_lz4 \
  --architectures CTS,SPLIT \
  --repeats 3 \
  --out experiments/runs/benchmark_results_10x_new
```
