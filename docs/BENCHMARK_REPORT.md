# 历史 benchmark：证据局限

状态：**历史探索，不是生产性能基线、格式符合性证据或当前选型结论。**

本轮为扫描/算法审计精简了报告，移除数值排名、压缩率表格和复跑命令，避免未经控制的结果继续主导设计。没有重跑实验，也没有据此断言所有原始测量都错误；现有证据不足以支持其产品外推。

## 1. 保留的结论只有证据边界

| 局限 | 不能据此得出的结论 |
|---|---|
| 输入是合成 RF，参数范围有限，没有真实设备持续输入 | 产品压缩率、实际吞吐、设备端不丢数据 |
| 完整回读预热、OS 缓存未受控，SPLIT/CTS 活跃通道可用缓存不同 | 冷盘带宽、纯解压速度或布局的普遍优劣 |
| 扩展实验同时改变数据量、chunk、缓存、批量及部分 codec；采样和原始计时不足 | 单因素因果、稳定尾延迟或生产默认值 |
| 部分历史汇总与现存结果不一致；缺少完整脚本/运行库/存储环境绑定 | 严格可复现的性能基线 |
| 写入含重排、resize、flush、close，不含 fsync | 持久化带宽、断电零损失或确定恢复窗口 |
| 缺完整位置、参数快照、封存/恢复契约及等价的逐请求校验 | 生产 SDK 能力或 Spec 符合性 |
| 源数据全量驻留内存，没有从实际 filter 表示完成 GPU 解压 | 超 RAM 单文件验证或 GPU 解压能力 |

SPLIT/CTS/TCS 只是适用工作负载的物理实验对照，压缩组合只是可探索候选，不是公共 schema 的强制映射或当前生产默认值。真实场景可能改变访问权重，不能反过来为了配合脚本而改变需求。

## 3. 什么证据足以重新讨论性能

先完成[场景与算法审计](SCENARIO_AUDIT.md)，明确输入速率、实际选择、输出布局、内存预算和延迟目标。再按[验证计划](SPEC_TEST_PLAN.md)建立：

1. 可独立核对的 Frame/流/原始位置/固定定义及 PA/FMC 选择样例。
2. 真实波形与不可压缩输入对照，有界内存的流式工具。
3. 固定工作负载的控制变量实验、明确缓存状态、完整环境和原始请求/计时记录。
4. 持续写入、超过 RAM 的访问与故障注入证据；CPU 解码与可选 GPU 完整链路分别验证。

上述均是未来验证条件，不是本轮已经完成的测试。
