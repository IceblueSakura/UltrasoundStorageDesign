# 超声采集数据 Spec 0.1-draft

状态：初版数据契约草案；不是冻结的二进制格式，也不是已实现 SDK 的符合性声明。

需求与架构理由见 [DESIGN.md](DESIGN.md)，验证方法见 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。本文是数据语义、不变量和参考映射的唯一规范来源；基准结果与候选目录不能修改本文契约。

面向实际扫描与算法的阅读路线见 [SCENARIO_AUDIT.md](SCENARIO_AUDIT.md#5-设计细节的阅读路线)。该文档用于收集证据和检查本契约的适用性；审计问题、候选场景和算法举例不自动升级为本文的确定规则。本轮整理未更改下列规则或 D-01～D-10 的状态。

## 1. 规范状态与适用范围

<a id="doc-01"></a>
### DOC-01：规范状态与声明边界〔确定〕

本文使用以下标记：

| 标记 | 含义 |
|---|---|
| 〔确定〕 | 已确认需求及其在当前架构下的必要契约；“必须/不得”具有约束意义 |
| 〔参考〕 | 用于样例和实现探索的候选映射/行为；选择采用时按该规则验证，但不等于产品格式已冻结 |
| 〔待定〕 | 尚无正式决定；实现不得把临时值描述为本 Spec 的规定 |

未带规则编号的示意、说明及机制讨论不增加新的强制要求。本文中的“支持”描述实现目标，不是现有脚本能力。

适用范围为常规、同构通道、共享触发和记录轴的采集。一个 Session 对应一个独立、自解释的 HDF5 文件；样本布局变化时新建文件。PA/FMC、独立通道流、异构或动态变长通道、分卷、在线文件读写、overlay 合并不在本版范围。

`0.1-draft` 是文档版本，不是已分配的 HDF5 `schema_version` 字面值。草案修订之间不自动承诺文件兼容。实验文件及测试报告必须能追溯到所用 Spec 修订（例如文档哈希）、实现版本和测试专用编码；具体落盘标识留待 D-07。旧微基准文件不能因为可以读取就被重新标为本版合规。

当前允许报告“某些确定规则已验证”或“采用指定参考映射的实验样例通过”。位置编码、身份编码等必要项未闭合前，不得宣布完整生产文件格式符合性，也不得声称独立读取器无需额外实验说明即可互通。

## 2. 术语与逻辑模型

| 符号/术语 | 含义 |
|---|---|
| `T` | `committed_count` 声明的完整记录数量；不是所有 dataset 的物理长度 |
| `t` | 文件内零起点记录索引，完整前缀为 `0 <= t < T` |
| `C` / `c` | 初始化固定的通道数及通道索引 |
| `S` / `s` | 初始化固定的每通道样本数及样本索引 |
| `K` / `k` | 完整参数快照数量及快照索引 |
| `E_x` | 某个记录相关数据对象的物理 extent，可大于 T |
| `T_r` | 恢复视图验证出的完整前缀长度，不等于声明值一定正确 |
| trace / TriggerRecord | 一次触发的通道波形集合、共享位置、状态和关联元数据 |
| waveform / AScan | 一条记录中一个通道的固定长度样本序列 |

```text
Session
  ├─ 固定布局与解释描述
  ├─ TriggerRecord
  │    ├─ waveforms[C,S]
  │    ├─ status[C]
  │    ├─ shared_acquisition_position
  │    ├─ config_index
  │    └─ 可选 source_trigger_id / 诊断时间戳
  └─ 参数快照与可选辅助块
```

<a id="rec-01"></a>
### REC-01：共同记录身份〔确定〕

所有通道必须共享同一触发的记录身份和位置关联。采集层一次提交完整记录或完整记录批次，SDK 不接收分通道追加后等待拼装，不进行时间配准。来源 trigger ID 与文件索引是不同概念，不得据前者隐式创建网格或时间同步关系。

设备 ID 的回绕、跳号、重复如何描述仍属 D-02；本版不规定遇到跳号自动补空记录。完整提交边界也不等于缺 payload 写入 API 已确定，见 D-08。

<a id="rec-02"></a>
### REC-02：计数、extent 与边界〔确定〕

T 的逻辑编码范围为 u64；索引 t 的合法性由记录数量决定。实现必须分别检查计数、索引、切片及字节长度运算，不得静默截成 32 位、溢出或把不支持的尺寸当作空选择。

实现支持上限可以低于 u64 编码上限，但必须明确报告。HDF5 的特殊尺寸常量、绑定层整数范围和内存数组限制不能直接冒充普通记录数量。

物理 extent、填充值和完整记录数量必须区分。正常读取不得暴露 `t >= T` 的尾部；若必要对象在前缀内缺行或关联不完整，应报告结构错误，不能静默将正常文件缩短后继续宣称完整。

## 3. 身份、版本与能力

<a id="id-01"></a>
### ID-01：解释身份〔确定〕

文件必须携带可识别的容器格式与 schema 身份、Session 身份、采集 profile 身份和物理布局身份。它们分别回答“哪套公共约定”“哪个扫描”“记录是什么”“数据如何组织”，不得混用。

读取器在不理解必要 schema/profile/layout 语义时必须拒绝相应解释，不能按路径相似程度或当前设备默认值猜测。精确字段字面值、字符串编码、版本比较与兼容范围留待 D-07；不预设“同一主版本必兼容”。

<a id="id-02"></a>
### ID-02：必要能力与可选扩展〔确定〕

必须区分影响当前请求解释的必要信息和可以忽略的可选辅助块。未知可选辅助块可以跳过；未知必要语义、编码或 filter 不得静默忽略。

如果只是不支持位置编码、但仍能独立验证波形及记录范围，可以显式提供受限波形访问；必须报告位置/绑定读取不可用，不能伪造位置或宣布完整 profile 合规。若连记录边界也无法验证，则不能以此降级。

扩展须具有格式标识、版本、必要类型/单位、来源与关联说明。能力声明的具体编码属 D-07。未知状态位的处理见 STA-01。

## 4. 波形、状态、位置与参数

<a id="wav-01"></a>
### WAV-01：固定布局与自解释〔确定〕

初始化后的 C、S、样本 dtype、通道顺序/身份以及采样轴定义不可改变。增益等非布局设置可以关联参数快照，但不得通过动态快照偷偷改变采样布局。

布局描述必须足以说明该实例的样本表示和样本轴：类型、字节序、样本的含义与必要单位、通道映射，以及把样本索引解释为采样位置/时间所需的信息。若有效 ADC 位、对齐、偏置或比例对解释不可缺少，也必须描述；不要求所有设备采用同一组 ADC 字段。

实际 dtype 集合、原始整数码/物理量的具体表示和轴参数编码仍属 D-02/D-07。不得仅保存某个本地驱动函数名来替代解释。

<a id="wav-02"></a>
### WAV-02：严格接收与无损保存〔确定〕

每份存在的 waveform 必须与初始化 shape、dtype 严格一致。SDK 不自动截断、补齐、广播、重采样或数值转换；调用者声明无效不豁免这些约束。输入内存布局和所有权属 D-02，不预设零拷贝或 TCS 输入。

已接受的样本必须无损回读，整数样本逐值一致。字节序不同的表示不能被直接当作原始字节相同；浮点 NaN、负零等逐位保真规则须在该 dtype 被纳入支持范围前补齐，不能先声称任意类型均受支持。

<a id="sta-01"></a>
### STA-01：槽位状态〔确定〕

状态逻辑类型为 uint8，含义为：

| 值 | PAYLOAD_PRESENT（bit 0） | CALLER_VALID（bit 1） | 含义 |
|---|---|---|---|
| 0 | 0 | 0 | 无 payload，不得将物理填充值解释为回波 |
| 1 | 1 | 0 | 有 payload，调用者声明业务无效 |
| 3 | 1 | 1 | 有 payload，调用者声明业务有效 |

值 2 不合法。本版只定义 0、1、3；其他值不可当作其中一种，也不可屏蔽未知高位后继续宣称本版语义成立。业务质量扩展另行描述。

调用者必须明确声明有效性，SDK 管理 payload 存在性。读取必须保留相关状态，不能静默丢弃值 1 的波形。结构损坏、解码失败不能降格成调用者无效。状态 0 的语义保留，但首版是否接收缺 payload 的记录尚待 D-08；本版不增加晚到补写功能。

<a id="pos-01"></a>
### POS-01：采集时位置绑定〔确定〕

每条完整记录必须具有明确的共享采集位置关联，全部通道使用同一关联。绑定基于记录身份，不依赖时间戳、浮点坐标相等或最近邻搜索。

绑定读取必须对波形、状态与位置使用同一记录选择及对应顺序。位置是采集时写入的历史值，不得被后处理或 overlay 静默替换。采集层负责物理同步准确性；SDK 只验证可表达的结构与关联，不进行插值或校准。

“存在位置关联”不预先决定无效位置是否允许及如何表示，见 D-01。不得用零坐标替代尚未定义的缺失位置语义。

<a id="pos-02"></a>
### POS-02：位置描述边界〔确定〕

位置描述必须足以解释具体实例的字段、类型、必要单位、轴/参考对象、来源及结构版本。允许多字段，但不预设 XYZ、四元数、编码器轴数或具体物理 shape。

独立反馈流可以作为辅助数据保存，但不得要求通过时间配准才能恢复本 profile 的记录位置绑定。绑定位置不等于已定义扫描网格；没有明确拓扑或调用者映射时，不承诺自动恢复 B/C/D 排列。具体位置编码与有效性仍为 D-01。

<a id="par-01"></a>
### PAR-01：参数和固定解释分离〔确定〕

每条完整记录的配置引用必须指向已完整保存的快照，逻辑上满足 `0 <= config_index < K`。已关联历史的快照不得被原地覆盖；配置变化使用新快照关联后续记录。

固定采样轴、通道身份、样本解释和位置描述不得只隐藏在可变快照中。参数领域 schema、逐记录/逐通道生效粒度、空配置表示和索引物理类型属 D-09；已有实验的全零配置列不等于存在合法快照。

<a id="par-02"></a>
### PAR-02：参数字节区的候选编码〔参考〕

采用 `data[U] + offsets[K+1]` 时，offsets 表示字节偏移：

- `offsets[0] = 0`，各值非负、非递减，最后一项为有效字节长度 U。
- 快照 k 对应半开字节区间 `[offsets[k], offsets[k+1])`。
- 每个引用的区间均须在有效 data 范围内，并可按声明的参数编码解释。
- offsets 相等仅表示空字节区间，不自动证明该快照语义合法。

物理预分配尾部不属于 U，如何存储 U、offsets 宽度与序列化编码仍待定。不得把“全部读成 JSON”当作正式决定。

waveform dataset 可从 `(0,S)` 增长，候选 maxshape 为 `(None,S)`。初始化不要求知道最终 T。chunk/filter 参数在创建时明确，但本版不分配生产默认值。

CTS/TCS 是实验对照，不因此成为本版每个读取器都必须实现的布局。切换布局不得改变记录语义或无损要求。

## 6. 写入和生命周期

<a id="wrt-01"></a>
### WRT-01：提交校验与阻塞行为〔确定〕

一个单写者按完整记录/批次追加。SDK 必须在修改 extent 或推进前缀之前完成提交单元的结构校验；校验失败不改变逻辑记录数量、相关 extent 或已提交数据。

写入慢时允许阻塞，不主动丢弃已交付数据或静默跳过记录。I/O 错误必须报告并停止正常追加，不能当成输入校验失败后无条件重试。具体异常类型、取消与重试语义、缓冲复用时机属 D-02/D-05/D-10。

上述要求不保证设备在调用者阻塞期间不会溢出，也不保证崩溃后零损失。端到端不丢数据还需设备停采/暂存契约及持续负载测试。

<a id="wrt-02"></a>
### WRT-02：完整前缀与不可变历史〔确定〕

在正常写入流程中，T 单调不减。推进前缀前，相关波形、状态、位置和参数依赖必须完成写入及选定的 flush 步骤。已提交记录和其历史解释不得原地修订或晚到补写。

这是逻辑顺序，不是跨 dataset 事务保证。后续追加可能改写包含旧数据的未填满压缩 chunk。调用返回、flush、设备持久化和最终封存不能互相等同；精确确认点、flush 周期、状态更新顺序及故障后的可恢复数量仍属 D-05。

<a id="lif-01"></a>
### LIF-01：正常封存与读取〔确定〕

逻辑生命周期包括初始化、追加、正常封存及故障/未正常关闭；状态字节编码未定。正常封存需完成必要数据/关联检查、前缀核对和所选关闭流程。

普通读取面向已封存文件，常规追加入口必须拒绝修改已封存文件。实时显示走采集内存，不要求读取增长中的文件或实施 SWMR。正常文件若不能满足必要结构和引用约束，应明确报错，不得自动当成有效的较短扫描。

<a id="lif-02"></a>
### LIF-02：尽力只读恢复〔确定〕

未正常关闭的文件通过显式恢复模式处理，不伪装成正常封存：

1. 只读尝试打开，失败时报告，禁止为打开而自动修复原文件。
2. 检查可读取的前缀、物理范围和必要关联；不把填充值或可解码字节自动认作完整记录。
3. 如果可建立可信完整前缀，则暴露验证范围 T_r；只有声明的 T 本身可验证时，才可以将其作为上界依据。前缀标记缺失/不可信时，不凭各 extent 最小值猜测恢复数量。
4. 报告声明范围、验证范围、失败对象及未执行检查；结构可读与逐样本完整性验证须区分。
5. 不原地续写、修复或截断源文件。超出可信前缀的抢救、前缀标记损坏后的重建策略留待 D-05。

HDF5 元数据损坏时可能无法打开。恢复目标是尽力，不预设最大损失时长，也不承诺某个 flush 前的数据必然存在。不能将不完整尾部或损坏记录改成 `CALLER_VALID=false` 来掩盖故障。

## 7. 读取语义与规模

<a id="read-01"></a>
### READ-01：独立和绑定访问〔确定〕

SDK 提供波形、位置的独立访问以及绑定访问；具体函数签名不属于本文。波形访问返回对应状态，不强制解码位置，但须满足 ID-02 的受限访问条件。单独读取的结果必须仍可识别记录对应关系。

绑定访问按 POS-01 保持关联，不静默过滤业务无效波形、不重新按时间匹配、不以 overlay 替换历史位置。一个请求无法满足时必须显式报告，不以空数组或零位置伪装成功。

<a id="read-02"></a>
### READ-02：选择行为候选〔参考〕

为下一阶段样例采用以下候选规则；它们尚未冻结 SDK API（D-10）：

- 记录/样本范围使用半开区间 `[start,stop)`，合法空区间返回有明确形状的空结果。
- 负索引、逆序区间及越界范围显式拒绝，不采用隐式截断。
- 显式索引集合按输入顺序返回，保留重复项，例如 `[2,0,2]`；可内部排序读取，但须恢复输出顺序。
- 通道选择保留可识别的通道映射；全通道拼装是显式操作，不强制所有下游使用 `[B,C,S]`。

不支持某种选择时应报告不支持；不能宣称已经实现本候选再静默去重/排序。读取器是否必须实现任意索引集合尚待接口设计决定。

<a id="cap-01"></a>
### CAP-01：超 RAM 访问〔确定〕

目标是超过 100 GB 的单文件，T 仍在 u64 范围内。写入缓冲和读取缓存必须有界，不随总 T 线性增长；波形、位置、状态、配置均须允许分批访问。正常打开不要求扫描全部波形，深度检查单独执行。

大选择可以分批输出，不能要求整个通道同时物化为内存数组。内存预算、性能门槛和具体迭代 API 留待 D-02/D-03/D-10，不在此设定数值。只通过小文件测试不能声明本条规模目标已验证。

## 8. 压缩与解码

<a id="cmp-01"></a>
### CMP-01：无损与依赖可识别〔确定〕

压缩用于降低磁盘流量与长期容量，必须满足 WAV-02。文件的有效 filter 编码链和必要参数必须可识别，读取端可以部署第三方 filter；缺少解码器或不支持参数时明确报告，不能回退为错误数值。

不固定 codec、级别、chunk、线程或缓存参数（D-04）。“具有 filter ID”不表示所有 HDF5 安装均自带解码器。生产带宽规划不得以当前合成数据压缩率作为不可压缩输入仍不丢数据的证明。

<a id="cmp-02"></a>
### CMP-02：GPU 可选能力的声明〔确定〕

CPU 可读路径是基础，GPU 解压是待验证的可选能力（D-06）。声称 GPU 解压时，必须验证从实际存储的压缩表示到样本的完整链路，包括封装、压缩块、预处理逆变换、尾块及存在的校验。

主机先解压再 H2D 不属于 GPU 解压。缺少 GPU 不影响基础 CPU 读取符合性；GPU 厂商、库、输出顺序和性能阈值不在本版指定。

## 9. 符合性检查与错误解释

<a id="val-01"></a>
### VAL-01：分层、可追溯的验证报告〔确定〕

检查必须区分文件错误、不支持的能力、普通业务无效以及尚未验证：

| 层次 | 检查对象 | 不足以证明什么 |
|---|---|---|
| 识别 | schema/profile/layout、必要能力、解码依赖 | 不证明数据完整 |
| 结构 | 类型、shape、固定布局、状态与声明长度 | 不证明全部字节已正确落盘 |
| 关联 | 完整前缀、共享位置、参数引用 | 不证明物理位置准确 |
| 深度 | 分批解码、内容比对/已定义的完整性校验 | 不自动证明抗断电、性能或设备不丢数据 |

测试记录至少包括 Spec 修订、采用的参考映射/临时编码、输入样例、规则编号、检查层次、执行结果和未覆盖项。结果可以表达 PASS、FAIL、NOT_RUN、BLOCKED、UNSUPPORTED 等含义，但正式错误码与报告序列化格式未定。

待定编码造成的 BLOCKED、选择未实现的 UNSUPPORTED、未执行的 NOT_RUN 都不得计为完整符合性通过。未知可选块被跳过，也不等于该块已经被验证。

当前仅定义规则与测试计划，没有发布符合性检查器或样例文件。完整规范的冻结需要解决必要编码项并取得独立读取证据，见 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。
