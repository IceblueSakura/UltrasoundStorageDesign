## 1. 规范状态与适用范围

<a id="doc-01"></a>
### DOC-01：规范状态与声明边界〔确定〕

本文使用以下标记：

| 标记 | 含义 |
|---|---|
| 〔确定〕 | 已确认需求及其在当前架构下的必要契约；“必须/不得”具有约束意义 |
| 〔参考〕 | 用于样例和实现探索的候选映射/行为；选择采用时按该规则验证，但不等于产品格式已冻结 |
| 〔待定〕 | 尚无正式决定；实现不得把临时值描述为本 Spec 的规定 |
| 〔已替代〕 | 保留历史编号，不作为活动契约或通过证据 |

核心类型与身份定义、带编号的规则共同构成逻辑契约；示意路径、历史编码及机制讨论不增加新的强制要求。本文中的“支持”描述实现目标，不是现有脚本能力。

适用后端固定为 HDF5 2.x。一套公共 schema 覆盖多通道单晶、常规 PA、FMC；一个独立、自解释文件代表一个工件的扫描集合，允许多个独立 Scan 表达分块扫描、复扫和精扫。每个 Scan 承载一次固定采集方案；单晶与阵列数据仍不在同文件混存。“PA”指常规固定聚焦法则采集，并不表示 FMC 不属于阵列技术。

跨流异构合法，同一流在所属 Scan 内固定；不同 Scan 可使用不同固定定义。PA/FMC 同文件组合采集、独立通道时间轴、同一流动态变长、Scan 内定义变更、分卷、在线文件读取和 overlay 合并不在本版范围。多 Scan 不自动解除混存限制，也不引入自动拼接、重叠消解或结果替代。

本次草案修订将原“一个文件一个 Scan”改为工件容器下的多个 Scan；文档版本仍为 `0.2-draft`，实验须按下述修订追溯要求区分新旧契约，不自动承诺旧实验编码兼容。

`0.2-draft` 是文档版本，不是 HDF5 版本或已分配的文件内 `schema_version`。草案修订之间不自动承诺文件兼容。实验文件及报告必须追溯到所用 Spec 修订（例如文档哈希）、实现版本和 `test-only` 编码；正式标识留待 D-07。旧文件不能只更改版本号就宣称合规；可能的转换要求解释依赖充分、定义确实固定且关联可验证，参数变化需要分 Scan 或明确不支持。源文件不原地改写，本轮不实现迁移。

当前允许报告“某些确定规则已验证”或“采用指定参考映射的实验样例通过”。位置编码、身份编码等必要项未闭合前，不得宣布完整生产文件格式符合性，也不得声称独立读取器无需额外实验说明即可互通。

<a id="logical-model"></a>
## 2. 术语与逻辑模型

| 符号/术语 | 含义 |
|---|---|
| `File` / 工件容器 | 一个工件的 Scan 集合及工件身份；不是全局 Frame 轴，也不是工件已扫描完整的证明；Scan 映射关系待 D-11 |
| `Scan` | 一次扫描主体；持有固定方案、事件定义、波形流集合和共同 Frame 轴，不等于网格或图像 |
| `EventDefinition` / `e` | 固定方案中的发射事件槽位及含义；跨帧复用，不是每次实际发射的参数快照 |
| `WaveformStream` / `k` | 固定事件下固定接收输出的跨帧序列，具有固定 dtype、长度与采样解释；不必等于硬件通道或 dataset |
| `Frame` / `n` | 一次逻辑完整采集的组合记录及其零起点索引；不是三套模式专属主体 |
| `N` | 逻辑完整 Frame 前缀数量；不是 dataset 的物理长度，正式计数编码待定 |
| `K` | 固定波形流集合；不再表示旧版参数快照数量 |
| `S_k` / `τ_k` / `s` | 流 k 的固定样本数、原始 dtype 与样本索引 |
| `E_x` | 帧相关物理对象的 extent，可大于 N |
| `N_r` | 恢复视图验证出的完整 Frame 前缀长度，不等于声明值一定正确 |
| waveform / AScan | 指定 Frame、指定流的一条原始波形 |

```text
File（一个工件）
  ├─ 工件身份
  └─ Scan 集合
       └─ 每个独立 Scan
            ├─ Scan 描述（用途/区域/来源/坐标映射模型待 D-11）
            ├─ 固定定义
            │    ├─ Scan 共享采集设置与必要几何
            │    ├─ EventDefinition 集合
            │    └─ 各 WaveformStream 的固定接收与采样解释
            ├─ Frame 轴、原始位置与独立完整前缀
            └─ WaveformStream 集合：各 Frame 的原始波形及状态
```

逻辑身份为：帧 `(Scan,n)`、事件实例 `(Scan,n,e)`、波形 `(Scan,n,k)`、样本 `(Scan,n,k,s)`。Scan 身份须在文件内唯一，跨文件结果还须携带文件来源；n/e/k 的作用域均为所属 Scan，同名局部身份或相同位置不能跨 Scan 合并。N、E_x、N_r 均逐 Scan 解释，不存在隐含的全文件 Frame 计数。k 静态关联正确的事件与接收输出；这些元组不分配 wire 字段。

接收输出必须辨识实际保存的数据层次，例如单接收阵元信号或固定接收法则的合成波形，不能从 shape、路径或硬件通道编号推断。同一硬件接收通道在不同事件下可以对应不同流。几何、探头、法则与采样解释属于固定定义的组成或引用，具体子类型与字段暂缓，不以任意字典替代必要解释。

| 模式 | 一帧的含义 |
|---|---|
| 多通道单晶 | 既定采集方案归组的一组多通道结果 |
| 常规 PA | 一次完整采集的全部预定声束输出 |
| FMC | 一次预定完整收发矩阵采集 |

事件定义不同不自动要求串行执行，共同 Frame 也不证明事件同时发生。“波形流”仅描述身份和跨帧序列，不引入逐通道时间轴、异步拼装或晚到补写。

<a id="scan-01"></a>
### SCAN-01：工件容器与独立 Scan〔确定〕

文件须能识别工件及枚举其中的 Scan。每个 Scan 独立持有固定定义、事件/流集合、Frame 轴、原始位置关联、状态和完整前缀。不同 Scan 的流数、长度、dtype、采样解释或几何可以不同，但每个 Scan 内仍遵守既有不变量及文件的采集类别限制。不能通过同名引用错误复用另一 Scan 的定义。

分块、停止后重新扫描、复扫、精扫、换探头、重装、重新标定或固定定义变化创建新 Scan，不修改旧 Scan。属于同一工件且满足文件类别限制时，可在未封存文件中创建；文件已封存则另建文件，不重新打开追加。跨文件任务关系仍可由外部清单组织，本版不定义跨文件来源解析协议。短暂停顿与一次扫描结束的实际区分仍需场景证据。

首版保持单写者，顺序完成 Scan 后再开始下一 Scan，不引入交错追加多个活动 Scan。每个 Scan 的必要解释须在文件内可解析，不以其他 Scan 的当前默认值解释历史；跨 Scan 定义去重不是本版要求。

<a id="scan-02"></a>
### SCAN-02：Scan 映射关系〔待定〕

已确定的目标是以多个独立 Scan 承载分块扫描工件、复扫/精扫特定区域；每个 Scan 如何映射到工件区域、如何与其他 Scan 关联，仍待决策，**不只是字段编码待定**。本条撤回上一轮提前确定的必填区域/来源、关系方向与基数、无环/已有来源约束、共同工件参考系、坐标变换及映射不可用处理规则。

以下仅为 D-11 的讨论范围，不作为当前强制字段或校验规则：

- 扫描用途、目标区域和来源关系是否需要显式保存，采用何种模型、作用域和必要性约定。
- Scan 与工件区域、Scan 与 Scan 之间的关系类型、引用、方向、基数及合法性约束。
- 是否采用共同参考系、如何表达局部坐标关系，以及是否需要坐标映射或不可用状态。
- 关系的建立/变更时机、读取接口，以及它们是否影响封存、恢复和符合性判断。

上述模型决定前，不要求每个 Scan 提交特定映射，不把缺少这些尚未定义的关系判为错误，也不以 test-only 编码或样例预先选择答案。工件容器、多 Scan 独立身份及原始历史不可覆盖仍按 SCAN-01、WRT-02 执行；不自动拼接、融合、替代或据此宣称完整覆盖的边界不变，见 U-14。Scan 内 Frame 位置绑定、PA 声束及 FMC Tx/Rx 映射不属于本次退回待定的范围。

<a id="rec-01"></a>
### REC-01：共同记录身份〔确定〕

所有流使用同一 Scan 的共同 Frame 轴，波形可追溯到 Frame、事件和接收输出。采集层一次提交完整 Frame 或批次；SDK 不接收逐流追加后等待拼装，不进行时间配准。Frame 不统一解释为一次物理触发；来源 ID 与文件内身份不同，不得据其隐式创建网格或同步关系。

共同 Frame 轴不说明规则网格、空间邻接、位置相同、相位同步或已完成运动校正。位置值相同的帧仍有独立身份。来源 ID 的回绕、跳号、重复属 D-02，不自动补空帧。完整归组不等于全部 payload 存在；缺 payload 写入接口仍见 D-08。

<a id="rec-02"></a>
### REC-02：计数、extent 与边界〔确定〕

N 的逻辑计数范围为 u64；n 合法范围为 `0 <= n < N`。实现必须分别检查计数、索引、切片及字节长度运算，不得静默截成 32 位、溢出或把不支持的尺寸当作空选择。

实现支持上限可以低于 u64 编码上限，但必须明确报告。HDF5 的特殊尺寸常量、绑定层整数范围和内存数组限制不能直接冒充普通记录数量。

物理 extent、填充值和完整 Frame 数量必须区分。正常读取不得暴露 `n >= N` 的尾部；必要对象在前缀内缺行或关联不完整时报告结构错误，不能静默缩短后继续宣称完整。旧 `committed_count` 字面值不是本轮已冻结的路径或计数协议。

## 3. 身份、版本与能力

<a id="id-01"></a>
### ID-01：解释身份〔确定〕

文件必须携带可识别的容器格式与 schema 身份、工件身份及各 Scan 身份、采集语义/profile 身份和物理布局身份。它们分别回答“哪套公共约定”“哪个工件/扫描”“采集是什么”“数据如何组织”，不得混用。文件公共描述与 Scan 专属描述的作用域须明确，不能从同级 Scan 隐式继承定义。单晶/阵列类别、PA/FMC 含义不能仅由 shape 推测；必要语义须足以拒绝类别冲突。

读取器在不理解必要 schema/profile/layout 语义时必须拒绝相应解释，不能按路径相似程度或当前设备默认值猜测。精确字段字面值、字符串编码、版本比较与兼容范围留待 D-07；不预设“同一主版本必兼容”。

<a id="id-02"></a>
### ID-02：必要能力与可选扩展〔确定〕

必须区分影响当前请求解释的必要信息和可以忽略的可选辅助块。未知可选辅助块可以跳过；未知必要语义、编码或 filter 不得静默忽略。

如果只是不支持位置编码、但仍能独立验证波形及记录范围，可以显式提供受限波形访问；必须报告位置/绑定读取不可用，不能伪造位置或宣布完整 profile 合规。若连记录边界也无法验证，则不能以此降级。

扩展须具有格式标识、版本、必要类型/单位、来源与关联说明。能力声明的具体编码属 D-07。状态语义与编码边界见 STA-01。

## 4. 波形、状态、位置与参数

<a id="wav-01"></a>
### WAV-01：流内固定与自解释〔确定〕

对每条流 k，存在 payload 的样本形状表示为：

\[
X_k \in \tau_k^{N\times S_k}
\]

`S_k`、`τ_k`、样本表示、接收输出身份及采样解释在所属 Scan 内固定，跨流、跨 Scan 可以不同；一个 Scan 的原始数据是有身份的数组集合 `k ↦ X_k`，不强制为一个 `[N,C,S]` 数组。缺失槽位不因底层有填充值而成为真实波形。

固定描述必须足以说明各流的类型、字节序、样本含义与必要单位、事件/接收输出映射和采样轴。若有效 ADC 位、对齐、偏置或比例不可缺少，也必须描述；不要求所有设备采用同一组 ADC 字段。相同样本索引、长度或 dtype 不证明相同物理采样时刻或信号处理层次。

实际 dtype 集合、原始整数码/物理量的具体表示和轴参数编码仍属 D-02/D-07。不得仅保存某个本地驱动函数名来替代解释。

<a id="wav-02"></a>
### WAV-02：严格接收与无损保存〔确定〕

每份存在的 waveform 必须与对应流的固定长度及 dtype 严格一致。SDK 不自动截断、补齐、广播、重采样、信号处理或数值转换；调用者声明无效不豁免约束。业务同构化属于显式计算输入转换，不能把转换结果描述为原始回读。输入内存布局和所有权属 D-02，不预设零拷贝或 TCS 输入。

已接受的样本必须无损回读，整数样本逐值一致。字节序不同的表示不能被直接当作原始字节相同；浮点 NaN、负零等逐位保真规则须在该 dtype 被纳入支持范围前补齐，不能先声称任意类型均受支持。

<a id="sta-01"></a>
### STA-01：槽位状态〔确定〕

每个 `(Scan,n,k)` 槽位必须区分 payload 是否存在与调用者声明的业务有效性：

| 逻辑状态 | 必须保持的含义 |
|---|---|
| 无 payload | 不得将物理填充值解释为回波，也不因槽位有状态就声称实际采集完整 |
| 有 payload、业务无效 | 保留原始波形及调用者状态，不静默过滤 |
| 有 payload、业务有效 | 保留原始波形及调用者状态；不由此证明算法正确或采集同步精度 |

调用者业务有效性不能替代 payload 存在性，结构损坏、未完成写入或解码失败也不能降格成业务无效。首版是否接收显式缺 payload 的输入仍属 D-08，不增加晚到补写。

0.1 的 uint8、PAYLOAD_PRESENT/CALLER_VALID 位和 0/1/3 值仅保留为历史编码参考，不是本次确定的字段或字节规范。状态编码及未知值处理留待 D-07；将来若测试采用该表示，须明确 test-only 范围，不能从测试数字反推产品契约。

<a id="pos-01"></a>
### POS-01：采集时位置绑定〔确定〕

每个完整 Frame 必须具有明确的帧级原始采集位置关联；多通道单晶沿用共享关联，PA 使用唯一原始映射位置，见 PA-01。绑定基于 Frame 身份，不依赖时间戳、浮点坐标相等或最近邻搜索。FMC 的矩阵关联不自动提供各收发对的独立空间位置，更细的运动定位模型暂缓。

绑定读取必须对波形、状态与位置使用同一 Frame 选择及对应顺序，并关联正确的固定定义。位置是采集时写入的历史值，不得被后处理或 overlay 静默替换。采集层负责采集关联准确性；SDK 只验证可表达的结构与关联，不进行插值或校准。

“存在位置关联”不预先决定无效位置是否允许及如何表示，见 D-01。不得用零坐标替代尚未定义的缺失位置语义。

<a id="pos-02"></a>
### POS-02：位置描述边界〔确定〕

位置描述必须足以解释具体实例的字段、类型、必要单位、轴/参考对象、来源及结构版本。允许多字段，但不预设 XYZ、四元数、编码器轴数或具体物理 shape。

独立反馈流可以作为辅助数据保存，但不得要求通过时间配准才能恢复 Frame 位置绑定。绑定位置不等于扫描网格；没有明确拓扑或调用者映射时，不承诺自动恢复 B/C/D 排列。具体位置编码与有效性仍为 D-01。

<a id="pa-01"></a>
### PA-01：唯一帧位置与派生声束解释〔确定〕

第 n 帧原始关系为 `Frame_n = (P_n, {W_n,b}, 状态与关联)`。完整 PA 帧只有一个原始映射位置 P_n，全部声束关联它，不要求为 B 个声束另存 B 份独立位置测量。读取结果可随束交付这一引用，但唯一事实来源保持在 Frame 层。

声束空间解释依赖 `P_n + 固定探头/安装几何 + 对应固定聚焦法则及必要解释`。束号必须找到正确事件和接收输出，不与法则、硬件通道或阵元编号混用。参考样例一组法则对应一个保存声束，不把它变成所有设备的假设。

入射点、方向、焦点与样本空间位置不是同一对象，样本定位可能还需传播模型。本轮不定义坐标字段或几何算法。原始读取不以定位完成为前提；派生声束位置或图像不覆盖 P_n，共享 P_n 不代表束在工件中位置相同。旧“PA 逐事件独立采集位置”候选已被替代。

<a id="par-01"></a>
### PAR-01：固定采集定义的作用域与复用〔确定〕

Scan 共享设置只保存一次，事件专属设置每个事件保存一次，流专属设置每条流保存一次。固定参数指整个采集程序与定义不随帧变化；预定执行 L0、L1、L2 后在下一帧重复，不属于修改参数，也不要求程序只有一种法则。

本轮不需要逐帧 config_index、动态快照历史、生效区间或重复法则内容。所有必要固定引用须存在且可解释；真实采集设置、方案、流身份、长度、dtype 或采样解释变化应新建 Scan，是否另建文件按 SCAN-01 判断，不能更换定义或增加配置引用维持旧身份。固定性的作用域为 Scan，不要求同文件所有 Scan 共用一套定义。位置、波形与状态是可变化的观测结果，不因参数固定而移除。

固定定义的具体领域子 schema/编码属 D-09；不得依赖设备当前默认值或只保存本地驱动函数名代替解释。

<a id="par-02"></a>
### PAR-02：旧动态快照字节区〔已替代〕

`data + offsets` 动态快照字节区不是当前模型的必要对象或活动参考映射。保留编号用于项目内历史追踪，不表示 PASS；其职责已由 PAR-01 的固定定义复用取代。固定定义采用何种序列化仍待 D-09，不预设 JSON。

<a id="fmc-01"></a>
### FMC-01：固定 Tx/Rx 映射与覆盖〔确定〕

固定有序发射集合 I、接收集合 J 及映射 π 定义 `M_n[i,j] = X_π(i,j)[n,:]`；行是 Tx，列是 Rx。流目录顺序、物理排列或扁平编号不构成隐式映射。

声明为完整矩阵的采集域必须覆盖 I×J，每个有序收发对有明确且唯一的逻辑流对应；引用须存在，流的事件发射身份与接收输出须与对应 Tx/Rx 一致。不同有序对不得别名到同一测量身份。物理打包或共享存储对象不等于共享逻辑波形。

普通单阵列完整 FMC 样例中 I、J 为选定的同一阵元集合，包含全部有序对。覆盖声明须说明阵元范围，子孔径不冒充全探头。`Tx0→Rx2` 与 `Tx2→Rx0` 保持独立；不利用互易性合并、推算或复制另一半矩阵。

帧结构闭合、完整 FMC payload、业务有效分别判断：预定槽位及关联明确可结构闭合；声明域全部对有实际 payload 才能称 payload 完整；有 payload 仍可业务无效。明确标记的缺失可用于诊断/受限访问，不能作为零信号；无说明结构缺口、未完成写入或解码失败不能转换成调用者无效。缺 payload 写入支持仍待 D-08。

<a id="fmc-02"></a>
### FMC-02：矩阵访问与异构结果〔确定〕

访问层必须能交付完整帧矩阵、固定 Tx 行、固定 Rx 列、有序 Tx×Rx 子矩阵、显式收发对清单、连续/离散多帧及给定样本选择。可组合基础读取，不要求每项独立函数；不能只交付未解释的流集合，让调用者自行维护映射。

矩阵、流和单波形视图使用同一原始来源，不维护两份可分别修改的事实。一般矩阵单元为：

\[
M_n[i,j]\in\tau_{ij}^{S_{ij}}
\]

所选单元长度和 dtype 一致时必须可取得逻辑轴序 `[Frame,Tx,Rx,Sample]` 的稠密数值视图；该轴序不承诺物理布局、连续内存或一次 I/O，显式转置须保留轴身份。有明确缺失的选择可用于诊断或受限读取，不得把填充值当作原始测量或宣称 payload 完整；具体缺失结果容器、掩码或拒绝方式仍待 D-08/D-10，不在本轮规定。

共同物理时间轴还要求采样解释一致；仅 shape/dtype 一致时只能声明按样本序号堆叠，并保留各流解释。异构时返回有 Tx/Rx 身份的波形矩阵或分组结果，不隐式转换、填充或截断。同构主路径不降为只有逐流访问，矩阵读取也不强制全扫描驻内存。

TFM 消费收发波形及对应路径的传播时间；不同收发对可能取不同样本。按传播时间选样还依赖各流的采样起点、间隔及必要解释，不能仅由矩阵 shape 推出。逐对选样可以在已读输入块上执行，不要求逐像素磁盘读取。本轮不实现传播时间、TFM 或图像重建；Tx/Rx 轴不是工件网格，派生图像不替代原始矩阵。

## 5. HDF5 组织边界

<a id="map-01"></a>
### MAP-01：逻辑语义与物理组织分离〔确定边界，编码待定〕

本轮不规定 HDF5 路径、chunk、压缩、缓存或定义序列化。逻辑职责如下，不是已冻结字段表；`TBD` 不得作为实际文件的万能解释。

| 逻辑对象 | 逻辑形状/关系 | 编码边界 |
|---|---|---|
| 工件容器 / Scan 集合 | 工件身份、Scan 枚举；用途/区域/来源/坐标映射模型待定 | 容器语义 SCAN-01；Scan 映射关系 SCAN-02/D-11，协同 D-01/D-07/D-09 |
| 解释身份 | schema、Scan、采集语义、物理布局 | 必要语义确定，字面值/版本/路径 D-07 |
| 固定定义 | Scan/事件/流及其必要引用 | 领域子 schema D-09，编码 D-07 |
| Frame 轴 | 身份、原始位置及采集关联 | 位置 D-01；具体字段 D-07 |
| 各流 payload | 每流 `[N,S_k]`、dtype τ_k；状态决定真实存在性 | 逻辑流不必一流一个 dataset |
| 状态 | 每个 `(n,k)` 槽位 | 原有状态逻辑保留，物理组织暂缓 |
| PA/FMC 映射 | 束→事件/输出；Tx/Rx→流 | 必须明确，不由目录顺序推断 |
| 前缀与生命周期 | 各 Scan 的 N、完成/故障/恢复范围；文件封存 | 确认协议 D-05，编码 D-07 |
| 可选辅助块 | 自解释扩展及其关联 | 不替代必要位置、固定定义或采集语义 |

HDF5 datatype、dataspace 与布局是不同属性，Frame 不要求一帧一个 group。初始化不要求知道最终 N；采用逐行组织的必要对象须覆盖 `[0,N)`，位置编码也须能验证该段逻辑关联。预分配使 E_x>N 本身不是错误，但不能仅凭 extent 判定封存。

物理设计需要区分以下机制；这些说明不分配生产路径或默认值：

| 机制 | 本项目中的解释与约束 |
|---|---|
| datatype | 描述存储元素的类型、位宽及字节序，不由 shape 决定；HDF5/绑定层可执行类型转换，不意味着 SDK 可跳过 WAV-02 的严格输入校验或改变原始样本 |
| dataspace / extent | 描述数据轴及物理尺寸；预分配或 resize 不等于 Frame 逻辑提交，完整前缀由 REC-02/WRT-02 验证 |
| chunk / filter | chunk 是物理分块和常见压缩处理单元，不是事件、波形流或事务身份；逻辑样本窗口可能触发整块解码，局部追加可能重写未填满的块 |
| HDF5 chunk cache / OS cache | 缓存层不同，命中会改变读取代价但不得改变逻辑结果；逻辑样本吞吐不等于磁盘物理带宽 |
| 属性与固定描述 | HDF5 对象属性和 dataset 数据可以承载编码，但对象路径及数组维度本身不提供采集含义；必要身份、单位和引用仍须明确 |

旧 SPLIT 路径和 CTS/TCS 只可作为适用工作负载的历史参考，不升格为所有模式的强制映射。样例可采用明确标记的 test-only 编码；物理设计选择不得改变语义和保真要求。

## 6. 写入和生命周期

本节定义写入、封存及恢复的逻辑边界；具体 flush/确认顺序、持久化与恢复协议仍属 D-05，不是本次已确定的实现方案，也不要求下一阶段全部测试一并实现。

<a id="wrt-01"></a>
### WRT-01：提交校验与阻塞行为〔确定〕

一个单写者向明确指定的活动 Scan 按完整 Frame/批次追加，提交单元不跨 Scan。SDK 必须在修改 extent 或推进前缀之前完成提交单元的结构校验，包括 Scan 身份、逐流 shape/dtype、状态和固定引用；校验失败不改变逻辑帧数量、相关 extent 或已提交数据。不得通过帧提交偷换固定定义。

写入慢时允许阻塞，不主动丢弃已交付数据或静默跳过记录。I/O 错误必须报告并停止正常追加，不能当成输入校验失败后无条件重试。具体异常类型、取消与重试语义、缓冲复用时机属 D-02/D-05/D-10。

上述要求不保证设备在调用者阻塞期间不会溢出，也不保证崩溃后零损失。端到端不丢数据还需设备停采/暂存契约及持续负载测试。

<a id="wrt-02"></a>
### WRT-02：完整前缀与不可变历史〔确定〕

在每个 Scan 的正常写入流程中，其 N 单调不减；新 Scan 从自己的 Frame 轴开始，不延长旧 Scan 的 N。推进前缀前，相关波形、状态、原始位置和固定定义依赖必须完成写入及选定的 flush 步骤。已提交 Frame 和其历史解释不得原地修订或晚到补写。

这是逻辑顺序，不是跨 dataset 事务保证。后续追加可能改写包含旧数据的未填满压缩 chunk。调用返回、flush、设备持久化和最终封存不能互相等同；精确确认点、flush 周期、状态更新顺序及故障后的可恢复数量仍属 D-05。

<a id="lif-01"></a>
### LIF-01：正常封存与读取〔确定〕

文件生命周期包括初始化、顺序写入 Scan、正常封存及故障/未正常关闭。Scan 生命周期包括定义/初始化、追加、完成或故障；完成 Scan 后拒绝继续追加，但未封存文件可开始下一个 Scan。完成 Scan 不等于文件封存或持久化保证；普通读取仍等待整个文件封存。状态字节编码未定。

文件正常封存需核对 Scan 集合、每个 Scan 的完成状态/前缀及已确定的必要定义和 Scan 内关联，完成所选关闭流程；不得把未完成 Scan 静默跳过后宣布全文件正常。D-11 尚未决定的区域/来源/坐标映射不作为当前封存前提。初始化时 N=0 不代表 Scan 已完成；是否允许空 Scan 完成并纳入正常封存文件、是否允许无 Scan 的文件正常封存及相应 API 行为，留待 D-05/D-10。此处“完成”仅指存储记录闭合，不证明区域实际覆盖或整个工件检测完成。

普通读取面向已封存文件，常规追加入口必须拒绝修改已封存文件。实时显示走采集内存，不要求读取增长中的文件或实施 SWMR。正常文件若不能满足必要结构和引用约束，应明确报错，不得自动当成有效的较短扫描。

<a id="lif-02"></a>
### LIF-02：尽力只读恢复〔确定〕

未正常关闭的文件通过显式恢复模式处理，不伪装成正常封存：

1. 只读尝试打开，失败时报告，禁止为打开而自动修复原文件。
2. 检查可读取的前缀、物理范围和必要关联；不把填充值或可解码字节自动认作完整 Frame。
3. 如果可建立可信完整前缀，则暴露验证范围 N_r；只有声明的 N 本身可验证时，才可以将其作为上界依据。前缀标记缺失/不可信时，不凭各 extent 最小值猜测恢复数量。
4. 报告声明范围、验证范围、失败对象及未执行检查；结构可读与逐样本完整性验证须区分。
5. 不原地续写、修复或截断源文件。超出可信前缀的抢救、前缀标记损坏后的重建策略留待 D-05。

上述 N/N_r 与范围验证逐 Scan 执行，并报告 Scan 集合及已确定的必要结构检查结果。某 Scan 失败不允许静默缩短或合并其他 Scan；能够独立验证的 Scan 可显式报告为恢复子集，但不代表整个文件正常。D-11 的映射关系验证等待模型决定，不因尚无关系定义而伪造关联或报告产品规则失败。HDF5 group 不构成事务或故障隔离边界，文件级元数据损坏仍可能使多个乃至全部 Scan 无法访问。

HDF5 元数据损坏时可能无法打开。恢复目标是尽力，不预设最大损失时长，也不承诺某个 flush 前的数据必然存在。不能将不完整尾部或损坏记录改成调用者业务无效来掩盖故障。

## 7. 读取语义与规模

<a id="read-01"></a>
### READ-01：独立和绑定访问〔确定〕

SDK 提供波形、位置的独立访问以及绑定访问；具体函数签名不属于本文。波形访问返回对应状态，不强制解码位置，但须满足 ID-02 的受限访问条件。单独结果须可核对 Scan、Frame、流及事件/输出来源；PA 声束和 FMC 矩阵视图保持相同来源。

访问层还须能枚举/选择 Scan 并识别所属工件；用途、目标区域、Scan 间来源及坐标映射的读取能力等待 D-11 决定，不在本轮要求具体关系或结果。原始数据请求以一个明确 Scan 为作用域，不能默认第一个或“最新”Scan；跨 Scan 消费可组合独立请求，不隐式拼接 Frame 轴、统一 dtype 或筛选替代结果。即使各 Scan 的 n/k 和位置相同，也须保留独立数据来源，不据此推导空间映射。

绑定访问按 POS-01 保持关联，不静默过滤业务无效波形、不重新按时间匹配、不以 overlay 替换历史位置。一个请求无法满足时必须显式报告，不以空数组或零位置伪装成功。

<a id="read-02"></a>
### READ-02：选择结果语义〔确定语义，API 编码待定〕

下列语义用于访问规划和 UC 验证；不冻结函数签名、返回类型、异常名称或负索引等 API 扩展语法（D-10）：

- 有序 Frame/Stream、PA 声束、Tx/Rx、配对和 Sample 清单保序保重复，例如 `[2,0,2]`；内部可以排序读取，但须恢复结果顺序与重复项。
- Tx 清单与 Rx 清单的交叉选择为笛卡尔子矩阵；显式收发对清单只返回列出的对，不展开成子矩阵。
- 样本边界按每个选中流自己的 S_k 检查，不以最长流的边界替代其他流，不静默截断、补齐或溢出。
- Sample 清单 `[3,1,3]` 表示按顺序交付原始样本 `s=3、1、3`，不能排序或去重后改变结果；逐流/逐对给定样本清单时，同一要求分别适用。此类显式有序清单不等于已经确定负步长切片等逆序 API 语法。
- 选择结果保留 Frame、流/轴身份、状态、固定定义关联；绑定结果还保留原始位置来源。
- 逐对样本选择表或窗口可以作用于已读数据块；不承诺每项选择单独触发磁盘 I/O。

本项目用半开区间 `[a,b)` 和可含重复项的有序清单表达预期，不冻结 API 语法、返回对象形态或异常类名。少量空选择、单元素、首尾、越界变体属于后续用例素材；具体空结果表示、负索引或逆序语法留待 D-10，不可用空结果伪装越界成功。

请求异构流集合时，必须明确报告越界流及相关范围，不静默截断、补齐或伪装整个请求成功。采用整个请求拒绝，还是显式逐项结果/错误的形式，本轮不决定，留待 D-10。不支持的选择须明确报告，不能算能力通过，也不能削弱 FMC-02 的目标能力。

<a id="cap-01"></a>
### CAP-01：超 RAM 访问〔确定〕

目标是超过 100 GB 的单文件，每个 Scan 的 N 仍在 u64 范围内，不要求其总和可表示为一个全局 N。写入缓冲和读取缓存必须有界，不随各 Scan 的总 Frame 数线性增长；波形、位置、状态、相关定义及 Scan 目录访问均须有界，矩阵访问允许分批，不能要求打开时全量物化所有 Scan 的定义。正常打开不要求扫描全部波形，深度检查单独执行。

大选择可以分批输出，不能要求整个通道同时物化为内存数组。内存预算、性能门槛和具体迭代 API 留待 D-02/D-03/D-10，不在此设定数值。只通过小文件测试不能声明本条规模目标已验证。

## 8. 压缩与解码

<a id="cmp-01"></a>
### CMP-01：无损与依赖可识别〔确定〕

压缩用于降低磁盘流量与长期容量，必须满足 WAV-02。文件的有效 filter 编码链和必要参数必须可识别，读取端可以部署第三方 filter；缺少解码器或不支持参数时明确报告，不能回退为错误数值。

不固定 codec、级别、chunk、线程或缓存参数（D-04）。“具有 filter ID”不表示所有 HDF5 安装均自带解码器。生产带宽规划不得以当前合成数据压缩率作为不可压缩输入仍不丢数据的证明。

<a id="cmp-02"></a>
### CMP-02：GPU 可选能力的声明〔确定〕

CPU 可读路径是基础，GPU 解压是待验证的可选能力（D-06）。声称 GPU 解压时，必须验证从实际存储的压缩表示到样本的完整链路，包括封装、压缩块、预处理逆变换、尾块及存在的校验。

主机先解压再 H2D 不属于 GPU 解压。缺少 GPU 不影响基础 CPU 读取符合性；GPU 厂商、库、输出顺序和性能阈值不在本版指定。

压缩字节在主机到设备间传输后再由 GPU 解码，与主机先解码再传输原始样本，是两条不同的消费路径。后续比较须包含实际传输字节、解码、预处理逆变换、必要布局转换及下游消费代价，不能仅凭传输量减少或单独解码计时宣称端到端更快。具体测量规划见 SPEC_TEST_PLAN 的性能与 GPU 专项；本轮没有运行验证。

## 9. 符合性检查与错误解释

<a id="val-01"></a>
### VAL-01：分层、可追溯的验证报告〔确定〕

检查必须区分文件错误、不支持的能力、普通业务无效以及尚未验证：

| 层次 | 检查对象 | 不足以证明什么 |
|---|---|---|
| 识别 | schema/profile/layout、必要能力、解码依赖 | 不证明数据完整 |
| 结构 | 各流类型/shape、固定定义、状态与声明长度 | 不证明全部字节已正确落盘 |
| 关联 | Frame 前缀、原始位置、事件/接收输出引用、PA/FMC 映射 | 不证明物理位置准确或成像正确 |
| 深度 | 分批解码、内容比对/已定义的完整性校验 | 不自动证明抗断电、性能或设备不丢数据 |

测试记录至少包括 Spec 修订、采用的参考映射/临时编码、输入样例、规则编号、检查层次、执行结果和未覆盖项。结果可以表达 PASS、FAIL、NOT_RUN、BLOCKED、UNSUPPORTED 等含义，但正式错误码与报告序列化格式未定。

待定编码造成的 BLOCKED、选择未实现的 UNSUPPORTED、未执行的 NOT_RUN 都不得计为完整符合性通过。未知可选块被跳过，也不等于该块已经被验证。

当前仅定义规则与测试计划，没有发布符合性检查器或样例文件。完整规范的冻结需要解决必要编码项并取得独立读取证据，见 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。

### 待定项的阶段门槛与闭合依据

以下只说明各 D 项何时影响完成声明及如何取得证据，不确定其具体取值，也不授权启动后续工作。M0～M4 的交付物和执行状态只在 [验证计划的里程碑](SPEC_TEST_PLAN.md#milestones)维护；本表不是第二份执行账本。

M1 可以使用明确记录、关联 Spec 修订的 test-only 编码和实验接口。临时选择只解除相关实验用例的实施依赖，不将 D 项标为正式闭合；未决行为不得按某一产品答案编写强制断言。后续按已声明的 profile、API 或目标环境逐项闭合，未覆盖范围继续保留，不要求一个阶段解决所有可能的设备或可选能力。

| D 项 | 影响的阶段 / 声明门槛 | M1 临时处理边界 | 正式闭合所需的决定与证据 |

| D-01 | M2：所声明 profile 的位置可独立解释 | 可用 test-only 位置描述核对 Frame 关联，不冒充真实坐标/标定 | 明确字段、类型、单位、参考对象、组织和无效位置策略；独立读取及有效/无效反例与预期一致 |

## 11. 契约修订流程

按“候选规则 → 正反样例 → 独立检查 → 修订规则”迭代。每次规则升级说明需求依据、影响的数据解释、旧实验样例是否仍适用及验证证据。改变记录含义不能伪装成纯性能优化。
