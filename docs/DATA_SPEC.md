## 1. 规范状态与适用范围

<a id="doc-01"></a>
### DOC-01：规范状态与声明边界〔确定〕

本文使用以下标记：

| 标记 | 含义 |
|---|---|
| 〔确定〕 | 已确认需求及其在当前架构下的必要契约；“必须/不得”具有约束意义 |
| 〔参考〕 | 用于样例和实现探索的候选映射/行为；选择采用时按该规则验证，但不等于产品格式已冻结 |
| 〔待定〕 | 尚无正式决定；实现不得把临时值描述为本 Spec 的规定 |
| 〔已替代〕 | 保留历史编号，不作为活动契约或通过证据 |

复合标记（如〔确定语义，打包待定〕）表示同一规则内已确定部分与待定部分的分界，各部分分别按上表解释。核心类型与身份定义、带编号的规则共同构成逻辑契约；示意路径、历史编码及〔参考〕机制不增加新的强制要求。本文中的“支持”描述实现目标，不是现有脚本或实验原型的能力。

当前确认的是 BUS-01～MEAS-01 的业务范围，不是所有扫描类型、数据模型或首发范围定版。既有 HDF5 2.x 库及 1.10–1.14 可读格式选择（ADR-0005）保留；下文的流组/Frame、工件容器和 PA/FMC 规则是已有原始波形 Core 模型，不自动成为仅特征、混合扫描或所有新内容的强制模型。UMS Run、SDK Scan、工件及文件的映射待 D-11，不强制一 Run 一 Scan 或一文件，也不承诺完整业务成果跨电脑自足交付。“PA”在旧 Core 模型中指常规固定聚焦法则采集，不表示 FMC 不属于阵列技术。

混合扫描范围暂不确定（D-13）。旧 Core profile 的单晶/阵列不同文件、PA/FMC 不同文件限制仅描述该 profile，不作为产品永久边界，也不能因本次同步就宣称混存、同步或融合已支持。跨流组异构、组内固定等既有规则在其适用模型中保留；不能推定不同模式共享 Frame 轴、位置或采样定义。在线文件读取、自动拼接、重叠消解和结果替代不因扩大存取范围而加入。

`0.3-draft` 是文档版本，不是 HDF5 版本或已分配的文件内 `schema_version`。草案修订之间不自动承诺文件兼容。实验文件及报告必须追溯到所用 Spec 修订（例如文档哈希）、实现版本和 `test-only` 编码；正式标识留待 D-07。旧文件不能只更改版本号就宣称合规；源文件不原地改写，本轮不实现迁移。

当前允许报告“某些确定规则已验证”或“采用指定参考映射的实验样例通过”。位置编码、身份编码等必要项未闭合前，不得宣布完整生产文件格式符合性，也不得声称独立读取器无需额外实验说明即可互通。

### CORE-01：既有原始波形 Core 与调用边界〔确定适用范围，新增能力承接待定〕

产品范围按 BUS-01～MEAS-01；不再以“首版只做 Core、领域 schema 后置”为由排除已确认的模式参数、C 扫快照或基础取值。Core 与扩展如何分工尚未定版，不引入通用文件集合或派生成果管理平台。以下同步 Frame/Batch、poll/push 等规则保留为原始波形路径的既有工程合同，不将它们未经设计直接套用于全部快照、关系与取值操作。

写入提供同步单 Frame 和 Frame 批次入口。读取分两层（ADR-0006）：**Core I/O** 按一个 Scan、一组 Frame（单帧或 Batch，B≥1）及一个或多个流组交付稠密样本、有效性位图、帧位置与帧级附加记录，提供随元信息返回的分析读取与 Batch 读取两种交付方式，每种都可以走 poll 或 push；**选择层**是在 Core I/O 结果上执行帧内流/声束/Tx/Rx/样本选择的纯函数，不做文件 I/O。Batch 的连续/离散选择形式仍待 D-10，不跨 Scan 自动拼接。文件/Scan 目录和固定描述可独立访问，不做按位置查询。

并发范围（ADR-0004）：SDK 在进程内对全部 HDF5 调用做全局串行化；同一 Reader 或 Writer 对象不得被并发调用，对外不承诺对象级线程安全。一个进程可持有多个 Reader，各自的 poll 借用独立；同一文件同一时刻只有一个 Writer，且不能同时被 Writer 与 Reader 打开（SDK 须检测并拒绝，不只是调用约定）。多个进程可以同时只读同一个已封存文件。该路径仅同步读写；写入输入及 push 读取目标由调用者维持，poll 读取返回 SDK 管理的只读借用视图（BUF-01）。读取本身不修改数据，相同数据和选择条件下等价读取值一致；另行写入指定快照按 SNAP-01，不据此开放同文件读写并存。写入无取消，普通写入不立即落盘；Flush 和调用失败见 WRT-03/IO-01，有效性位图与无效零填充见 STA-01。

Core 不负责等待、补全、设备协议解码、业务字节序转换或坐标计算；必要的存储类型和编码约定不因此省略。平台及语言目标见 DESIGN 的 [Core 决定](DESIGN.md#core-scope)，本阶段只在 Linux 上验证；公开接口的稳定边界见 API-01，精确支持矩阵与绑定方式见 D-12；本阶段不开展实现、部署设计或细节调优。

<a id="api-01"></a>
### API-01：公开接口的稳定边界〔确定原则，签名待定〕

本条保留 ADR-0010 的后续工程原则，不是当前阶段的 API 定版或已发布兼容承诺；本次业务确认不冻结接口，也不以旧工程约束排除 BUS-01～MEAS-01。公开 API 的稳定包括调用语义稳定与接口演进兼容；适用合同不随实现偷偷改变，正式兼容起点仍待决定。后续设计原则如下：

1. 原生库唯一的稳定边界是 C ABI。对象以不透明句柄表示；公开头文件不出现 HDF5、C++ 标准库或异常类型，C++ 异常不穿过该边界。C++ 便利层（若提供）只是头文件内的薄封装。
2. 长度、偏移、计数与帧号使用 64 位整数；调用者缓冲以“指针＋字节长度”描述，SDK 据此检查容量（BUF-01）。
3. 选项与描述结构体以自身大小（或版本号）开头，新字段只追加；SDK 按调用者声明的大小读取，未提供的字段取默认值。可能演进的调用带 flags 或选项参数，未识别的标志位须明确报错，不得静默忽略。
4. 错误码数值一经发布不再复用或改变含义，并归入稳定的分类；写入类调用另外报告提交状态（已提交、未提交或未知，见 IO-01）；错误消息文本不属于稳定契约。

具体签名、错误码清单与分类、提交状态的表示属 D-10；实现语言、绑定方式与支持矩阵属 D-12；兼容承诺的级别与起始版本、版本与能力查询尚未决定。

<a id="bus-01"></a>
### BUS-01：超声专用产品边界〔业务确定〕

SDK 是包含权威 schema 与读写能力的单一超声数据规范产品，承载原始波形、必要解释信息与数据关系、布局信息及 C 扫数值快照。由 UMS 实际需求驱动完善，后续独立维护并开源；不规划许可证或定版 API，不依赖 UMS 的 UI、Workflow 或业务数据库才能定义数据含义。

设备控制、扫描复现、完整工艺工程、包络/滤波/成像、复杂闸门分析、标注及缺陷分析成果、激光等点云、额外导出与成果打包不在范围。标注与缺陷成果由 UMS 管理。SDK 只执行调用方表达的数据操作，不规定保存按钮、确认弹窗、任务准入或检测合格政策。接口层校验不替代设备事实或业务判断。

<a id="ret-01"></a>
### RET-01：保留内容、状态与部分成果〔业务确定，表示待定〕

全波、仅特征、波形与特征混合保留均合法，实际内容由工艺选择。只保存特征时不要求虚构波形、Frame 或有效性位图；原始波形路径的模型仅适用于实际保留的原始内容。特征须有含义、单位、有效性、来源和必要解释；来源关联不要求来源波形仍被保留，没有输入就不能提供依赖该输入的取值或重算。

有意未保留、应有但缺失、实际无效、有效零值分别表达。允许保存能自洽解释缺口与失败的部分成果；保存成功不证明扫描完整或检测合格。SDK 不自动补齐、推算或伪造数据。STA-01 的波形有效位仅是局部规则，不能独自承担全部内容与质量状态；具体表示协同 D-01/D-16。

<a id="rel-01"></a>
### REL-01：必要关系与自包含解释〔业务确定，模型待定〕

SDK 必须承载扫描与目标区域的关系，以及复检/局部重扫与原扫描的关系；后者须能指向原扫描中的具体区域，不限于整份扫描。快照与数据来源的关联继续有效。区域信息究竟只需区分区域，还是包含范围及位置关系，本轮暂不确定；作用域及合法性仍待 D-11。

本轮未将扫描与检测对象的归属关联追加为产品必需关系，不据此禁止应用保存对象信息，也不将旧 Core 的工件容器扩成产品唯一组织。SDK 不管理任务、复检调度或审批，不计算区域或自动融合；新旧扫描保留独立原始身份，不因关系存在就回填、覆盖或替代原结果。

自包含参数只覆盖解释已有数据必需的采样、闸门、探头等参数和硬件信息，不以复现扫描为目标。单探头与相控阵使用清晰可辨识的不同参数 schema，可复用含义一致的公共定义，不能靠 shape、设备名称或无约定字典猜测模式；具体必要信息待 D-09。

曲面扫描仅承载解释超声数据所需的曲面、坐标关系和采用几何。激光等点云属于前置知识，不进入本 SDK；保存关系不等于执行坐标转换、配准、轨迹规划或重建。几何说明与已有数据必要解释随场景细化，不扩成通用几何处理产品。

<a id="snap-01"></a>
### SNAP-01：C 扫特征快照与后续保存〔业务确定，组织待定〕

SDK 存取一份或一组 C 扫特征值 snapshot 及其解释与来源，不是截图或缺陷成果。读取已有快照不重新计算；快照缺失不自动取值补建。本次基础取值与已保存结果分别表达，保存仍须由调用方显式发起。

关闭重开后允许在已有扫描文件中新增或替换指定快照，也支持写入另一个目标。新增保留已有内容；替换只作用于明确指定的快照，不影响其它数据。原始波形、采集采用参数及其它原始事实不变，写入失败须保留原有可用成果。不由此批准原始 Scan 续写、补扫回填或覆盖整份文件。具体快照分组、参数关联、替换粒度及完成/失败合同待 D-16，不预设原地覆写或并发读写。

区分采集采用参数、分析参数与快照实际采用参数。不要求恢复逐批次在线分析参数历史；在线设置曾变化且无历史时，不把最后一组设置冒充全部数值的共同参数，也不承诺精确重演在线结果。

<a id="access-01"></a>
### ACCESS-01：布局、分层访问与规范子集〔业务确定，规则细化待定〕

布局规划确定存储组织和读写优化重点，优先支持的布局应获得高效访问，不代表只能支持这些布局。已确认五类重点使用场景：浏览已保存 C 扫快照、C 扫选点取 A 波形、区域批量读波形/基础取值、按 B/D/S 等布局批量读取，以及分批遍历整次扫描。五类均需满足，本轮不排序或承诺同等访问速度；负载与优化目标待 D-03，不据此增加布局编辑、成像或绘制。

底层提供选定位置实际关联并保留的 0～N 条原始波形及来源；零条须能与未保留、缺测等内容状态对应。顶层按 SDK 统一内建规则选取一条代表波形，同时给出来源与实际有效性；无可返回数据时明确表达。相同数据和选择条件下结果一致，不依赖读取顺序或缓存。代表选择不改写有效性，不删除其余来源，也不重新解释已有快照的历史来源。

代表候选限定在已选定扫描、通道/声束及声路所对应的同类观测中，只比较目标位置的重复测量，不自动跨扫描、声束或声路挑选。顶层只从已记录为有效的波形中选择，不新增质量判定算法；没有有效候选时明确返回无有效代表，并区分未保留、缺测或全部无效，不以无效波形兜底。底层实际保存的其它来源仍可访问。

业务意图是近似取得最新有效测量，考虑以到达先后估测，但 SDK 不承诺确认真实采集时间。“到达”是采集侧接收还是交付给 SDK 的环节尚未选择，最终顺序与并列规则继续待 D-17；不能把当前读取或缓存顺序作为依据。其它能力可采用分层，不机械复制两套接口；此业务分层不等同于旧 Core I/O／纯选择层划分。

SDK 提供规范数据子集的提取与读取，已确认选择范围为：选定的扫描记录、基于已有位置/布局的空间区域、通道/声束/收发组合，以及波形样本窗口。多扫描保持各自独立，样本窗口保留在原波形中的位置、采样解释及来源；其它子集同样保留必要解释与来源，不修改原始成果。采集记录区间未追加为本轮必需选择维度，不据此删除旧 Core 已有的按记录索引访问。

子集能力不附带图片/CSV 等额外导出、格式转换或成果打包。数据写入与快照操作仍有效，不把“无导出”误解为只读。空间选择不要求任意坐标搜索、插值或几何重建，区域含义及具体选择合同仍待 D-11/D-17。

<a id="meas-01"></a>
### MEAS-01：基础窗口取值〔业务确定，模式含义待定〕

仅针对 SDK 文件读取的数据，提供明确窗口内的基础幅值与位置/时间取值，例如峰峰值、前沿取值；不提供任意内存波形输入，不要求在线计算先落盘。SDK 不做深度/厚度等派生物理量转换、额外信号或坐标转换，不自动包含包络、滤波、同步跟随门、跨波形跟踪或完整分析引擎。

区域批量取值保持请求区域的位置对应，逐点给出数值与状态；输入无效、缺少输入、未检出与有效零值可区分，不挤掉其它点或用占位零冒充测量。结构损坏、解码或 I/O 错误不能伪装为普通无效点。

保留本次取值条件与输入来源，不修改原始数据或隐式覆盖快照。前沿取值已确认同时返回同一前沿点的位置/时间与对应幅值，不转换为深度或厚度。前沿判据、取点方式、窗口参考及单位、信号表示、阈值/极性、越界与未检出含义继续待 D-18；用户后续统一提供算法参考，本轮不选定首次越阈、回波峰值或其它具体方案。

## 2. 术语与逻辑模型

本节至后续 Frame/流组工程规则描述既有原始波形 Core，不是对仅特征成果的伪波形要求。新增快照与关系按上述业务条款及 D-09/D-11/D-16～D-18 承接；旧 Core 模型不直接约束尚未定义的混合扫描。

| 符号/术语 | 含义 |
|---|---|
| `File` / 工件容器 | 一个工件的 Scan 集合及工件身份；不是全局 Frame 轴，也不是工件已扫描完整的证明；Scan 映射关系待 D-11 |
| `Scan` | 一次扫描主体；持有固定方案、事件定义、波形流集合和共同 Frame 轴，不等于网格或图像 |
| `EventDefinition` / `e` | 固定方案中的发射事件槽位及含义；跨帧复用，不是每次实际发射的参数快照 |
| `WaveformStream` / `k` | 固定事件下固定接收输出的跨帧序列，Scan 内身份唯一；不必等于硬件通道或 dataset |
| `StreamGroup` / `g` | 同构流组：组内各流的 dtype、样本数、样本表示与采样间隔一致，逐流差异以流表保存；每条流静态属于唯一一个组，组内序号为 `q`（ADR-0001） |
| 组解释 | 通道组、PA 声束集或 Tx×Rx 矩阵；解释属于流组，不属于文件或 Scan |
| 帧级附加记录 | Scan 内固定描述、每帧一行的带类型记录，例如原始帧位置、时间戳、来源 ID、额外坐标 |
| `Frame` / `n` | 一次结构闭合的组合记录及其零起点索引，包含各流组的第 n 行、帧位置及帧级附加记录，可显式标记无效波形槽位 |
| `N` | 逻辑完整 Frame 前缀数量；不是 dataset 的物理长度，以提交记录为准 |
| `B` | 一次 Batch 读取的帧数（B≥1）；PA 声束数改记为 `N_b` |
| `K` / `K_g` | Scan 的固定流集合 / 流组 g 的流数 |
| `S_g` / `τ_g` / `s` | 流组 g 的固定样本数、原始 dtype 与样本索引；单流引用时也写作 `S_k`、`τ_k` |
| `E_x` | 帧相关物理对象的 extent，可大于 N |
| `N_r` | 恢复视图验证出的完整 Frame 前缀长度，不等于声明值一定正确 |
| waveform / AScan | 指定 Frame、指定流的一条原始波形 |

```text
File（一个工件）
  ├─ 工件身份
  └─ Scan 集合
       └─ 每个独立 Scan
            ├─ Scan 描述（用途/区域/来源/坐标映射模型待 D-11）
            ├─ 固定定义
            │    ├─ Scan 共享采集设置与必要几何
            │    ├─ EventDefinition 集合与接收输出
            │    └─ StreamGroup 集合：组内共享表示 + 流表（k → 事件、接收输出、逐流采样参数）+ 组解释
            ├─ Frame 轴、提交记录与独立完整前缀
            ├─ 帧级附加记录：适用的位置及状态、其他带类型记录
            ├─ 按类型/版本描述的元信息
            └─ 各流组的样本 [N, K_g, S_g] 与有效性位图 [N, K_g]
```

逻辑身份为：帧 `(Scan,n)`、事件实例 `(Scan,n,e)`、波形 `(Scan,n,k)`、样本 `(Scan,n,k,s)`。Scan 身份须在文件内唯一，跨文件结果还须携带文件来源；n/e/k 的作用域均为所属 Scan，同名局部身份或相同位置不能跨 Scan 合并。N、E_x、N_r 均逐 Scan 解释，不存在隐含的全文件 Frame 计数。k 静态关联正确的事件与接收输出，并静态属于唯一流组 g、组内序号 q；物理存储与 Core I/O 按 `(g,q)` 定位。这些元组不分配 wire 字段。

接收输出必须辨识实际保存的数据层次，例如单接收阵元信号或固定接收法则的合成波形，不能从 shape、路径或硬件通道编号推断。同一硬件接收通道在不同事件下可以对应不同流。几何、探头、法则与采样解释属于固定定义的组成或引用；内容按 META-01 描述，模式 schema 的必要信息按 REL-01/D-09 细化，不以未来 Extensions 代替当前解释责任。Core 不验证物理法则，但必要身份与关联不能藏入没有类型/版本或作用域说明的任意字典。

| 组解释 | 该组在一帧中的含义 |
|---|---|
| 通道组（多通道单晶） | 既定采集方案归组的一组多通道结果 |
| PA 声束集 | 一次采集的全部预定声束槽位及有效性位图，无效槽位零填充 |
| Tx×Rx 矩阵（FMC） | 一次预定收发矩阵的槽位及有效性位图，结构闭合与全部槽位有效分别判断 |

一个 Scan 可以有多个流组；旧 Core profile 类别限制见 DOC-01，产品的混合扫描范围仍属 D-13。事件定义不同不自动要求串行执行，共同 Frame 也不证明事件同时发生。“波形流”仅描述身份和跨帧序列，不引入逐通道时间轴、异步拼装或晚到补写。

<a id="scan-01"></a>
### SCAN-01：工件容器与独立 Scan〔确定〕

文件须能识别工件及枚举其中的 Scan。每个 Scan 独立持有固定定义、事件/流集合、Frame 轴、原始位置关联、状态和完整前缀。不同 Scan 的流数、长度、dtype、采样解释或几何可以不同，但每个 Scan 内仍遵守既有不变量及文件的采集类别限制。不能通过同名引用错误复用另一 Scan 的定义。

分块、停止后重新扫描、复扫、精扫、换探头、重装、重新标定或固定定义变化创建新 Scan，不修改旧 Scan。属于同一工件且满足旧 Core profile 类别限制时，可在同一 Writer 会话的未封存文件中创建；文件已封存后不重新打开追加原始 Scan，指定快照的后续保存另按 SNAP-01。跨文件任务关系仍可由外部清单组织，本版不定义跨文件来源解析协议。短暂停顿与一次扫描结束的区分、未封存文件干净关闭后能否重开追加，均属 D-15。

首版保持单写者，顺序完成 Scan 后再开始下一 Scan，不引入交错追加多个活动 Scan。每个 Scan 的必要解释须在文件内可解析，不以其他 Scan 的当前默认值解释历史；跨 Scan 定义去重不是本版要求。

<a id="scan-02"></a>
### SCAN-02：必要关系的具体模型〔承载方向确定，模型待定〕

REL-01 已明确目标区域、复检/局部重扫指向原扫描具体区域及快照来源的关系需求，不再讨论是否完全排除这些责任。区域包含哪些信息、具体模型与作用域，以及 UMS Run 到 Scan/文件的映射仍待 D-11，**不只是字段编码待定**。不预设每条记录必填、引用基数、无环约束或共同参考系，也不追加检测对象归属为产品必需关系；保存坐标关系不要求 SDK 执行转换。

以下仅为 D-11 的讨论范围，不作为当前强制字段或校验规则：

- 已确认目标区域及复检来源需求采用何种模型、作用域和适用条件；区域信息的具体内容与扫描用途描述。
- Scan 与工件区域、Scan 与 Scan 之间的关系类型、引用、方向、基数及合法性约束。
- 是否采用共同参考系、如何表达局部坐标关系，以及是否需要坐标映射或不可用状态。
- 关系的建立/变更时机、读取接口，以及它们是否影响封存、恢复和符合性判断。

上述模型决定前，不要求每个 Scan 提交特定映射，不把缺少这些尚未定义的关系判为错误，也不以 test-only 编码或样例预先选择答案。工件容器、多 Scan 独立身份及原始历史不可覆盖仍按 SCAN-01、WRT-02 执行；不自动拼接、融合、替代或据此宣称完整覆盖的边界不变，见 U-14。Scan 内 Frame 位置绑定、PA 声束及 FMC Tx/Rx 映射不属于本次退回待定的范围。

<a id="rec-01"></a>
### REC-01：共同记录身份〔确定〕

所有流使用同一 Scan 的共同 Frame 轴，波形可追溯到 Frame、事件和接收输出。采集层一次提交完整 Frame 或批次；SDK 不接收逐流追加后等待拼装，不进行时间配准。Frame 不统一解释为一次物理触发；来源 ID 与文件内身份不同，不得据其隐式创建网格或同步关系。

共同 Frame 轴不说明规则网格、空间邻接、位置相同、相位同步或已完成运动校正。位置值相同的帧仍有独立身份。设备来源 ID 的解释由调用者提供，其承载方式属 D-02；SDK 不做回绕展开或自动补空帧。结构闭合不等于全部波形槽位有效；无有效数据以 STA-01 的有效性位和零填充表达，不等待或补采。

<a id="rec-02"></a>
### REC-02：计数、extent 与边界〔确定〕

N 的逻辑计数范围为 u64；n 合法范围为 `0 <= n < N`。实现必须分别检查计数、索引、切片及字节长度运算，不得静默截成 32 位、溢出或把不支持的尺寸当作空选择。

实现支持上限可以低于 u64 编码上限，但必须明确报告。HDF5 的特殊尺寸常量、绑定层整数范围和内存数组限制不能直接冒充普通记录数量。

物理 extent、填充值和完整 Frame 数量必须区分。正常读取不得暴露 `n >= N` 的尾部；必要对象在前缀内缺行或关联不完整时报告结构错误，不能静默缩短后继续宣称完整。旧 `committed_count` 字面值不是本轮已冻结的路径或计数协议。

## 3. 身份、版本与能力

<a id="id-01"></a>
### ID-01：解释身份〔确定〕

文件必须携带可识别的容器格式与 schema 身份、工件身份及各 Scan 身份、采集语义身份（每个流组的组解释及其所属类别）和物理布局身份。它们分别回答“哪套公共约定”“哪个工件/扫描”“采集是什么”“数据如何组织”，不得混用。文件公共描述与 Scan 专属描述的作用域须明确，不能从同级 Scan 隐式继承定义。单晶/阵列类别、PA/FMC 含义不能仅由 shape 推测；必要语义须足以拒绝类别冲突。

“首发 profile”专指首版声明支持的符合性子集（支持的组解释、样本表示、位置描述与编码），不同于上述采集语义身份。读取器在不理解必要 schema、采集语义或 layout 时必须拒绝相应解释，不能按路径相似程度或当前设备默认值猜测。精确字段字面值、字符串编码、版本比较与兼容范围留待 D-07；不预设“同一主版本必兼容”。

<a id="id-02"></a>
### ID-02：必要能力与可选扩展〔确定〕

必须区分影响当前请求解释的必要信息和可以忽略的可选辅助块。未知可选辅助块可以跳过；未知必要语义、编码或 filter 不得静默忽略。

如果不支持位置的结构编码、不能验证其 Frame 关联，但仍能独立验证波形及记录范围，可以显式提供受限波形访问；必须报告位置/绑定读取不可用，不能伪造位置或宣布完整 profile 合规。若连记录边界也无法验证，则不能以此降级。不认识位置或元信息的领域 schema，与不能读取其公共描述、内容和索引关联不同：能够按公共约定交付时，不因此宣称已解释其业务含义，具体容器见 META-01/D-10。

扩展须具有格式标识、版本、必要类型/单位、来源与关联说明。能力声明的具体编码属 D-07。状态语义与编码边界见 STA-01。

<a id="meta-01"></a>
### META-01：公共描述与带类型/版本的内容〔确定组织，细节待定〕

元信息采用必要公共描述＋带类型/版本的扩展内容。公共描述须能辨识所关联对象、作用域及内容类型/版本；Core 负责保存、读取和结构关联，不要求理解全部设备或业务字段。固定定义继续按 Scan/事件/流作用域复用；不因可扩展而允许逐帧偷换固定定义。

REL-01 所要求的模式专属 schema 和自包含解释属于产品责任；字段全集、序列化格式、公共描述编码及读取容器仍待 D-07/D-09/D-10，不以类型/版本透传就宣称已满足领域解释。类型/版本声明不等于 SDK 已实现该领域的解释器，未知必要公共语义与未知可选内容按 ID-02 区分。

元信息可以独立读取，也须能从相应数据定位其关联内容或可核对引用；不要求每条波形重复复制定义。扩展内容不能替代 Core 必要的 Frame、流、位置及 PA/FMC 映射身份。元信息扩展不引入通用文件集合或派生成果管理；C 扫快照是 SNAP-01 已明确纳入的专用内容。

## 4. 波形、状态、位置与参数

<a id="wav-01"></a>
### WAV-01：流组内固定与自解释〔确定〕

对每个流组 g，包含无效槽位零填充的逻辑样本形状表示为：

\[
X_g \in \tau_g^{N\times K_g\times S_g}
\]

`S_g`、`τ_g`、样本表示与采样间隔在组内一致并在所属 Scan 内固定；逐流的起始延迟、事件与接收输出身份等差异以组内流表表达。跨组、跨 Scan 可以不同；单条特殊流可以独占一个组（`K_g = 1`）。一个 Scan 的原始数据是有身份的数组集合 `g ↦ X_g` 及其有效性位图，不强制为一个 `[N,C,S]` 数组。有效性位决定槽位是否代表真实波形，不能从样本是否全 0 判断。

固定描述必须足以说明各组的类型、字节序、样本含义与必要单位，以及各流的事件/接收输出映射和采样轴。若有效 ADC 位、对齐、偏置或比例不可缺少，也必须描述；不要求所有设备采用同一组 ADC 字段。相同样本索引、长度或 dtype 不证明相同物理采样时刻或信号处理层次。

实际 dtype 集合、原始整数码/物理量的具体表示和轴参数编码仍属 D-02/D-07。不得仅保存某个本地驱动函数名来替代解释。

<a id="wav-02"></a>
### WAV-02：严格接收与无损保存〔确定〕

每份标记 `valid=1` 的 waveform 必须提供样本，并与所属流组的固定长度及 dtype 严格一致。SDK 接受调用者的有效性声明，不做幅值、成像意义或其他业务合法性判断；仍须校验身份、shape/dtype、容量和引用。SDK 不自动截断、补齐、广播、重采样、信号处理或数值转换。`valid=0` 的槽位可以不提供有效内容；稠密输入缓冲中的对应位置被忽略，不作为原始数据保存，槽位按 STA-01 零填充。可选严格模式（默认关闭）下，`valid=0` 槽位出现非零样本时整个调用被拒绝（ADR-0003）。业务同构化属于显式计算输入转换，不能把转换结果描述为原始回读。写入输入缓冲归调用者，SDK 同步消费；具体布局仍属 D-02，不预设零拷贝或 TCS 输入。

标记有效且通过结构校验的样本必须无损回读，整数样本逐值一致；无效槽位没有调用者原始样本保真承诺。样本按数值语义交付：文件字节序是存储细节，读取接口交付调用平台原生字节序的数值，同一数值保持不变；改变数值或位宽的转换仍然禁止。浮点 NaN、负零等逐位保真规则须在该 dtype 被纳入支持范围前补齐，不能先声称任意类型均受支持。

<a id="sta-01"></a>
### STA-01：单一有效性位图与零填充〔确定语义，打包待定〕

本条仅适用于实际保留的原始波形槽位；RET-01 的保留状态、缺口与特征有效性另行表达，不把“未保留全波”编码成一组伪无效波形。本条不要求新增波形双位状态，也不能阻止业务状态的必要区分。

每个 `(Scan,n,k)` 波形槽位只使用一个有效性位 `valid`；粒度为整条波形，不是逐样本有效性。不独立保存 payload 存在性与业务有效性，也不区分无数据和“有值但业务无效”的原因。

**写入必须显式提交完整位图**（ADR-0003）：每次写调用须为调用内每个 Frame 的每个槽位给出有效位。位图缺失、长度不符或与流组/流身份对不上属于结构错误，整个调用被拒绝。存储初值 0 只描述尚未写入的空间，不是写接口的默认行为。

| 有效性位 | 样本含义与存取行为 |
|---|---|
| `valid=0` | 无有效数据；输入中对应样本被忽略（严格模式下非零样本报错），存储及读取的逻辑样本均为全 0 填充值，不代表真实零回波 |
| `valid=1` | 调用者声明有效，须提供符合 WAV-02 的波形；SDK 按有效数据无损保存和回读，包括真实全 0 波形 |

读取须同时交付所选波形的有效性位图，按相同 Frame/流或 PA/FMC 身份、顺序及重复项对应；不跳过无效槽位。稠密矩阵和 Batch 采用样本数组＋有效性位图，无效槽位零填充；异构结果同样保留各槽位身份、原始类型/长度及对应有效性位。不得仅凭全 0 推断无效，或将 `valid=0` 的填充值当成真实测量。具体返回容器和位图布局仍待 D-08/D-10。

存储初值 0 与波形零填充只定义已提交范围内的逻辑表示，不授权暴露预分配尾部或用初值掩盖位图缺行、损坏及关联错误；已提交行是否完整写入，由提交记录与校验和核对（ADR-0002）。未完成写入、结构损坏、解码或 I/O 失败必须报错，不能自动变成 `valid=0` 的成功结果；完整前缀及调用级失败仍按 REC-02/WRT-02/IO-01 验证。SDK 不等待补采或晚到补写，零填充不是信号补全。

零填充不要求预先物理写满整个 dataset；可以通过符合约定的 HDF5 fill value/空间分配等机制实现，但不能把逻辑全 0 等同于磁盘空间、压缩率或性能保证。位图打包、位序、HDF5 映射和接口表示仍待 D-07/D-08/D-10；存储填充按所声明样本类型表达零，具体支持类型仍按 WAV-02 闭合。

无损保证仅覆盖标记有效并被接受的波形；旧 PAYLOAD_PRESENT/CALLER_VALID 双维状态及 0/1/3 编码已被替代，不能作为当前用例的状态模型。设备报告的逐 A 扫状态（例如饱和、失同步）不改变有效性位，需要保存时作为可选附加内容（D-01/D-09）。本规则只处理波形有效性，不替代 D-01 的位置有效性决定。

<a id="pos-01"></a>
### POS-01：采集时位置绑定〔确定〕

支持不要求空间坐标的纯时间或顺序记录，不伪造零坐标。要求位置的扫描中，波形有效但位置获取失败时仍须保全有效波形，并明确位置未知/无效；波形有效性与位置状态分开。实际位置及其状态须有明确的采集记录关联；旧 Core 的多通道单晶共享关联、PA 唯一原始映射位置见 PA-01。绑定基于 Frame 身份，不依赖时间戳、浮点坐标相等或最近邻搜索。FMC 的矩阵关联不自动提供各收发对的独立空间位置，更细的运动定位模型暂缓。

绑定读取必须对波形、状态与位置使用同一 Frame 选择及对应顺序，并关联正确的固定定义。位置是采集时写入的历史值，不得被后处理或 overlay 静默替换。采集层负责采集关联准确性；SDK 只验证可表达的结构与关联，不进行插值或校准。

无位置记录与位置失败时保全有效波形的业务行为已确定。D-01 仅继续细化适用性、未知/无效位置的表示及读取合同，不再保留“一律拒绝有效波形”作为并列选项；不得用零坐标或波形无效位替代位置状态。

<a id="pos-02"></a>
### POS-02：位置描述边界〔确定〕

位置仿照元信息，采用必要公共描述＋带类型/版本的内容。不同 Scan 可以使用不同位置描述，同一 Scan 的位置描述固定，每帧保存一份对应值。描述须能说明具体实例的字段、类型、必要单位、轴/参考对象、来源及版本；不预设 XYZ、四元数、编码器轴数或完善的领域 schema。A/B 编码器计数可以作为一份位置值的两个字段，不要求转换成物理坐标。

实际反馈坐标、理论坐标、时间戳、设备来源 ID 等每帧内容统一作为**帧级附加记录**（ADR-0001）：每类记录在 Scan 内有固定的类型/版本/字段/单位/来源描述，每帧一行，与 Frame 在同一提交单元写入，按 Frame 索引关联；不转为每束一份独立位置，也不替换帧级原始位置。需要位置时，位置值或其未知/无效状态必须可解释；无需空间位置的记录不要求位置值。其他记录的必要性、值缺失表示及是否影响提交/封存仍待 D-01；不由此承诺晚到补充已提交记录的能力。

独立反馈流不得要求通过时间配准才能恢复 Frame 位置绑定。首版仅按索引关联，不按位置查找数据；未来其他匹配方式与位置 schema 一起规划。Core 不计算坐标变换、标定或空间网格，也不承诺自动恢复 B/C/D 排列。具体编码与无效位置表示仍为 D-01。

<a id="pa-01"></a>
### PA-01：唯一帧位置与派生声束解释〔确定〕

PA 声束集是一个流组的解释，声束 b 映射到组内流。第 n 帧原始关系为 `Frame_n = (P_n, {W_n,b}, 状态与关联)`。PA 帧所有声束共用帧级原始位置 P_n，例如同一对 A/B 编码器值，不为 `N_b` 个声束另存 `N_b` 份独立位置测量。读取结果可随束交付这一引用，但事实来源保持在 Frame 层。POS-02 的其他帧级附加记录是独立的按帧关联内容，不改变同帧共享位置的原则；多个独立运动探头的位置模型属 D-13。

声束空间解释依赖 `P_n + 固定探头/安装几何 + 对应固定聚焦法则及必要解释`。束号必须找到正确事件和接收输出，不与法则、硬件通道或阵元编号混用。参考样例一组法则对应一个保存声束，不把它变成所有设备的假设。

入射点、方向、焦点与样本空间位置不是同一对象，样本定位可能还需传播模型。本轮不定义坐标字段或几何算法。原始读取不以定位完成为前提；派生声束位置或图像不覆盖 P_n，共享 P_n 不代表束在工件中位置相同。旧“PA 逐事件独立采集位置”候选已被替代。

<a id="par-01"></a>
### PAR-01：固定采集定义的作用域与复用〔确定〕

Scan 共享设置只保存一次，事件专属设置每个事件保存一次；流组共享的表示与采样间隔每组保存一次，逐流差异以组内流表保存，不为每条流建立独立的定义对象（ADR-0001）。固定参数指整个采集程序与定义不随帧变化；预定执行 L0、L1、L2 后在下一帧重复，不属于修改参数，也不要求程序只有一种法则。

本轮不需要逐帧 config_index、动态快照历史、生效区间或重复法则内容。所有必要固定引用须存在且可解释；真实采集设置、方案、流组划分、流身份、长度、dtype 或采样解释变化应新建 Scan，是否另建文件按 SCAN-01 判断，不能更换定义或增加配置引用维持旧身份。固定性的作用域为 Scan，不要求同文件所有 Scan 共用一套定义。位置、波形与状态是可变化的观测结果，不因参数固定而移除。

固定定义遵循 META-01/REL-01；模式 schema 须包含解释已有数据必需的设备、探头、法则等信息，D-09 保留具体必要内容与表示的未决项。不依赖设备当前默认值或只保存本地驱动函数名代替解释，不承担物理法则校验或扫描复现。上述固定性仅指采集解释参数；在线分析设置变化与快照采用参数按 SNAP-01 区分，不因此强制新建原始 Scan，也不恢复逐批次分析参数历史。

<a id="par-02"></a>
### PAR-02：旧动态快照字节区〔已替代〕

`data + offsets` 动态快照字节区不是当前模型的必要对象或活动参考映射。保留编号用于项目内历史追踪，不表示 PASS；其职责已由 PAR-01 的固定定义复用取代。固定定义采用何种序列化仍待 D-09，不预设 JSON。

<a id="fmc-01"></a>
### FMC-01：固定 Tx/Rx 映射与覆盖〔确定〕

Tx×Rx 矩阵是流组的解释。固定有序发射集合 I、接收集合 J 及映射 π 定义 `M_n[i,j] = X_π(i,j)[n,:]`，π 指向流 k。首版一个 Tx×Rx 矩阵限于单个流组；跨组（异构）矩阵的解释归属与声明方式属 D-14；行是 Tx，列是 Rx。流目录顺序、组内序号、物理排列或扁平编号不构成隐式映射。

声明为完整矩阵的采集域必须覆盖 I×J，每个有序收发对有明确且唯一的逻辑流对应；引用须存在，流的事件发射身份与接收输出须与对应 Tx/Rx 一致。不同有序对不得别名到同一测量身份。物理打包或共享存储对象不等于共享逻辑波形。

普通单阵列完整 FMC 样例中 I、J 为选定的同一阵元集合，包含全部有序对。覆盖声明须说明阵元范围，子孔径不冒充全探头。`Tx0→Rx2` 与 `Tx2→Rx0` 保持独立；不利用互易性合并、推算或复制另一半矩阵。只采集部分收发对（HMC、Sparse）或以法则/平面波为发射单元（PWI）的矩阵，其声明方式属 D-14，不能借 `valid=0` 冒充未采集的收发对。

帧结构闭合与矩阵全部槽位有效分别判断：预定槽位及关联明确可结构闭合；声明域全部对的 `valid=1` 才能称矩阵数据全部有效。SDK 不另行判断业务合法性或记录独立的 payload 存在性。无有效数据的对采用 `valid=0` 和零填充，不作为真实零信号；固定映射缺口、未完成写入或解码失败不能转换成无效槽位。具体位图编码和读取容器仍待 D-08/D-10。

<a id="fmc-02"></a>
### FMC-02：矩阵访问与异构结果〔确定〕

访问层须在一个明确 Frame 内交付完整矩阵、固定 Tx 行、固定 Rx 列、有序 Tx×Rx 子矩阵、显式收发对清单及给定样本选择。这些选择由选择层在 Core I/O 结果上完成（ADR-0006），不要求每项独立函数；不能只交付未解释的流集合，让调用者自行维护映射。Batch 可包含同一 Scan 的多个 Frame；其选择及内存布局按 READ-03/D-10 细化，不自动规定任意离散帧清单。

矩阵、流和单波形视图使用同一原始来源，不维护两份可分别修改的事实。一般矩阵单元为：

\[
M_n[i,j]\in\tau_{ij}^{S_{ij}}
\]

所选单元长度和 dtype 一致时必须可取得单 Frame 的逻辑轴序 `[Tx,Rx,Sample]` 稠密数值视图，同时返回对应有效性位图；Batch 保留各 Frame 身份以及矩阵/样本轴，物理排列及具体返回 shape 待 D-10。逻辑轴序不承诺连续内存或一次 I/O，显式转置须保留轴身份。无效单元按 STA-01 零填充，不跳过、不仅因无效而拒绝稠密交付，也不得将填充值当作原始测量或宣称矩阵数据全部有效。

共同物理时间轴还要求采样解释一致；仅 shape/dtype 一致时只能声明按样本序号堆叠，并保留各流解释。异构时返回有 Tx/Rx 身份的波形矩阵或分组结果，不隐式转换、填充或截断。同构主路径不降为只有逐流访问，矩阵读取也不强制全扫描驻内存。

TFM 消费收发波形及对应路径的传播时间；不同收发对可能取不同样本。按传播时间选样还依赖各流的采样起点、间隔及必要解释，不能仅由矩阵 shape 推出。逐对选样可以在已读输入块上执行，不要求逐像素磁盘读取。本轮不实现传播时间、TFM 或图像重建；Tx/Rx 轴不是工件网格，派生图像不替代原始矩阵。

## 5. HDF5 组织边界

<a id="map-01"></a>
### MAP-01：逻辑语义与物理组织分离〔确定边界，编码待定〕

本轮不规定 HDF5 路径、chunk、压缩、缓存或定义序列化。逻辑职责如下，不是已冻结字段表；`TBD` 不得作为实际文件的万能解释。

| 逻辑对象 | 逻辑形状/关系 | 编码边界 |
|---|---|---|
| 工件容器 / Scan 集合 | 工件身份、Scan 枚举；用途/区域/来源/坐标映射模型待定 | 容器语义 SCAN-01；Scan 映射关系 SCAN-02/D-11，协同 D-01/D-07/D-09 |
| 解释身份 | schema、Scan、采集语义、物理布局 | 必要语义确定，字面值/版本/路径 D-07 |
| 固定定义与元信息 | Scan/事件/接收输出、流组共享表示与流表、组解释及必要引用；公共描述＋带类型/版本的内容 | META-01、PAR-01、REL-01；必要解释内容 D-09，编码 D-07 |
| Frame 轴与帧级附加记录 | 身份、适用的位置及状态、其他带类型帧级记录；无空间位置记录合法 | POS-01/02；缺值与必要性 D-01，编码 D-07 |
| 各流组样本 | 每组 `[N,K_g,S_g]`、dtype τ_g；有效样本无损保存，无效槽位零填充 | 参考映射为每组一个 dataset；零填充不要求预先物理写满 |
| 有效性位图 | 每组 `[N,K_g]`，每槽位一位，与样本身份对应 | STA-01；打包/位序/路径 D-07/D-08 |
| PA/FMC 映射 | 束→组内流；Tx/Rx→流 | 必须明确，不由目录顺序或组内序号推断 |
| 前缀、提交记录与生命周期 | 各 Scan 的提交记录、物理块校验值、完成/失败/恢复范围；文件封存 | WRT-02、LIF-01/02；参考机制 MAP-02，编码 D-07 |
| C 扫快照及保留内容 | 正式数值、来源及解释，支持仅特征或混合保留 | RET-01、SNAP-01；组织及写入合同 D-16，不预设伪波形或物理布局 |
| 可选辅助块 | 自解释扩展及其关联 | 不替代适用的位置、固定定义或采集语义 |

HDF5 datatype、dataspace 与布局是不同属性，Frame 不要求一帧一个 group。初始化不要求知道最终 N；采用逐行组织的必要对象须覆盖 `[0,N)`，位置编码也须能验证该段逻辑关联。预分配使 E_x>N 本身不是错误，但不能仅凭 extent 判定封存。

物理设计需要区分以下机制；这些说明不分配生产路径或默认值：

| 机制 | 本项目中的解释与约束 |
|---|---|
| datatype | 描述存储元素的类型、位宽及字节序，不由 shape 决定；HDF5/绑定层可执行类型转换，不意味着 SDK 可跳过 WAV-02 的严格输入校验或改变原始样本 |
| dataspace / extent | 描述数据轴及物理尺寸；预分配或 resize 不等于 Frame 逻辑提交，完整前缀由 REC-02/WRT-02 验证 |
| chunk / filter | chunk 是物理分块和常见压缩处理单元，不是事件、波形流或事务身份；逻辑样本窗口会触发整块解码；重写含已有数据的块时，HDF5 原地覆写（大小不变或无压缩）或释放后重新分配，已实测可破坏已 Flush 的数据（ADR-0002） |
| HDF5 chunk cache / OS cache | 缓存层不同，命中会改变读取代价但不得改变逻辑结果；逻辑样本吞吐不等于磁盘物理带宽 |
| 属性与固定描述 | HDF5 对象属性和 dataset 数据可以承载编码，但对象路径及数组维度本身不提供采集含义；必要身份、单位和引用仍须明确 |

旧 SPLIT 路径和 CTS/TCS 只可作为适用工作负载的历史参考，不升格为所有模式的强制映射。样例可采用明确标记的 test-only 编码；物理设计选择不得改变语义和保真要求。写出文件的 libver 范围为 v1.10–v1.14，不使用 2.0 专有特性；单个 chunk 小于 4 GiB；复数样本若纳入支持，采用实部/虚部复合类型（ADR-0005）。

<a id="map-02"></a>
### MAP-02：写入保护与读取原子性的参考机制〔参考〕

以下是满足 WRT-02/WRT-03/IO-01 的一种候选，供 M1/M2 取证，不冻结路径与编码。实验原型与证据见 `experiments/m1/`。

1. **物理块只写一次**：SDK 按流组组装整块、自行编码（可在 HDF5 锁外并行），用直接块写入（`H5Dwrite_chunk`）写出；Scan 完成时最后一个半满块也只写这一次。写入不经过 HDF5 块缓存，原始数据写错误同步返回。
2. **Flush 尾部日志**：各帧轴对象的半满尾部写入两个交替槽位的尾部日志，不碰主数据集；把数据与日志写给操作系统（`H5Fflush`）后，再写两个交替槽位的提交记录（序号、各对象行数、校验值），然后再次 `H5Fflush`；不需要 `fsync`（ADR-0008）。
3. **恢复**：选择序号最大且校验通过的提交记录；主数据集只读取完整块部分，尾部从对应的日志槽读取，逐块核对校验值。
4. **可选 SWMR**：每个 Scan 先在非 SWMR 状态下创建全部对象，再进入 SWMR 追加（HDF5 须关闭并重开文件才能退出 SWMR；这种会话内重开不算 LIF-01 的关闭，期间崩溃的恢复须单独取证），获得元数据写入顺序与不回收空间的性质；代价是 SWMR 期间不能新建对象或写变长字符串，帧级记录须为定长类型。
5. **push 两阶段读**：先读入并校验本调用所需的全部存储块，再解码写入目标；暂存只占存储字节。存储损坏在修改目标之前就被发现；校验通过的数据仍解码失败属于实现缺陷，此时目标内容未定义，须作为内部错误报告。

## 6. 写入和生命周期

本节保留原始波形 Core 的写入、Flush、封存及恢复契约（ADR-0002、ADR-0008）；新增快照保存的业务保护按 SNAP-01，具体协议待 D-16，不能直接宣称 MAP-02 已覆盖。正式编码与剩余取证属 D-05/D-07；断电与操作系统崩溃不在既有保证范围内，本次不扩展或重验该保证。

<a id="wrt-01"></a>
### WRT-01：提交单元、提交校验与写失败态〔确定〕

**提交单元**是一次写调用提交的全部 Frame，它们属于一个明确指定的活动 Scan，不跨 Scan。单写者通过同步单 Frame 或 Frame 批次接口追加；每帧结构须闭合，可按 STA-01 标记无效槽位并零填充，不等待或补采。SDK 必须在写入任何文件对象或推进提交记录之前，对整个提交单元完成结构校验：Scan 身份；覆盖全部槽位的显式有效性位图及其与流组/流身份的关联；有效波形的存在性/shape/dtype；位置适用性、位置值或未知/无效状态及其他必需帧级记录的存在与类型；容量和固定引用。任一 Frame 校验失败则整个调用被拒绝，逻辑帧数量、提交记录与已提交数据均不变。不得通过帧提交偷换固定定义。

写入慢时允许阻塞，不主动丢弃已交付数据或静默跳过记录，不提供写入取消。输入缓冲由调用者维持，SDK 同步消费；调用返回后不再借用该缓冲，后续 Flush 不得依赖调用者仍保留原输入。普通写入成功不要求立即落盘。设备缓存、停采及归组由调用方处理。

**写失败态**：写调用、Flush、完成 Scan 或封存过程中出现任何 I/O 错误时，该调用按 IO-01 失败并报告原因/错误码，Writer 进入失败态，拒绝继续追加；不得把它当作输入校验失败后重试。失败态只允许两种操作：放弃并关闭；或在全部已提交数据通过校验后带失败标记封存（LIF-01）。具体错误码与可重试条件属 D-10。

<a id="wrt-02"></a>
### WRT-02：提交记录、完整前缀与不可变历史〔确定〕

每个 Scan 由 SDK 维护**提交记录**：已提交帧数 N、各帧轴对象的有效行数及校验值。提交记录是该 Scan 可见范围的唯一依据；HDF5 dataset 的 extent 只是上界，不能据此推断提交（REC-02）。正常写入流程中 N 单调不减；新 Scan 从自己的 Frame 轴开始。推进提交记录前，相关波形、位图、帧级记录和固定定义依赖须已完成写入步骤；普通写入不强制逐次持久化。已提交 Frame 及其历史解释不得原地修订或晚到补写。

每个物理块必须带完整性校验值（存储字节与解码后字节），作为深度检查、恢复核对与“旧数据未变”的独立观察依据（VAL-01）；算法与编码属 D-07。

这是 SDK 维护的逻辑顺序，不是 HDF5 自带的跨 dataset 事务。HDF5 重写含已有数据的块时会原地覆写或重新分配空间，仅最后更新 N 不能证明旧数据安全（ADR-0002）；实现须保证已提交数据所在的物理块不被重写，其文件空间也不被复用，参考做法见 MAP-02。

<a id="wrt-03"></a>
### WRT-03：显式 Flush 与成功后条件〔确定〕

除普通同步写入外，提供显式同步 `Flush`。普通写入成功不等于已持久化；Flush 不完成 Scan、不封存文件、不开放在线读取，也不修复失败调用。

**成功后条件**：Flush 返回成功后，此前全部成功写入的 Frame 及解释它们所需的元数据，在之后任意时刻发生进程崩溃（包括后续追加、Flush、完成 Scan 与封存期间）后，均能由恢复模式完整恢复并通过校验。断电、操作系统崩溃与存储设备故障不在保证范围内（ADR-0008）：SDK 不对其作承诺，也不为其取证；此类事件后，文件可能丢失最近的写入或无法打开，恢复模式只能尽力而为。

**实现要求**：Flush 须把 SDK 与库缓存中的相关数据交给操作系统（Linux 本地文件系统上，进程退出后内核仍会写回其页缓存）；不要求操作系统层同步，是否另行同步属实现选项，不构成对外承诺。只调用 `H5Fflush` 不足以满足该后条件：之后重写含已 Flush 数据的块时发生进程崩溃，仍可能破坏这些数据（ADR-0002）。

Flush 失败按写失败态处理；它不意味着此前写入已撤销，也不削弱此前成功 Flush 的后条件。持久化不等于调用级事务。

<a id="io-01"></a>
### IO-01：调用级强原子性〔确定边界，机制待定〕

每一次数据读写调用（单帧、Batch、A-Scan 均同）都是一个成功/失败单元（ADR-0006）。任一部分发生 I/O 错误，或因存储数据损坏导致解码失败时，整个调用失败并返回原因/错误码；不交付可消费的部分结果，也不通过悄悄缩短数量报告成功。

- **push 读失败**：调用者目标缓冲逐字节保持调用前状态，随调用交付的位图、位置和元信息也不被部分更新。
- **poll 读失败**：不发布本次视图或部分结果；先前借用已在本次读取开始时到期（BUF-01），不因失败恢复有效。
- **写失败**：不新增已提交 Frame；失败调用不得覆写或修改已提交的数据与关联，并且这一点能通过校验值观察到（WRT-02）。文件中允许留下不可见的未提交空间。Writer 进入失败态（WRT-01）。
- **范围**：本条不是崩溃一致事务。进程崩溃后的保证只由 WRT-03 的 Flush 后条件给出，断电与操作系统崩溃不作保证；未 Flush 的成功写入不自动获得持久化保证。

“此前成功写入的数据不变”的观察路径有两条：带失败标记封存后的正常读取，或恢复模式读取；两者都须核对校验值，只检查 N 或热缓存不足以证明。push 读的参考实现是两阶段读（MAP-02）。HDF5 不提供跨对象事务，失败后 resize 或只撤销计数都不足以证明上述目标；机制未验证前，不能把仅返回整体错误的实验计为 IO-01 通过。

原生调用与语言绑定之间的分配、封送、结果构造失败另属 D-10/D-12。例如原生写入已提交后绑定构造结果失败，不能未经决定就等同于本条的 I/O 失败；应优先把可能失败的准备工作放在提交或目标复制之前，仍存在的失败必须能区分已提交、未提交与未知。

<a id="lif-01"></a>
### LIF-01：Scan 完成、封存与读取〔确定〕

文件生命周期有三条路径：初始化 → 顺序写入 Scan → 正常封存；进入 Writer 失败态 → 带失败标记封存或放弃；未正常关闭。Scan 生命周期为：定义/初始化 → 追加 → 完成，或故障（Writer 失败态时活动的 Scan 在带失败标记封存后保持未完成，读取方看到其已提交范围与失败标记）。完成 Scan 后拒绝继续追加，同一 Writer 会话可开始下一个 Scan；上一个 Scan 未完成时创建新 Scan 须被拒绝，不隐式完成。**完成 Scan 隐含一次 Flush**，并写入该 Scan 的完成与校验记录；它不等于文件封存，普通读取仍等待整个文件封存。

正常封存需核对 Scan 集合、每个 Scan 的完成状态与提交记录、已确定的必要定义及 Scan 内关联，并以等价 Flush 结束；不得把未完成 Scan 静默跳过后宣布全文件正常。D-11 尚未决定的区域/来源/坐标映射不作为当前封存前提。空 Scan 与无 Scan 文件能否正常封存，留待 D-05/D-10。“完成”仅指存储记录闭合，不证明区域实际覆盖或工件检测完成。

**带失败标记封存**：Writer 处于失败态时，若全部已提交数据通过校验，可以封存：先持久化已提交范围，以等价 Flush 结束，并在文件中标记失败原因及失败时的提交范围；读取方可以正常读取已提交数据，并看到失败标记。校验不通过或封存本身失败时，文件按 LIF-02 恢复。

Writer 未封存即关闭（含进程退出、析构或终结器）视为未正常关闭，按 LIF-02 处理，不隐式宣布封存成功；干净关闭后能否重开追加属 D-15。普通读取面向已封存文件，原始数据追加入口必须拒绝修改已封存文件；另行新增/替换指定快照按 SNAP-01，不能沿用旧的全文件禁止更新规则拒绝此能力。实时显示走采集内存，不读取增长中的文件。正常文件若不能满足必要结构和引用约束，应明确报错，不得自动当成有效的较短扫描。

<a id="lif-02"></a>
### LIF-02：尽力只读恢复〔确定〕

未正常关闭的文件通过显式恢复模式处理，不伪装成正常封存：

1. 不修改源文件。打开前若须清除状态标志（例如 HDF5 v3 superblock 在写者崩溃后留下的写访问标志），只能在副本上或只在内存中清除（不写回源文件，M1 已验证一种做法），或使用不要求清除标志的只读路径（例如写者处于 SWMR 时的 SWMR 只读）。建议在独立进程中执行恢复，因为损坏文件可能使解析库崩溃。
2. 依据提交记录建立每个 Scan 的候选前缀，逐块核对校验值，暴露验证通过的范围 N_r；不把填充值或可解码字节自动认作完整 Frame。提交记录缺失或不可信时，不凭各 extent 最小值猜测恢复数量。
3. 报告声明范围、验证范围、失败对象及未执行的检查；结构可读、可解码与校验通过三者须区分。
4. 不原地续写、修复或截断源文件。超出可信前缀的抢救、提交记录损坏后的重建策略留待 D-05。

上述验证逐 Scan 执行。某 Scan 失败不允许静默缩短或合并其他 Scan；能独立验证的 Scan 可显式报告为恢复子集，但不代表整个文件正常。D-11 的映射关系验证等待模型决定。HDF5 group 不构成事务或故障隔离边界，文件级元数据损坏仍可能使多个乃至全部 Scan 无法访问。

恢复本身是尽力而为，不预设最大损失时长；但不能以“尽力恢复”免除 WRT-03 的 Flush 后条件。不得将不完整尾部或损坏记录改成 `valid=0` 并零填充来掩盖故障。

## 7. 读取语义与规模

<a id="read-01"></a>
### READ-01：独立和绑定访问〔确定〕

SDK 提供波形、位置、元信息的独立及关联访问，具体函数签名不属于本文。每次 Core I/O 数据请求指定一个 Scan、单 Frame 或 Batch 的 Frame 选择，以及一个或多个流组（CORE-01）；这是既有原始 Core 路径，产品访问优先级另按 ACCESS-01/D-03。A-Scan 读取是选择层在单帧结果上的取用（ADR-0006），其 I/O 代价由物理块大小决定（D-04）；不新增逐流追加写入。波形返回对应有效性位图，独立波形读取不强制解码位置，但须满足 ID-02。两种交付方式见 READ-03，均保留 Frame、流组、流及事件/输出来源。

访问层还须能枚举/选择 Scan 并识别所属工件；用途、目标区域、Scan 间来源及坐标映射的读取能力等待 D-11。不能默认第一个或“最新”Scan；Batch 在同一 Scan 内选择 Frame，不隐式拼接不同 Scan 的轴、统一 dtype 或筛选替代结果。即使各 Scan 的 n/k 和位置相同，也须保留独立数据来源，不据此推导空间映射或按位置查询。

绑定访问按 POS-01 保持关联，保留无效波形槽位及其有效性位并按 STA-01 零填充，不重新按时间匹配、不以 overlay 替换历史位置。一个请求无法满足时必须显式报告，不以空数组或零位置伪装成功。

读取操作本身不更新文件；相同数据与选择条件下，等价成功读取须返回相同数值、有效性位、位置和元信息关联，不因前一选择、缓存、poll/push 或交付用途改变。poll 视图只读且有借用期限；push 的调用者缓冲可以复用，其内存变化不更新文件。多次读取一致不表示旧 poll 指针永久有效或 push 目标永不覆盖。失败行为见 IO-01；并发范围见 CORE-01；位图接口/布局、Batch 布局和错误码仍待 D-08/D-10。

<a id="read-02"></a>
### READ-02：选择结果语义〔确定语义，API 编码待定〕

除 Frame/Batch 与流组选择外，下列帧内选择属于选择层（CORE-01）：作用于 Core I/O 结果的纯函数，不做文件 I/O，也不另行组合 poll/push 或 IO-01。语义用于访问规划和 UC 验证；不冻结函数签名、返回类型、异常名称或负索引等 API 扩展语法（D-10）：

- Frame 可单独指定或由 Batch 选择多个，Batch 起点/数量或离散索引语法尚未冻结；不得因此自动声称支持任意清单。同一 Frame 内有序 Stream、PA 声束、Tx/Rx、配对和 Sample 清单保序保重复，例如 `[2,0,2]`。Batch 输出须保持所声明的 Frame 顺序及全部关联；若后续开放有序 Frame 清单，同样不得静默排序或去重。
- Tx 清单与 Rx 清单的交叉选择为笛卡尔子矩阵；显式收发对清单只返回列出的对，不展开成子矩阵。
- 样本边界按每个选中流自己的 S_k（即所属组的 S_g）检查，不以最长流的边界替代其他流，不静默截断、补齐或溢出。
- Sample 清单 `[3,1,3]` 表示按顺序交付原始样本 `s=3、1、3`，不能排序或去重后改变结果；逐流/逐对给定样本清单时，同一要求分别适用。此类显式有序清单不等于已经确定负步长切片等逆序 API 语法。
- 选择结果保留 Frame、流组/流/轴身份、有效性位、固定定义关联；绑定结果还保留原始位置来源。
- 逐对样本选择表或窗口作用于已读数据块；不承诺每项选择单独触发磁盘 I/O。

本项目用半开区间 `[a,b)` 和可含重复项的有序清单表达预期，不冻结 API 语法、返回对象形态或异常类名。少量空选择、单元素、首尾、越界变体属于后续用例素材；具体空结果表示、负索引或逆序语法留待 D-10，不可用空结果伪装越界成功。

请求跨组的异构流集合时，必须明确报告越界流及相关范围，不静默截断、补齐或伪装整个请求成功。采用整个请求拒绝，还是显式逐项结果/错误的形式，本轮不决定，留待 D-10。不支持的选择须明确报告，不能算能力通过，也不能削弱 FMC-02 的目标能力。

Core I/O 调用失败遵守 IO-01，不得用逐项错误容器交付部分成功；上述选择校验的具体报告形式不放宽 I/O 原子失败要求。`valid=0` 是正常数据状态，读取时按 STA-01 交付零填充和对应位图，不等同于 I/O 错误；I/O 错误也不能转换成无效槽位。

<a id="read-03"></a>
### READ-03：分析读取与 Batch 内存视图〔方式确定，布局待定〕

提供两种关联内容交付方式，共用同一文件来源，不维护两份可独立修改的数据。它们描述内容/用途，与 BUF-01 的 poll/push 内存所有权是两个维度，不把分析读取限定为 push，也不把 Batch 限定为 poll：

1. **常规分析**：返回数据及关联元信息、位置/状态，保持 Frame/流组/流/事件身份；固定描述可以共享，不要求逐波形复制。具体容器及元信息选择形式待 D-10。
2. **Batch 消费**：一次同步读取同一 Scan 的 B 个 Frame，通过 poll 借用 SDK 只读内存视图，或通过 push 复制到调用者缓冲供上传 GPU。结果须附可核对的范围、类型、形状/偏移及身份关联说明，不能只返回无法解释的裸地址。

流组内同构，因此每个请求的流组都可以交付为一个稠密 `[B,K_g,S_g]` 样本块及 `[B,K_g]` 有效性位图；跨组时的多缓冲/偏移描述、Batch 选择形式以及是否携带完整元信息仍待 D-10。有效波形不隐式转换、填充或截断来拼成一个数组。无效槽位零填充，随样本交付有效性位图，不跳过槽位；位图与数据缓冲的具体布局仍待 D-08/D-10。主机指针不代表 GPU 设备指针、固定页内存、GPU 解压或零拷贝；SDK 本轮不负责 GPU 上传与异步传输调度。

<a id="buf-01"></a>
### BUF-01：poll/push 缓冲与同步生命周期〔确定所有权与借用结束条件，表示待定〕

本文沿用 poll/push 名称：poll 指消费者经 SDK 同步拉取并借用结果，不是轮询任务状态；push 指 SDK 在同步调用中向指定目标复制，不是后台主动推送。两种读取模型都支持，写入仍由调用者提供输入缓冲、SDK 同步消费。

| 模型 | 内存所有者与操作 | 有效期 |
|---|---|---|
| poll | SDK 读取/必要时解码到自己管理的主机内存，成功后返回只读借用视图；调用者不得释放或修改它 | 至同一 Reader 的下一次样本数据读取调用开始，或该 Reader 关闭，以先发生者为准（ADR-0004） |
| push | 调用者提供可写目标及容量，SDK 同步读取并复制数据；SDK 不接管目标分配/释放 | 由调用者管理；关闭 Reader 或对其他缓冲读取不会使其失效，复用该目标会覆盖内容 |

**借用结束条件**：同一 Reader 上任何交付样本数据的读取调用（poll 或 push，无论成功、失败还是被参数校验拒绝）在开始时结束先前的 poll 借用；不承诺失败后旧视图恢复有效。目录、固定定义、元信息与容量查询不结束借用；只读取位置或帧级附加记录的调用视同样本数据读取。各 Reader 的借用彼此独立。选择层结果须在接口上标明是独立副本还是继承源 poll 借用期的视图。依附 poll 结果内存的关联位置/元信息视图遵循同一借用期，不能只保存裸指针后在下一次读取继续使用；独立复制的内容不受此借用期影响。push 的调用者目标在失败时按 IO-01 保持不变。

“磁盘上的内存指针”不是此处的物理实现：可解引用指针必须指向进程可访问的内存。poll 不承诺把 HDF5 文件偏移直接当作指针，也不承诺 mmap、固定地址、免解压或零拷贝。实现可以复用或重新分配 SDK 缓冲；旧视图到期不等于必须立即覆写，但调用者不得再使用它。

单个 Reader 同一时刻只有一份 poll 视图。GPU 上传若异步执行，poll 调用者须在上传完成前不在同一 Reader 上发起下一次样本读取或关闭；需要双缓冲流水线时使用 push，或使用两个 Reader。push 调用者须在上传完成前保持目标缓冲有效且不复用/修改。SDK 的同步返回不等于外部 GPU 操作已完成。

语言绑定须表达借用期/所有者；仅保留 Reader 对象引用不能延长已结束的 poll 视图，push 则须避免调用中 Python/.NET 缓冲移动或释放。不默认自动复制来延长 poll 寿命；绑定可以在仍有导出视图时拒绝下一次读取（例如 Python 的 `BufferError`），是否采用属 D-12。裸缓冲导出、派生视图及受检包装的选择仍待 D-10/D-12；Python/.NET 对象仍存活不证明底层借用有效。后续须分别验证派生视图、失败读取、显式关闭、GC/终结器和异常路径释放；不能以永久保留全部旧分配来绕过借用期或有界资源要求。本条不承诺自动撤销已经导出的裸地址。

SDK 不在同步返回后继续借用调用者的 push 目标或写入输入。缓冲长度/布局/对齐、元信息容器及容量报告形式待 D-02/D-10；须检查运算和容量，不允许越界。poll 缓冲及 push 两阶段读所需的暂存都须有界；内部暂存不改变对外所有权，也不构成全链路零拷贝承诺。

<a id="cap-01"></a>
### CAP-01：超 RAM 访问〔确定〕

目标是超过 100 GB 的单文件，每个 Scan 的 N 仍在 u64 范围内，不要求其总和可表示为一个全局 N。写入缓冲和读取缓存必须有界，不随各 Scan 的总 Frame 数线性增长；波形、位置、状态、相关定义及 Scan 目录访问均须有界，不能要求打开时全量物化所有 Scan 的定义。正常打开不要求扫描全部波形，深度检查单独执行。

连续批量写入、Frame 随机读、GPU 上传前的 Batch 读及 A-Scan 随机读是已有候选负载；产品的布局/访问优化优先级按 ACCESS-01/D-03 重新据实际需求明确，不把原 Frame/Batch 优先约定固化为全部内容的优先级。单 Frame 不提供帧内分块交付；A-Scan 随机读须解码其所在的整个物理块。支持的 Frame/Batch 大小和容量要求须明确，超出上限须明确失败，不能偷偷改为部分结果或分块接口。调用者可控制 Batch 大小，不要求全扫描或整个通道驻内存；SDK 不在调用返回后保留 push 目标的引用，调用者可以复用目标缓冲（BUF-01）。原子失败所需暂存与写入端整块组装缓冲也须计入内存预算。本阶段不做布局/压缩/cache 调优；小文件测试不证明规模目标。

D-02/D-03 的资源口径须区分调用者输入/目标、SDK 结果及原子暂存、HDF5 缓存/解码工作区、位图/位置/元信息和绑定副本，明确请求上限、峰值口径及超限检查时机。调小 Batch 不能解决单 Frame 超限；实际 Frame 规模和上游交付证据应先约束支持范围，不能只用小型 H/P/F/W 推断设备适配性。.NET Framework 单个托管数组上限约 2 GiB（D-12），超过者须走非托管内存。具体预算值尚未确定。

## 8. 压缩与解码

<a id="cmp-01"></a>
### CMP-01：无损与依赖可识别〔确定〕

压缩用于降低磁盘流量与长期容量，必须满足 WAV-02。文件的有效 filter 编码链和必要参数必须可识别，读取端可以部署第三方 filter；缺少解码器或不支持参数时明确报告，不能回退为错误数值。解释所需的编码不得藏在 HDF5 filter 链之外的私有封装里。

不固定 codec、级别、chunk、线程或缓存参数（D-04）。压缩率不是本阶段的设计或验收指标，此前的压缩测试只用于 codec 选型。“具有 filter ID”不表示所有 HDF5 安装均自带解码器。生产带宽规划不得以合成数据或单份样例的压缩率作为不可压缩输入仍不丢数据的证明。选择首发编码链时须同时评估 CPU 读取端的部署可得性与 GPU 解码的可得性（D-04/D-06），以免日后启用 GPU 能力需要改写既有文件。

<a id="cmp-02"></a>
### CMP-02：GPU 可选能力的声明〔确定〕

CPU 可读路径是基础，GPU 解压是待验证的可选能力（D-06）。声称 GPU 解压时，必须验证从实际存储的压缩表示到样本的完整链路，包括封装、压缩块、预处理逆变换、尾块及存在的校验。

主机先解压再 H2D 不属于 GPU 解压。缺少 GPU 不影响基础 CPU 读取符合性；GPU 厂商、库、输出顺序和性能阈值不在本版指定。

压缩字节在主机到设备间传输后再由 GPU 解码，与主机先解码再传输原始样本，是两条不同的消费路径。后续比较须包含实际传输字节、解码、预处理逆变换、必要布局转换及下游消费代价，不能仅凭传输量减少或单独解码计时宣称端到端更快。具体测量规划见 SPEC_TEST_PLAN 的性能与 GPU 专项；本轮没有运行验证。

## 9. 符合性检查与错误解释

<a id="val-01"></a>
### VAL-01：分层、可追溯的验证报告〔确定〕

检查必须区分文件错误、不支持的能力、调用者标记的无效槽位以及尚未验证；不增加独立的业务合法性检查：

| 层次 | 检查对象 | 不足以证明什么 |
|---|---|---|
| 识别 | 格式/布局标识、必要能力、解码依赖 | 不证明数据完整 |
| 结构 | 各流组类型/shape、固定定义、位图与声明长度、提交记录 | 不证明全部字节已正确落盘 |
| 关联 | Frame 前缀、原始位置与帧级附加记录、事件/接收输出引用、PA/FMC 映射 | 不证明物理位置准确或成像正确 |
| 深度 | 逐块校验值（存储字节与解码后字节，WRT-02）、分批解码与内容比对 | 不证明性能或设备不丢数据 |

校验值是格式的必需部分；不匹配是文件错误，不能降格为无效槽位或静默缩短。恢复报告另按 LIF-02 区分声明范围、验证范围与未执行的检查；带失败标记封存的文件须报告失败标记（LIF-01）。

测试记录至少包括 Spec 修订、采用的参考映射/临时编码、输入样例、规则编号、检查层次、执行结果和未覆盖项。结果可以表达 PASS、FAIL、NOT_RUN、BLOCKED、UNSUPPORTED 等含义，但正式错误码与报告序列化格式未定。

待定编码造成的 BLOCKED、选择未实现的 UNSUPPORTED、未执行的 NOT_RUN 都不得计为完整符合性通过。未知可选块被跳过，也不等于该块已经被验证。

当前没有发布符合性检查器或正式样例文件。`experiments/m1/` 中的 test-only 原型与独立核对脚本只产生实验证据，不是符合性检查器。完整规范的冻结需要解决必要编码项并取得独立读取证据，见 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。

## 11. 契约修订流程

按“候选规则 → 正反样例 → 独立检查 → 修订规则”迭代。每次规则升级说明需求依据、影响的数据解释、旧实验样例是否仍适用及验证证据，理由写入 `docs/decisions/` 下的 ADR（ADR-0007）。改变记录含义不能伪装成纯性能优化。

文档职责：需求理由在 DESIGN.md；规则与必要机制解释在本文；决定理由在 ADR；访问覆盖在 ACCESS_USE_CASE_PLAN.md；样例、覆盖和执行证据在 SPEC_TEST_PLAN.md/实验报告。其他文档引用规则编号，不重述规则；不要在其他文档或测试代码中维护第二套隐含规范。采用 HDF5 或借鉴通用采集概念不构成与其他文件格式、SDK 或算法实现兼容的声明。
