## 1. 如何选择与使用

不必一次回答所有问题，可以只选一个角度，或限定到一种设备、采集模式和算法。未掌握的信息保留为“尚不清楚”；实际不存在的场景标为“不适用”，不据此扩展格式。

需要区分三类内容：

| 类型 | 要解决的问题 | 可用依据 |
|---|---|---|
| 事实补充 | 设备或业务实际如何工作？ | 设备说明、接口/调用示例、实际采集方案、算法输入说明 |
| 工程选择 | 在已知约束下，产品或 SDK 采用什么行为？ | 候选方案、适用范围、取舍理由及正反例 |
| 实验取证 | 某项保证在目标环境中是否成立？ | 可复核的正确性、持续负载、资源和故障实验结果 |

事实不能由实验默认值代替；工程选择不能代替设备能力；完成文档不能代替运行证据。本文列出的行为选项只是讨论提示，不表示已经采纳。

## 2. 设备与采集语义

<a id="angle-01"></a>
### 角度 1：Scan 起止与暂停

在已采纳多 Scan 方向下，需要补充：

- 哪些实际动作表示 Scan 开始、完成或中断，何时封存整个工件文件？
- 运动暂停、设备暂停、短暂停顿与结束后重启如何区分？
- 是否需要显式表示目标区域或来源 Scan？如果需要，它们的业务含义、模型及必要性是什么，而不是先指定关系方向、基数或无环约束？
- 是否需要共同工件参考系或 Scan 坐标映射？若需要，关系由谁提供，作用域及不可用情况怎样讨论？

适合提供的材料：一个工件的分块及局部复扫/精扫流程，说明 Scan 边界和实际空间/来源关系需求；未知项留空，不要求先构造区域或变换。

当前约束见 [R-01/R-12](DESIGN.md#r-01)及 [SCAN-01](DATA_SPEC.md#scan-01)，问题入口为 A-01、[SCAN-02/D-11](DATA_SPEC.md#scan-02)。不再把“是否允许多 Scan”列为待决策，但每个 Scan 的映射关系仍待决策；自动拼接、结果替代及已封存文件重开追加仍不在当前范围。

<a id="angle-02"></a>
### 角度 2：Frame 归组与事件/输出映射

需要补充：

- 一帧包含哪些预定事件、接收输出和波形流？设备按整帧、逐事件还是逐通道交付？
- 采集层如何判断归组完成？缺输出、来源 ID 跳号/回绕/重复时如何处理？
- 事件、硬件通道、阵元、合成输出和声束身份分别来自哪里？
- PA 的束如何对应事件、输出和法则？FMC 的有序 Tx/Rx 集合和 π 如何取得，是全探头还是子孔径？

适合提供的材料：一份采集方案和一帧交付示例，附事件/输出/流对应关系；设备不适用的模式无需填写。

关联 D-02/D-08/D-09、A-03/A-05。边界见 [REC-01](DATA_SPEC.md#rec-01)、[PA-01](DATA_SPEC.md#pa-01)、[FMC-01](DATA_SPEC.md#fmc-01)：归组由采集层承担，不将逐流拼装或晚到补写转移给 SDK。

<a id="angle-03"></a>
### 角度 3：样本表示与采样轴

需要补充：

- 各流实际 dtype、长度范围、字节序、有效 ADC 位、对齐、偏置及必要比例是什么？
- 保存的是原始整数码、物理量、RF、IQ、包络还是其他处理层次？哪些表示确实需要首版支持？
- 采样起点、间隔、延迟和单位如何解释？不同流是否使用共同物理时间轴？
- 若需要浮点或复数，原始表示与特殊值保真要求是什么？

适合提供的材料：按流列出的数据描述、少量可核对样本及采样轴解释，不以本地驱动函数名代替含义。

关联 D-02/D-07/D-09、A-07；契约见 [WAV-01](DATA_SPEC.md#wav-01)和[WAV-02](DATA_SPEC.md#wav-02)。可限定首版支持类型，不必先承诺所有 dtype；算法转换与原始存储分开。

<a id="angle-04"></a>
### 角度 4：原始位置与异常位置

需要补充：

- 位置描述探头、工件还是运动机构？参考系、轴向、单位、来源及标定关系是什么？
- 一帧跨多个事件或采集期间持续运动时，帧级位置代表哪个时刻或状态？设备能提供怎样的精度或新鲜度依据？
- 位置是否可能缺失、无效或过期？采集层和算法分别期望拒绝帧、明确保存异常关联还是停止采集？
- 空间显示是否还需要扫描线、方向或拓扑信息？这些信息来自哪里？

适合提供的材料：位置数据示例、参考对象说明，以及正常/异常位置下的操作预期。

关联 D-01/D-09、A-02/A-04。原始绑定与位置描述见 [POS-01](DATA_SPEC.md#pos-01)、[POS-02](DATA_SPEC.md#pos-02)；位置值不代替 Frame 身份，零坐标不代替缺失决定。更细运动模型若超出现有范围，单独记录冲突。

<a id="angle-05"></a>
### 角度 5：固定采集定义及外部解释依赖

需要补充：

- 设备能否导出完整固定采集程序及离线解释必需的设置？哪些属于 Scan、事件或流？
- PA 所需探头/安装几何和法则、FMC 阵元解释、各流采样解释有哪些具体内容？
- 真正的设置变化如何被检测并切换 Scan？哪些变化只是观测结果变化？
- 标定、声速、传播模型及空间映射中，哪些是解释原始数据必需的，哪些只属于特定算法？外部依赖如何追溯？

适合提供的材料：实际方案导出或字段说明，并标注“必要原始解释 / 算法依赖 / 可选辅助”。

关联 D-02/D-09、A-05/A-09/A-11；固定定义规则见 [PAR-01](DATA_SPEC.md#par-01)。H/P/F 的关联标记不是实际设备子 schema；不要因此宣称真实几何或完整算法可复现性已解决。

## 3. SDK 行为与消费接口

<a id="angle-06"></a>
### 角度 6：写入缓冲、确认与取消

需要讨论：

- 输入缓冲由谁持有，调用者什么时候可以复用或释放？同步消费、复制或借用方案各有什么限制？
- 批量调用成功、取消或 I/O 失败时，如何说明已接受范围及不确定范围，避免重复重试？
- 调用成功表示接收、完成写入还是某种确认点？如何与 flush、持久化和最终封存区分？
- 设备缓存多大、能否暂停、可容忍怎样的阻塞？调用方在阻塞或取消期间怎样工作？

适合提供的材料：采集缓冲生命周期、调用时序及设备停采/缓存能力说明。

关联 D-02/D-05/D-10、A-06；提交与前缀规则见 [WRT-01](DATA_SPEC.md#wrt-01)、[WRT-02](DATA_SPEC.md#wrt-02)。接口选择不能放宽完整 Frame 提交、前置校验或故障后停止正常追加的边界。

<a id="angle-07"></a>
### 角度 7：缺 payload 与错误结果

需要讨论：

- 首版是否开放显式缺 payload 写入？若开放，输入表示和结构闭合条件是什么？
- 缺失矩阵请求采用明确缺失的单元结果、掩码还是拒绝稠密交付？
- 异构请求一项越界时，是请求级拒绝还是逐项结果/错误？
- 空选择、不支持能力、位置无效与结构/解码错误如何分别表达？
- 算法怎样处理业务无效或明确缺失的数据，而不是由 SDK 隐式过滤？

适合提供的材料：几组输入/请求及预期结果说明，先说明含义，不必先选异常类或错误码。

关联 D-01/D-08/D-10、A-11；状态与选择语义见 [STA-01](DATA_SPEC.md#sta-01)、[READ-02](DATA_SPEC.md#read-02)。拒绝缺 payload 写入，不等于取消读取端的缺失诊断边界。

<a id="angle-08"></a>
### 角度 8：读取、分批及结果所有权

需要补充或选择：

- 一个实际算法需要哪些 Frame、流、束、Tx/Rx、配对和样本选择？是否滑窗、重叠或多遍回访？
- 结果缓冲由谁持有，下一次读取/迭代后是否仍有效？消费者能否保留、复制或并发处理？
- 哪些操作确实需要连续数组，哪些只需逻辑轴序和有身份的异构结果？
- 大请求如何分批，取消后如何结束迭代并释放缓冲和文件句柄？
- 独立位置与波形读取如何供消费者核对来源？

适合提供的材料：一个真实算法调用示例，说明选择、输出、解释依赖、消费时序和缓冲需求。完整工作负载记录入口见 [场景审计第 4 节](SCENARIO_AUDIT.md#4-算法输入与读取方式核查)。

关联 D-03/D-10、A-08/A-10/A-12；访问能力见 [访问规划](ACCESS_USE_CASE_PLAN.md)。不默认所有读取都零拷贝或连续，也不因实现方便改变保序保重复及逐流边界语义。

## 4. 正式格式与运行证据

<a id="angle-09"></a>
### 角度 9：正式格式与独立读取

需要讨论：

- 首个正式 profile 支持哪些模式、样本表示、位置描述和固定定义？如何限定支持范围？
- format/schema/profile/layout、版本与必要能力如何精确编码和解释？
- 状态、生命周期、计数、引用、字符串和字节序如何映射到 HDF5？
- 必要解码器如何部署，未知必要语义或 filter 参数如何拒绝？
- 独立读取器还需要哪些未写入正式说明的约定？

适合提供的材料：拟支持范围及必要编码方案，配套正反样例和独立读取证据规划。

关联 D-01/D-07/D-09、T-22；身份及组织边界见 [ID-01](DATA_SPEC.md#id-01)、[ID-02](DATA_SPEC.md#id-02)、[MAP-01](DATA_SPEC.md#map-01)。精确解释映射与性能默认值不是同一件事；可以先闭合一个范围明确的 profile。

<a id="angle-10"></a>
### 角度 10：真实负载与物理调优

需要补充并取证：

- 持续/突发输入速率、典型扫描规模和实际请求序列是什么？
- 延迟、阻塞、内存预算和输出连续性要求是什么？哪些是期望目标，哪些是已有测量？
- 目标机器、CPU、磁盘及解码依赖环境是什么？
- 能否取得可用于实验的真实波形和不可压缩压力输入？
- 在固定语义及负载下，如何比较布局、chunk、codec、cache、批量和预分配？

适合提供的材料：一份目标环境与工作负载说明；初期可先补事实和目标，不立即确定调优参数。

关联 D-02/D-03/D-04、A-12；测量方法见 [验证计划第 6 节](SPEC_TEST_PLAN.md#6-性能与-gpu-专项)。历史微基准的限制见 [BENCHMARK_REPORT.md](BENCHMARK_REPORT.md)，不能替代真实负载或超 RAM 证据。

<a id="angle-11"></a>
### 角度 11：封存、持久化与恢复

需要讨论并取证：

- Scan 完成与文件封存分别怎样检查？是否允许空 Scan 完成或无 Scan 文件封存，接口如何表达？
- Scan 目录及各 Scan 的完整前缀由什么建立可信依据？声明值、extent 或标记不可信时怎样报告？
- 磁盘满、I/O 失败、进程中断和断电分别怎样影响已接受数据？
- 部分压缩 chunk 更新中断是否影响旧帧？哪些损坏可检测，哪些只能报告尚未验证？
- 恢复报告怎样区分结构可读、可解码、内容已核对及未执行检查？

适合提供的材料：异常结束时的用户预期、候选确认/封存协议，以及受控故障实验计划。

关联 D-05/D-07/D-10、T-12/T-15；边界见 [LIF-01](DATA_SPEC.md#lif-01)、[LIF-02](DATA_SPEC.md#lif-02)。恢复仍是显式尽力只读，不预设零损失、固定时间窗或自动修复；讨论实验不等于授权破坏性故障操作。

<a id="angle-12"></a>
### 角度 12：可选 GPU 解压

需要补充并取证：

- 目标 GPU、库、实际 filter 链及下游计算输入是什么？
- 压缩封装、逆变换、尾块及校验是否全部能够正确处理？
- 与 CPU 解码对照时，原始样本及轴身份是否一致？
- 包含传输、解码、布局转换和下游消费后，端到端收益是什么？

适合提供的材料：目标 GPU 消费路径及实际编码链，而不只是一个 GPU 解码函数计时。

关联 D-06、T-20；声明边界见 [CMP-02](DATA_SPEC.md#cmp-02)。该方向可独立暂缓，不阻塞基础 CPU 读取。

## 5. 建议的选择顺序

以下是推进建议，不是新增里程碑完成条件，也不要求现在选择全部主题：

1. **真实采集方案**：优先选角度 1～5；从一种设备、一种采集模式开始，核对实际输入是否符合当前模型。
2. **真实算法与最小接口**：选角度 6～8，明确一条消费路径及实验缓冲/结果约定，为后续 M1 提供输入。
3. **正式互通**：选角度 9，在有限支持范围内闭合必要解释，面向 M2。
4. **生产运行证据**：选角度 10～11，取得实际负载与目标环境，再推进 M3 的规模、持续输入及恢复验证。
5. **可选加速**：角度 12 独立推进，面向 M4。

里程碑及证据状态以 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md#milestones) 为准，D 项的具体阶段依赖以 [DATA_SPEC 闭合表](DATA_SPEC.md#closure-gates) 为准。暂缓某一方向不表示该项已解决，也不阻止其他独立方向继续补充。

## 6. 后续补充与调整方式

可以直接指定“角度 4：位置异常”或“角度 6＋8：缓冲所有权”，再说明适用设备/算法、已知事实、拟调整行为、依据和仍不明确的内容；不必先填写完整方案。

实际场景证据使用 [SCENARIO_AUDIT 的记录模板](SCENARIO_AUDIT.md#6-审计记录与收敛方法)维护，本文不复制证据或已采纳决定。讨论结论按现有职责落回：

- 需求/范围变化 → `DESIGN.md`。
- 数据语义、编码、接口语义边界及 D 项决定 → `DATA_SPEC.md`。
- 实际设备/算法事实与范围冲突 → `SCENARIO_AUDIT.md`。
- 访问覆盖调整 → `ACCESS_USE_CASE_PLAN.md`。
- 正反样例、验证方法和实际执行证据 → `SPEC_TEST_PLAN.md` / 对应实验报告。

若结论改变当前契约，先明确修订依据，再同步相关文档和后续断言。本文仅保留选择角度与问题入口；已解决问题以权威文档为准，必要时更新这里的引用或移除不再适用的问题，避免形成第二套待定状态。
