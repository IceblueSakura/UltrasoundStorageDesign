<a id="core-scope"></a>
### Core 范围与本轮决定

最终目标是通用超声数据存储管理 SDK，承担数据的高效读写及数据、位置、元信息的关联访问。首版仅设计和开发基于 HDF5 的 **Core**：文件内管理，不实现文件集合管理或派生资源管理。未来相关能力及更多领域 schema 沿 **Core + Extensions** 方向扩展；这不是 HDF5 自带的产品 schema，也不表示本轮实现扩展插件体系。

本轮采纳以下边界；数据契约落在 DATA_SPEC 对应规则中，不以本文替代编码规范：

| 决定 | 理由与剩余边界 |
|---|---|
| 元信息采用必要公共描述＋带类型/版本的扩展内容 | Core 保持身份、作用域和关联；不在本阶段设计完善的领域 schema，更多 schema 可由未来 Extensions 提供 |
| 位置采用相同描述方式，Scan 内描述固定、每帧保存一份值 | 不同 Scan 可使用不同描述；PA 同帧所有声束共用位置。其他坐标内容以额外 dataset 按帧关联，不由 SDK 做坐标计算 |
| poll/push 两种同步读取缓冲模型 | poll 借用 SDK 管理的只读内存，下一次读取或关闭文件时失效；push 同步复制到调用者指定缓冲，由调用者管理。写入仍同步消费调用者输入，不承诺直接磁盘指针或全链路零拷贝 |
| 同步单 Frame／Frame 批次写入，无写入取消 | 普通写入不要求立即落盘；另提供显式 Flush 强制落盘，持久化协议仍需设计和验证 |
| 单一有效性位图＋无效槽位零填充 | 初版不区分缺数据与“有值但业务无效”；接受调用者有效性声明，有效样本原样保存，无效槽位不保留输入内容。位图与样本一起交付，真实全 0 与无效零填充可区分；具体打包和 API 待定 |
| 两种内容交付：随元信息返回、Batch 消费 | 常规分析关联元信息；GPU 消费按 Batch 读取多个 Frame。用途与 poll/push 所有权分别定义，不相互绑定；不自动恢复任意 Frame 清单语法 |
| Frame 优先、A-Scan 次之，单 Frame 不分块交付 | 优先满足 Frame/Batch 读写，A-Scan 是次级读取视图；Batch 大小及缓冲布局待定，不要求实现单 Frame 内分块接口 |
| 批次 I/O 调用级强原子性，失败给出原因/错误码 | push 读失败目标不变；poll 失败不发布部分新结果，旧借用期已在下次读开始时结束；写失败无新增提交且旧数据不变。不要求物理布局复原或崩溃事务；机制仍需设计 |
| 读取不提供 update，多次等价读取值一致 | 文件只读与结果视图只读分别约束；调用者复用缓冲不构成更新文件，update 留待未来规划 |
| 单读单写、串行调用 | 不提供线程安全保证，不支持并发 Reader；不改变封存后读取边界，不表示同一文件可同时读写 |
| 目标平台为最新 Linux LTS、Windows 10+ | Linux 的具体发行版及版本基线待确认；本阶段不规划部署方案 |
| 优先支持 Python、.NET Framework 4.8，原生实现倾向 C/C++ | 功能集中，便于使用 pybind11 等成熟绑定工具；pybind11 是 Python 候选路径，不解决 .NET 绑定，具体语言/ABI 仍未冻结；.NET Framework 4.8 消费端面向 Windows |

本次仍只推进设计，不启动 SDK 实现、测试或物理参数调优。有效性位图打包/接口、Batch 布局/选择、调用级强原子性机制及 Flush 持久化协议仍未闭合；单一有效性和零填充语义已定，不再讨论是否另存“有值但业务无效”。原子性边界已定，不以同步调用或一次错误返回代替实现证据。平台/语言剩余决定登记在 D-12。

| <a id="r-06"></a>R-06 | 调用者维持缓冲，同步单 Frame／Frame 批次写入允许阻塞、不提供取消；普通写入不要求立即落盘，显式 Flush 用于强制落盘；Core 不负责设备背压、缺失补全或端到端采集不丢数据保证 |

| <a id="r-10"></a>R-10 | 无损压缩用于降低采集磁盘流量和长期容量，允许第三方 filter；GPU 解压是期望的可选能力 |
| <a id="r-11"></a>R-11 | Scan、事件、流的采集设置分别固定，每份定义保存一次；不要求逐帧参数快照或 config_index。观测位置、波形和状态可变化；派生结果与辅助块不改写原始历史 |
| <a id="r-12"></a>R-12 | 多 Scan 服务于分块扫描工件、复扫/精扫特定区域；原始结果并存，不自动拼接、融合或替代旧结果。每个 Scan 的区域、来源及坐标映射关系均待决策，不仅是编码待定；工件容器不等于完整覆盖证明 |
| <a id="r-13"></a>R-13 | 首版为文件内存储管理 Core，公共描述与带类型/版本的元信息、位置内容分离；未来 Extensions 可提供更多 schema，不要求本轮完善领域模型 |
| <a id="r-14"></a>R-14 | 首版单读单写、无并发 Reader 或线程安全保证；平台、语言支持目标及偏好见 Core 范围，精确支持矩阵待 D-12 |
| <a id="r-15"></a>R-15 | 批次 I/O 失败报告原因/错误码：push 目标不变；poll 不发布部分新结果且不延长旧借用期；写失败无新增提交且旧数据不变。不要求物理布局复原或崩溃事务，机制待验证 |

## 2. 职责划分

```text
设备与采集层
  ├─ 按固定采集方案归组完整 Frame、各流波形及原始关联
  ├─ 采集内存 → 实时显示
  └─ 同步提交结构闭合的 Frame/批次及波形有效性位图
          ↓
       SDK 单写者 → 单一 HDF5 工件文件
                         ├─ 顺序写入：Scan A 完成 → Scan B 完成 → …
                         ├─ 文件正常封存 → 普通离线读取
                         └─ 异常结束 → 显式尽力只读恢复，逐 Scan 报告
```

SDK 负责存取、结构校验及 Frame/事件/接收输出/位置/元信息关联，不做缺失补全、设备协议解码或业务字节序转换，也不做时间配准、位置插值、标定、包络、门指标、聚焦或几何重建。文件自身必要的类型和编码仍须有明确约定，不将这些存储描述等同于设备数据处理。帧级原始位置的采集准确性由采集层负责；共同 Frame 轴不证明物理同步或完成运动校正。

无效波形槽位的零填充是存储表示，不是补采或推算真实信号。SDK 接受调用者的有效性声明，但仍检查有效波形是否提供、dtype/长度、容量、身份和引用；文件损坏及 I/O 错误不能改成无效位来掩盖。此决定简化初版状态模型，取代原“有 payload 但业务无效仍保留样本”的要求；正式逻辑契约见 STA-01。

同步式单写者降低并发与缓冲复杂度，不引入无界异步队列。设备缓存和归组策略属于调用方，不作为 Core 必须设计的协议；其输入规模、速率可作为以后存储负载验收的依据。阻塞调用不证明设备可以无限暂存，也不等于断电后零损失。

## 3. 主要架构决策及理由

| 决策 | 理由与边界 | 数据契约入口 |
|---|---|---|
| 固定 HDF5 2.x，一套公共 schema | 不再做后端选型；采集语义与物理布局分离，模式通过必要语义区分而非 shape 猜测 | [ID-01](DATA_SPEC.md#id-01)、[MAP-01](DATA_SPEC.md#map-01) |
| Core + Extensions，首版只做 Core | 文件内管理与业务扩展分开；公共描述不绑定完整设备/位置 schema | [CORE-01](DATA_SPEC.md#core-01)、[META-01](DATA_SPEC.md#meta-01) |
| 文件为工件容器，Scan 为独立采集单元 | 分块及复扫/精扫可一起交付；每个 Scan 仍有固定定义、局部 Frame 轴和独立前缀，不将多次扫描拼成动态配置的大 Scan | [SCAN-01](DATA_SPEC.md#scan-01) |
| 多 Scan 结果并存，映射关系后置 | 先支持工件容器和独立扫描；区域/来源/坐标关系的模型及约束待定，不因应用目标预设字段或映射，也不自动融合 | [SCAN-01](DATA_SPEC.md#scan-01)、[SCAN-02](DATA_SPEC.md#scan-02) |
| 三个主体定义及一个 Frame 组合记录 | Scan、EventDefinition、WaveformStream 职责明确，不新增三套模式专属主体；采集层归组 | [逻辑模型](DATA_SPEC.md#logical-model)、[REC-01](DATA_SPEC.md#rec-01) |
| 流间异构、流内固定 | 保留设备原始表示；不能为了稠密数组而隐式转换。同一硬件接收通道在不同事件下可对应不同流 | [WAV-01](DATA_SPEC.md#wav-01)、[WAV-02](DATA_SPEC.md#wav-02) |
| 单一有效性位图，无效零填充 | 不为初版增加无效原因及双维状态；以位图区分真实零波形和填充值，有效样本保真，不承诺保存无效输入内容 | [STA-01](DATA_SPEC.md#sta-01)、[WAV-02](DATA_SPEC.md#wav-02) |
| 扫描/事件/流固定定义保存一次 | 固定程序重复执行不产生参数历史；真实定义变化新建 Scan，不要求整个文件共用定义 | [PAR-01](DATA_SPEC.md#par-01) |
| PA 一帧共用一份位置，额外坐标以 dataset 关联 | 不逐束重复位置；实际反馈与理论坐标等保持独立来源，不计算变换或覆盖原始位置 | [POS-01/02](DATA_SPEC.md#pos-01)、[PA-01](DATA_SPEC.md#pa-01) |
| FMC 显式矩阵语义与共享来源 | 流视图与 Tx/Rx 矩阵视图等价；同构可稠密，异构保留单元表示，互易对独立 | [FMC-01](DATA_SPEC.md#fmc-01)、[FMC-02](DATA_SPEC.md#fmc-02) |
| 物理布局后置 | 逻辑流不必对应一个 dataset，Frame 不必对应一个 group；旧 SPLIT 只是历史参考 | [MAP-01](DATA_SPEC.md#map-01) |
| 完整 Frame 提交、完整前缀、不修订历史 | 波形、状态、位置和固定定义依赖保持一致；不把逻辑闭合包装成 HDF5 事务 | [WRT-01](DATA_SPEC.md#wrt-01)、[WRT-02](DATA_SPEC.md#wrt-02) |
| 封存后读取，不做在线文件读取 | 实时显示已有采集内存路径，首版无需 SWMR 或跨进程发布协议 | [LIF-01](DATA_SPEC.md#lif-01) |
| 异常只读恢复 | 保留原始证据，避免自动修复或续写扩大损失；恢复范围由故障测试决定 | [LIF-02](DATA_SPEC.md#lif-02) |
| Frame/Batch 优先、poll/push、有界内存 | 常规分析与 GPU 上传共享来源；poll SDK 缓冲与 push 调用者缓冲分别管理，单 Frame 不分块，不要求全扫描驻内存 | [READ-01/03](DATA_SPEC.md#read-01)、[BUF-01](DATA_SPEC.md#buf-01)、[CAP-01](DATA_SPEC.md#cap-01) |
| 显式 Flush 与批次原子失败 | 普通写入与强制落盘分开；错误不能只统一返回码而留下未说明的部分成功 | [WRT-03](DATA_SPEC.md#wrt-03)、[IO-01](DATA_SPEC.md#io-01) |
| CPU 解码基础路径，GPU 解压可选 | GPU 完整编码链兼容性尚无证据，不应成为基本可读性的前提 | [CMP-01](DATA_SPEC.md#cmp-01)、[CMP-02](DATA_SPEC.md#cmp-02) |

SPLIT/CTS/TCS 可在适用的同构工作负载中作为后续物理实验对照，不是公共 schema 的强制组织。代表性负载包括连续批量写入、Frame 随机读、GPU 上传前的 Batch 读取和次级 A-Scan 随机读；Frame/Batch 优先，比例、尺寸与指标待定。本阶段不调优，不为布局改变数据含义；主机只读指针不等于 GPU 内存、零拷贝或 GPU 解压。

Bitshuffle + LZ4、Blosc2 + Bitshuffle + LZ4 及低级别 Zstd 仅是可探索的压缩候选，不作为本轮选型优先级或测试前提。布局、压缩参数及缓存全部暂缓；后续选择由真实工作负载与部署证据驱动。

### 3.1 本轮逻辑收敛与尚未验证的边界

v0.2 已替换同构共同触发、动态快照以及排除 PA/FMC 的旧前提。其余边界继续保留；若实际场景与新契约冲突，应显式修订需求、Spec 和测试，而不是在实现里加入例外。

本次进一步用“一个工件文件包含多个独立 Scan”替换原一文件一扫描限制。多 Scan 扩展不改变封存后只读、同文件类别限制或不自动融合的范围；文件未封存时顺序创建 Scan，已完成 Scan 不再追加。跨 Scan 数据共用物理文件，不获得 HDF5 group 级故障隔离保证。

- **Scan 与轨迹**：分块/复扫/精扫以独立 Scan 承载；每个 Scan 的映射关系（含区域、来源和坐标模型）保持待决策，撤回上一轮提前设定的关系约束。短暂停顿仍需场景证据，Frame 轴不等于空间邻接或实际覆盖。
- **输出与测点**：接收阵元、合成输出、硬件通道和声束身份分开；共享帧位置不表示各输出的物理测点重合。
- **存储消费**：保留帧内流/束/FMC 选择及 Batch 多 Frame 读取；本轮将“全部读取由调用者持有缓冲”修订为 poll/push 双模型，不做单 Frame 内分块。数据随单一有效性位图返回，无效槽位零填充；位图/数据布局及失败保证的机制继续讨论。
- **运行边界**：实时算法走采集内存，文件算法面向封存或显式恢复视图；若实际需求要求增长文件读取，属于范围变更。
- **正确性与性能**：先用有独立期望值的小样例确认语义，再定义资源与延迟目标；SPLIT、压缩候选和 GPU 期望均不构成生产性能保证。

具体问题与设计细节索引集中在 [SCENARIO_AUDIT.md](SCENARIO_AUDIT.md)，不在这里维护第二份待定项清单。

## 4. 首版不包含的范围

- 文件集合管理、派生资源管理及完整 Extensions 产品实现；完善的设备、元信息和位置领域 schema。
- 按位置查询或其他非索引匹配；后续匹配能力与位置 schema 一起规划。Batch 读取已纳入，不自动承诺任意离散 Frame 清单语法。
- 单 Frame 内分块交付、写入取消、读取 update；不把批次指针交付扩为 GPU 上传调度或 GPU 内存管理。
- 线程安全、并发 Reader、部署打包方案；本阶段不做 chunk/codec/cache 等细节调优。
- PA 与 FMC 的同文件组合采集方案；这是当前不覆盖，不是硬件上的必然禁令。
- 独立通道时间轴、同一流动态变长或采集定义在同一 Scan 内变更。
- Scan 内 Segment/Round、跨 Scan 自动拼接、重扫融合、结果替代优先级或完整重建模型；Scan 间映射/来源关系另列 D-11 待决策，不当作已确定能力。
- 分卷、多写者、在线文件读取、独立背压协议。
- SDK 等待缺通道、乱序组装和已提交记录的晚到补写。
- 波形 payload 存在性与业务有效性的独立状态、无效原因分类及无效输入波形的原样保留；不增加 SDK 业务合法性判断。
- 自动修复/原地续写异常文件、严格断电零损失保证。
- 已封存文件重新打开追加 Scan、多个活动 Scan 交错追加、跨 Scan 固定定义去重。
- overlay 加载与冲突合并；仅保留原始历史不覆盖的边界。

同工件的文件内扫描归组由工件容器承担，跨文件任务可由外部清单处理。区域、来源关系、辅助计划/反馈和记录位置不等于完整扫描拓扑，不能因此承诺自动生成 B/C/D 空间排列。

## 5. 渐进完善与文档职责

需求不足的部分保持待定，不以实验默认值替代。后续优先处理故障/持久化保证、位置异常与提交条件、数据/位图接口及跨语言生命周期，同时补充首发范围和真实输入/资源依据。单一有效性与无效零填充、poll/push 的所有权与借用期、同步读写、无写入取消等已定语义不重开。待定项统一登记在 [DATA_SPEC.md 第 10 节](DATA_SPEC.md#open-items) 的 D-01～D-12。
