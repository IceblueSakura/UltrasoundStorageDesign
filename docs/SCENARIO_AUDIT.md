# 扫描场景与算法需求审计

状态：已同步 ADR-0011 的业务边界，A-01 已收到 UMS 扫描流程输入；当前只核对需求，不执行设备、算法或既往 SDK 实验。

本文只维护事实问题与证据入口，不维护第二套 schema，也不是算法实现或审计通过报告，文档职责按 [设计维护原则](DESIGN.md#integration-policy)划分。

需求与选择理由以 [DESIGN.md](DESIGN.md) 为准，语义和不变量以 [DATA_SPEC.md](DATA_SPEC.md) 为准，待定项只在其 [D-01～D-18 登记表](DATA_SPEC.md#open-items)维护。本文 A 编号是讨论主题，不是需求；访问选择见 [ACCESS_USE_CASE_PLAN.md](ACCESS_USE_CASE_PLAN.md)，独立样例及执行状态见 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md)。

## 1. 本轮要回答什么

当前先核对超声数据的必要解释、关系、保留内容、快照、基础取值及子集访问，范围见 BUS-01～MEAS-01。点云、标注/缺陷、复杂处理及导出不进入 SDK；混合范围暂缓。以下原始 Core 调查保留为后续工程输入，不把设备归组、定位或算法正确性转为 SDK 责任：

1. 上游提交的 Frame 如何声明流身份、有效波形及单一有效性位图？
2. 必要公共描述与带类型/版本的元信息、位置内容如何保存和关联？模式专属解释是 SDK 责任，具体必要信息待 D-09。
3. 分析/Batch 与 poll/push 怎样保留样本/有效性位图关联、表达借用期和调用者所有权？
4. 调用级原子性与 Flush 的成功后条件已定（[ADR-0002](decisions/0002-durability-and-failure.md)，只覆盖进程崩溃，见 [ADR-0008](decisions/0008-process-crash-scope.md)）；参考机制还需哪些证据？

Frame/Batch/A-Scan 是已有候选负载，实际优化优先级待 D-03；原始 Core 的同步/分块限制不等于整个产品访问范围。指定快照写入和基础取值按 SNAP-01/MEAS-01，本轮不调优。设备缓存、扫描控制和算法信息仅用于解释输入或记录范围冲突，不作为 Core 必须实现的协议。

既有原始 Core 模型内保留的事项（不自动适用于所有新内容或混合扫描）：核心类型及 Frame 身份见 [逻辑模型](DATA_SPEC.md#logical-model)；流组与组间异构/组内固定见 [WAV-01](DATA_SPEC.md#wav-01)；固定参数见 [PAR-01](DATA_SPEC.md#par-01)；单一有效性位图与无效零填充见 [STA-01](DATA_SPEC.md#sta-01)；PA 唯一帧位置见 [PA-01](DATA_SPEC.md#pa-01)；FMC 矩阵语义见 [FMC-01](DATA_SPEC.md#fmc-01)、[FMC-02](DATA_SPEC.md#fmc-02)。实际设备不符合这些规则时，记录范围冲突，不在实现中偷偷加入例外。

既有工件容器可关联多个独立 Scan，不自动融合，见 [SCAN-01](DATA_SPEC.md#scan-01)。目标区域关系及复检指向原扫描具体区域已确认；区域信息范围、模型及 Run/Scan/文件映射待 [SCAN-02/D-11](DATA_SPEC.md#scan-02)。不追加对象归属为产品必需关系，不把旧容器定为唯一业务组织。

## 2. 先对齐四种“顺序”

| 对象 | 当前设计能表达什么 | 本轮要查的缺口 |
|---|---|---|
| Frame 索引 `n` | Scan 内身份和结构闭合前缀，允许以无效位标记无有效波形并零填充 | 上游提供的身份与位图如何承载；设备归组不由 Core 完成 |
| 设备来源 trigger/event ID | 可选诊断/追溯信息，不等于 Frame 身份 | 跳号、回绕、重复语义；多事件来源怎样说明，不默认补空行 |
| 原始采集位置 | Frame 绑定历史位置；PA 层级已确定 | 参考对象、单位、有效性、精度、来源及运动期间的位置含义 |
| 空间网格/算法顺序 | 目前未定义自动重建映射 | 扫描线、方向、邻接关系、重复位置与缺点如何处理 |

位置相同不等于同一 Frame，帧相邻不等于空间相邻，共同 Frame 不证明事件同时发生。真实采集准确性由采集层负责，SDK 不补时间配准。

### UMS 扫描流程记录（A-01）

按 [§6 模板](#6-审计记录与收敛方法)记录 UMS 交来的场景输入，供 D-11/D-15/D-19 讨论；候选方案见[角度 1](DECISION_DIRECTIONS.md#angle-01)。

| 模板项 | UMS 输入 |
|---|---|
| 场景 | UMS 的一次执行（Run）按段日程顺序扫描一个工件上的多个区域 |
| 证据来源 | UMS 设计文档（段与段日程、存储规格、SDK 对接说明），用户于 2026-11-19/20 确认；属于设计阶段的业务输入，不是设备实测 |
| 实际动作与预期结果 | 每次 Start 创建一个 Run，并冻结一份段日程：每个区域一段，按顺序执行，段间转场。各段的采集、触发、声路及布局参数相同，标定采用值在 Start 时冻结；目前只有扫描速度逐区域不同，其它参数是否逐区域设定，用户尚未完全确定。暂停后继续仍属同一段。Stop 或故障使当前段提前结束并留下缺口，后续段不再执行。收尾时封存成果；UMS 侧成果以文件为准，成果目录可由文件重建 |
| 复检与跨进程 | 复检是另一次 Run。按下行候选，复检数据总在另一份文件（推断）；D-19 决定前，复检关系由 UMS 逻辑成果持有并指向原文件中对应区域的 Scan（UMS 已定）。跨进程恢复原执行已后置，两次任务之间机台可能重启，UMS 当前不需要干净关闭后重开追加 |
| UMS 候选映射（未采纳） | 一次 Run 写一份文件，每段一个 Scan，段内暂停留在同一 Scan；若 D-15 决定暂停须结束 Scan，则一段可对应多个 Scan，由 UMS 逻辑成果归到同一区域 |
| 审计主题与规则 | A-01，复检部分涉及 A-09；R-01/R-12；SCAN-01、LIF-01、REL-01、RET-01；D-11/D-15/D-19 |
| 结论 | 现有契约已覆盖：同一 Writer 会话顺序完成多个 Scan，Scan 完成与文件封存分开，封存后不追加原始 Scan。需要补充：段内暂停的表示（D-15）、提前结束的 Scan 怎样表达缺口（RET-01，协同 D-01/D-16）、Scan 与目标区域的关系（D-11）、复检跨文件（D-19）。与现有约束无冲突 |
| 最小验证样例 | 角度 1 选定后补充。草例：一份文件含三段，第二段中途暂停后继续，第三段因 Stop 提前结束；重开后枚举到三个 Scan，第二段帧序连续且同属一个 Scan，第三段的已提交范围可读，提前结束的表示待定 |

### 每个真实工作负载应留下的最小记录

不要先估计“单通道占主导”。对实际存在的算法/操作填写：

| 项目 | 需要记录的内容 |
|---|---|
| 输入来源与阶段 | 采集内存、正常封存文件或显式恢复视图；是否跨文件 |
| 选择 | 一个 Scan、单 Frame 或 Batch 选择，帧内流/束/Tx/Rx/收发对及样本窗口；具体 Batch 语法待定 |
| 顺序与关联 | 采集还是空间顺序；重复索引、位置、状态、固定定义关联 |
| 解释依赖 | 各流数值/采样轴、坐标系、事件/输出及矩阵映射、固定定义、标定和传播模型来源 |
| 输出与执行 | 分析/Batch 内容、dtype/布局与关联；poll 借用期或 push 目标所有权；单 Frame 不分块，SDK 不安排 GPU 上传 |
| 负载与验收 | 实际访问场景及优先级、负载大小/比例/速率/延迟与内存预算（含原子暂存）；单 Reader、多 Reader 或多进程只读 |
| 证据与预期 | 调用示例或算法输入说明、可共享的小样例及独立期望值；未知项显式留空 |

首发范围冻结前，每个声明支持的模式应有可核对的上游交付说明或真实小样例，含设备/接口版本、事件—输出—流映射、样本/采样轴、位置和有效性来源及最大 Frame 规模。此项是输入契约证据，不要求现在操作设备，也不把 SDK 存取验收变成设备同步或成像验收；缺少材料须保留证据缺口，不能用 H/P/F/W 的人工尺寸替代。

资源记录须分列调用者缓冲、SDK 结果/原子暂存、HDF5 缓存与解码工作区、位图/关联内容及绑定副本，并区分典型值、支持上限和验收目标。单 Frame 不分块，B=1 仍须核对其容量；目标环境、速率、延迟/阻塞和峰值预算在验收测量前确定。决定与门槛写回 D-02/D-03，候选讨论见 [决策入口](DECISION_DIRECTIONS.md#angle-10)。

### 信息应该归在哪里

审计中发现必需信息时，先按现有职责分类，再讨论具体字段：

- **固定定义与解释**：扫描/事件/流设置、各流采样轴、输出及矩阵映射、必要几何和位置描述；不能依赖设备当前默认值，不能逐帧更换。
- **Frame 观测关联**：每帧的原始波形、状态、位置及正确固定引用；不是逐帧配置历史。
- **帧级附加记录与可选内容**：时间戳、来源 ID、额外坐标等按 Frame 索引关联，各自描述和来源明确；不得将其当作逐束独立原始位置。计划等可选内容不引入派生资源管理，必要性与缺值规则不由样例猜定。
- **既有工件容器与区域/来源关系**：原始独立身份保持；目标区域、复检局部来源的责任已定，区域内容、模型、作用域和约束待 D-11，不预定字段或将检测对象归属扩为产品必需。
- **C 扫快照与其它成果**：快照属于 SDK，数值、状态及参数/来源按 SNAP-01；标注/缺陷成果归 UMS。曲面只保存解释超声数据所需几何，点云属于前置知识。不把自解释数据等同于完整业务包跨电脑交付。

这只是审查分类方法，不预先决定所有标定、拓扑或处理参数必须存入哪条 HDF5 路径。

结论按以下规则落回权威文档：

1. 已覆盖：引用具体规则，不为了记录讨论再复制字段表。
2. 待补充：关联现有 D 项；新增待定领域仅在证据支持时加入 Spec 登记表。
3. 有冲突：先在 DESIGN 修订需求/范围，再同步 Spec 和测试计划，不能让实现默默改变契约。
4. 可验证：在 [SPEC_TEST_PLAN.md](SPEC_TEST_PLAN.md#scenario-validation) 中将场景映射为小型正反例；没有执行证据时不标为 PASS。
