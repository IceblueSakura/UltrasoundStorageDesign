# 数据 Spec 验证计划

适用文档：[DATA_SPEC.md](DATA_SPEC.md)，版本 `0.2-draft`；访问规划见 [ACCESS_USE_CASE_PLAN.md](ACCESS_USE_CASE_PLAN.md)。

状态：测试用例编写前的验收素材与追踪计划，**未编写可执行用例、未实现检查器、未生成本计划样例、未执行本计划测试**。H/P/F 和 UC 是本项目的语义样例与回归设计，不是已编写的可执行测试。本文不新增产品字段、设备指标或性能门槛，文档职责按 [设计维护原则](DESIGN.md#integration-policy)划分。

## 1. 分离验证目标

| 类型 | 目标 | 当前边界 |
|---|---|---|
| 符合性 | 验证语义、结构、关联和拒绝行为 | 可以先用很小的测试专用样例推进 |
| 规模/性能 | 验证有界内存、持续写入及访问代价 | 数值目标仍待定；不能替代符合性 |
| 故障恢复 | 验证异常文件只读访问与明确失败 | 必需的尽力恢复目标，不承诺恢复比例或严格时间窗 |
| 可选加速 | 验证 GPU 完整编码链 | GPU 非基础读取必选 |

每个用例记录 Spec 修订/哈希、规则 ID、实现版本、样例版本、临时编码选择、环境与原始结果。NOT_RUN、BLOCKED、UNSUPPORTED 与 PASS 分开；已被替代的历史用例不计为 PASS。实验通过也不宣称生产编码或 API 已冻结。

## 2. 小型样例策略

首轮使用容易逐项核对的小数据，不追求吞吐：

- 各 Frame 和流的样本值可区分，避免全零掩盖错配。
- test-only 位置描述能区分帧，也包含重复位置值，防止以坐标值代替 Frame 身份。
- 固定扫描/事件/流定义有可辨识身份，跨帧复用；真实定义变化用拒绝反例，不使用动态快照切换正例。
- 覆盖 payload 存在且有效/无效，以及明确缺失的语义。缺失样例不意味着缺 payload 写入 API 已确定；具体状态字节编码另行说明，不预设旧版 0/1/3 为产品要求。
- 编码未定时，在样例说明中明确记录 `test-only` 的位置、固定定义、映射、身份和生命周期编码；这些不是产品默认值或已注册 profile。

空文件能否作为正常封存扫描仍需生命周期/API 细化；可以构造 N=0 的初始化或参考封存样例，但须单独说明候选规则，不能混为既定产品行为。

损坏/故障样例必须生成在新的专用实验目录，不能改写真实采集文件或现存基准结果。本计划不授权实际设备操作、破坏性磁盘故障或付费测试。

### 2.1 异构单晶样例 H

三条流、两个 Frame，固定长度和 dtype。以下数值是独立期望，不是设备默认值；样例尚未生成。

| 流 | dtype / 长度 | Frame 0 | Frame 1 |
|---|---|---|---|
| W0 | u8 / 4 | `[0,127,128,255]` | `[1,126,129,254]` |
| W1 | u16 / 3 | `[0,256,65535]` | `[1,257,65534]` |
| W2 | i32 / 5 | `[-2147483648,-1,0,65536,2147483647]` | `[-2147483647,-2,1,65537,2147483646]` |

Frame 0/1 使用抽象位置 P0/P1，不规定坐标编码。目标为异构、符号、位宽、数据身份和无隐式转换。事件/接收输出的具体夹具标识及事件数量留待编写用例时说明，不是本轮固定的产品字段。

共同样本请求 `[3,4)` 对 W0/W2 合法、对 W1 越界。独立预期仅要求 W1 明确越界，不能静默截断、补零或伪装整个请求成功；请求级拒绝还是逐项错误结果待 D-10，不预写具体异常或返回容器断言。

### 2.2 常规 PA 样例 P

两个 Frame、三个声束、每波形八点、测试 dtype u16：

```text
W[n,b,s] = 1000*n + 100*b + s
```

每帧仅有一个 P_n。固定几何 G、法则 L0/L1/L2 各定义一次；束 b 能追溯到正确事件、接收输出及 L_b。本参考样例采用一组法则对应一个保存声束，不泛化为设备假设。P/G/L 是关联标记，不冒充真实几何模型。具体事件/流编号、定义序列化在后续 test-only 夹具中说明，本次不选定。

Frame 1、束顺序 `[2,0,2]`、样本 `[1,4)`：

```text
b2 → [1201,1202,1203]，Frame 1、P1、G、L2
b0 → [1001,1002,1003]，Frame 1、P1、G、L0
b2 → [1201,1202,1203]，Frame 1、P1、G、L2
```

检查引用而不计算束坐标；增加 P0=P1 变体，两个 Frame 不合并。不执行定位也可原始读取，派生位置不能替换 P_n。

### 2.3 FMC 样例 F

两个 Frame、三个 Tx、三个 Rx、八样本，测试 dtype u16：

```text
X[n,i,j,s] = 1000*n + 100*i + 10*j + s
```

I/J 为同一选定三阵元集合，π 声明全部九个有序收发对与流的对应。流的物理/目录顺序可与 π 的矩阵顺序不同，以验证读取不从排列猜 Tx/Rx。具体 π 排列、事件/流命名留待用例编写。预期按公式和手列值确定，不从被测读取器导出。

Frame 0、Tx `[2,0]`、Rx `[1,2]`、样本 `[2,5)`：

```text
             Rx1               Rx2
Tx2     [212,213,214]     [222,223,224]
Tx0     [ 12, 13, 14]     [ 22, 23, 24]
```

配对 `[(2,1),(0,2)]` 仅返回 `[212,213,214]`、`[22,23,24]`，不展开四格。

给定逐对样本选择表及独立结果：

```text
Q = [[1,4,2],       A[i,j] = X[0,i,j,Q[i,j]]
     [0,3,6],
     [5,2,7]]

A = [[  1, 14, 22],
     [100,113,126],
     [205,212,227]]
```

只验证非均匀选样，不计算传播时间，不测试 TFM 图像质量或逐像素磁盘 I/O。异构 FMC 变体需单独说明各单元类型、长度和采样解释；再加 shape/dtype 相同而时间解释不同的变体，防止误报共同时间轴。

| A-06/A-12：执行边界 | 用受控输入区分阻塞、I/O 失败、封存后读取和恢复读取；测量资源时保留实际请求及缓冲边界 | T-12～T-15/T-18；小样例不代替真实设备持续输入或超 RAM 验证 |

场景证据可能要求修订契约；此时先更新 DESIGN / DATA_SPEC，再修改断言。不得为了使已有脚本通过而缩减真实算法输入要求。

## 5. 检查器的实施边界

建议实现独立只读检查器，按“识别 → 结构 → 关联 → 可选深度”分层。深度检查使用有限批次，不能全量加载位置或波形。

检查器不直接复用写入器的全部内部校验函数，避免同一种缺陷同时出现在生产者和验证者。初期可使用同一种语言，但期望值和必要规则判断应独立；第二种语言/工具用于后续互通验证，不是本轮实施任务。

检查器输出至少指出失败规则、对象/记录范围、采用的参考编码、检查层次以及未检查项。尚不实现时，不用示意报告冒充实际 PASS。

后续最小工具的职责建议（不作为本次设计整合必须选定的实现架构）：

| 部分 | 未来职责 | 不作为本阶段承诺 |
|---|---|---|
| 样例说明/生成器 | H/P/F 固定引用、明确 π、test-only 编码，独立期望数据 | 真实 RF、最终产品字段或真实几何 |
| 最小写入工具 | 固定定义一次保存、Frame 提交、结构校验及关闭 | 完整 SDK、断电持久化协议 |
| 最小读取工具 | Frame/Stream、PA 束、FMC 行列/子矩阵/配对、样本选择 | 性能阈值、GPU、逐像素 I/O |
| 独立只读核对 | 数值/dtype/状态、原始位置及映射引用、拒绝反例 | 设备同步、定位或 TFM 正确性 |

活动源码/测试目录待实施时创建，不向 archive 追加 SDK。新样例及结果保存在新的实验输出位置，不覆盖历史文件。先在明确 test-only 编码下取得可重复语义证据，再闭合正式编码；实现语言和函数签名当前不冻结。

## 6. 性能与 GPU 专项

性能实验配置必须与文件语义分离。先从场景审计取得真实工作负载及资源目标；现有 benchmark 不作为新实验的验收基线：

1. 保留无压缩对照；先固定输入与输出要求，再比较 SPLIT/CTS，必要时加入 TCS。
2. 分别测试固定 Frame 轴长度与固定 chunk 字节预算，记录部分 chunk 更新和批量/flush 交互；异构结果不可转换后冒充原始数据对照。
3. 分开描述 OS 热缓存、HDF5 chunk 热缓存和受控低命中读取；不将逻辑 GiB/s 称为磁盘带宽。
4. 使用真实波形及不可压缩压力输入；记录 CPU、内存、阻塞时间、物理 I/O 和文件大小。
5. 保存请求序列、原始计时、执行顺序、脚本哈希、实际库/filter/线程与存储环境；没有目标门槛时只作测量，不宣布生产验收通过。

GPU 实验先验证完整编码链正确性，再比较压缩字节传输、GPU 解码和下游处理的端到端代价。普通主机解压后的 H2D 是对照，不是 GPU 解压证据。

进程中断测试与断电测试分开；一种故障的结果不外推另一种。flush 周期与恢复范围由观察决定，不预设用户尚未确认的时间门槛。
