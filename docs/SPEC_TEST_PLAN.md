# 数据 Spec 验证计划

适用文档：[DATA_SPEC.md](DATA_SPEC.md)，版本 `0.1-draft`。

状态：计划，**未实现检查器、未生成本计划样例、未执行本计划测试**。现有微基准仅能提供有限实验线索，不转记为下列用例已通过。本文是验证方法与覆盖关系的权威来源，不新增产品字段、设备指标或性能门槛。

## 1. 分离验证目标

| 类型 | 目标 | 当前边界 |
|---|---|---|
| 符合性 | 验证语义、结构、关联和拒绝行为 | 可以先用很小的测试专用样例推进 |
| 规模/性能 | 验证有界内存、持续写入及访问代价 | 数值目标仍待定；不能替代符合性 |
| 故障恢复 | 验证异常文件只读访问与明确失败 | 必需的尽力恢复目标，不承诺恢复比例或严格时间窗 |
| 可选加速 | 验证 GPU 完整编码链 | GPU 非基础读取必选 |

每个用例记录 Spec 修订/哈希、规则 ID、实现版本、样例版本、临时编码选择、环境与原始结果。NOT_RUN、BLOCKED、UNSUPPORTED 与 PASS 分开；参考规则通过只证明该候选行为，不宣称正式 API 已冻结。

## 2. 小型样例策略

首轮使用容易逐项核对的小数据，不追求吞吐：

- 各记录和通道的样本值可区分，避免全部为零掩盖索引错配。
- 测试专用位置描述能区分每条记录，也包含重复位置值，防止实现用坐标值当记录身份。
- 参数快照含不同内容和可识别切换点。
- 覆盖 payload 存在且有效/无效。状态 0 仅在明确的测试解释下验证，不能据此声称缺 payload 写入 API 已实现。
- 编码未定时，在样例说明中明确记录 `test-only` 的位置、参数、身份和生命周期编码；这些不是产品默认值或已注册 profile。

空文件能否作为正常封存扫描仍需生命周期/API 细化；可以构造 T=0 的初始化或参考封存样例，但应分别报告所采用的候选规则，不能混为既定产品行为。

损坏/故障样例必须生成在新的专用实验目录，不能改写真实采集文件或现存基准结果。本计划不授权实际设备操作、破坏性磁盘故障或付费测试。

## 4. 场景与算法证据如何转为验证

以下是 [场景审计](SCENARIO_AUDIT.md)后的候选样例方向，均未生成或执行，不代表新增产品能力。先确认场景确实存在、解释规则和独立期望值，再纳入具体测试；算法输出检查与存储符合性分开报告。

| 审计主题 | 候选小样例与期望检查 | 现有用例入口 / 剩余边界 |
|---|---|---|
| A-01～A-04：轨迹、位置、通道 | 重复位置、非等距点、反向扫描的少量可区分记录；绑定读取仍保留记录身份，不因坐标值合并或重排 | T-02/T-06/T-07；不证明自动网格化、物理同步或位置准确性 |
| A-03/A-07：通道映射、数值和采样轴 | 通道和记录各不相同的已知样本，明确整数解释、样本轴与通道身份；与外部手算/独立期望比对 | T-04/T-09/T-22；物理距离换算等须另有已确认模型 |
| A-05/A-11：参数与状态 | 参数切换点落在读取批次内部，混合状态 1/3；算法可找到正确快照，SDK 不隐式滤掉状态 1 | T-05/T-08/T-09；位置无效和缺 payload 等待 D-01/D-08，不擅自赋值 |

| A-06/A-12：执行边界 | 用受控输入区分阻塞、I/O 失败、封存后读取和恢复读取；测量资源时保留实际请求及缓冲边界 | T-12～T-15/T-18；小样例不代替真实设备持续输入或超 RAM 验证 |

## 5. 检查器的实施边界

建议实现独立只读检查器，按“识别 → 结构 → 关联 → 可选深度”分层。深度检查使用有限批次，不能全量加载位置或波形。

检查器不直接复用写入器的全部内部校验函数，避免同一种缺陷同时出现在生产者和验证者。初期可使用同一种语言，但期望值和必要规则判断应独立；第二种语言/工具用于后续互通验证，不是本轮实施任务。

检查器输出至少指出失败规则、对象/记录范围、采用的参考编码、检查层次以及未检查项。尚不实现时，不用示意报告冒充实际 PASS。

## 6. 性能与 GPU 专项

性能实验配置必须与文件语义分离。先从场景审计取得真实工作负载及资源目标；现有 benchmark 不作为新实验的验收基线：

1. 保留无压缩对照；先固定输入与输出要求，再比较 SPLIT/CTS，必要时加入 TCS。
2. 分别测试固定 trigger 轴长度与固定 chunk 字节预算，记录部分 chunk 更新和批量/flush 交互。
3. 分开描述 OS 热缓存、HDF5 chunk 热缓存和受控低命中读取；不将逻辑 GiB/s 称为磁盘带宽。
4. 使用真实波形及不可压缩压力输入；记录 CPU、内存、阻塞时间、物理 I/O 和文件大小。
5. 保存请求序列、原始计时、执行顺序、脚本哈希、实际库/filter/线程与存储环境；没有目标门槛时只作测量，不宣布生产验收通过。

GPU 实验先验证完整编码链正确性，再比较压缩字节传输、GPU 解码和下游处理的端到端代价。普通主机解压后的 H2D 是对照，不是 GPU 解压证据。

进程中断测试与断电测试分开；一种故障的结果不外推另一种。flush 周期与恢复范围由观察决定，不预设用户尚未确认的时间门槛。
