# 数据 Spec 验证计划

状态：已同步 ADR-0011 的业务验证规划；本次不修改或运行既往代码、测试或实验。UC/T 产品验证未执行，旧 M1 证据仅保留其原适用范围。

访问规划见 [ACCESS_USE_CASE_PLAN.md](ACCESS_USE_CASE_PLAN.md)。H/P/F/W 和 UC 是语义样例与回归设计；本文不新增产品字段、设备指标或性能数值门槛，文档职责按 [设计维护原则](DESIGN.md#integration-policy)划分。

## 1. 分离验证目标

| 类型 | 目标 | 当前边界 |
|---|---|---|
| 符合性 | 验证语义、结构、关联和拒绝行为 | 可以先用很小的测试专用样例推进 |
| 规模/性能 | 验证有界内存、持续写入及访问代价 | 数值目标仍待定；不能替代符合性 |
| 故障恢复 | 验证异常文件只读访问与明确失败 | 必需的尽力恢复目标，不承诺恢复比例或严格时间窗 |
| 可选加速 | 验证 GPU 完整编码链 | GPU 非基础读取必选 |

每个用例记录 Spec 修订/哈希、规则 ID、实现版本、样例版本、临时编码选择、环境与原始结果。NOT_RUN、BLOCKED、UNSUPPORTED 与 PASS 分开；已被替代的历史用例不计为 PASS。实验通过也不宣称生产编码或 API 已冻结。

以下既有 H/P/F/W、UC-01～19 和 T 项主要针对原始波形 Core，不覆盖全部产品业务。按 [CORE-01](DATA_SPEC.md#core-01)：同步读写，poll 借用 SDK 内存、push 复制到调用者缓冲，分别核对分析/Batch 内容交付；单 Frame 不分块、读取不更新、无写入取消。产品布局优先级待实际场景明确，指定快照写入不受旧全文件禁止 update 限制。帧内选择属于选择层（ADR-0006），只需核对其与 Core I/O 结果等价，不再与 poll/push 逐一组合。UC-14 覆盖 Batch 及 poll/push 等价，不自动规定任意 Frame 清单。按 IO-01 对每次读写调用分别验证 push 目标不变和 poll 不发布部分结果/旧借用到期，按 WRT-03 验证 Flush 成功后条件，不以错误码或 H5Fflush 成功代替证据。

## 2. 小型样例策略

首轮使用容易逐项核对的小数据，不追求吞吐：

- 各 Frame 和流的样本值可区分，避免全零掩盖错配。
- H/P/F 基础样例的全部波形槽位写入时均显式标记 `valid=1`；有效性变体仅修改其明确列出的槽位，不能因提供了样本就隐式推定有效。
- test-only 位置描述能区分帧，也包含重复位置值，防止以坐标值代替 Frame 身份。
- 固定扫描/事件/流定义有可辨识身份，跨帧复用；真实定义变化用拒绝反例，不使用动态快照切换正例。
- 覆盖有效非零、有效全 0 和无效零填充；每波形槽位只有一个有效性位，写入时须显式提交完整位图（ADR-0003），该槽位规则不区分缺数据与“有值但业务无效”，但不代替 RET-01 的成果保留及缺口状态。无效输入可省略，提供时内容忽略（严格模式下非零输入报错）；有效数据仍须通过结构校验并无损保存。具体位图打包和容器记录 test-only 选择，不恢复旧双位状态。
- 编码未定时，在样例说明中明确记录 `test-only` 的位置、固定定义、映射、身份和生命周期编码；这些不是产品默认值或已注册 profile。
- 元信息与位置使用必要公共描述＋带类型/版本内容；验证关联与原样内容，旧样例不证明 REL-01 的模式 schema 已满足，也不宣称 Extensions 已实现。

流组划分（ADR-0001）：H 的三条流 dtype/长度各不相同，各自构成一个 `K_g=1` 的流组，原“流间异构”用例即跨组异构；P 的三个声束是一个 `K_g=3` 的 PA 声束集；F 的九个收发对是一个 `K_g=9` 的 Tx×Rx 矩阵组；W 的每个 Scan 各一个组。独立期望值不因分组改变。

H/P/F/W 的原始 dtype、数值及独立期望保留，不自动成为首发类型清单。正式 profile 确定后，若其支持表示与原夹具不同，可建立独立命名、独立期望的 profile 适配变体，并在原 UC/T 下说明对应关系和覆盖：必须保留异构、身份、所支持类型的符号/边界、无隐式转换及其他 Core 规则检查。不得改写原夹具并冒称原数值预期已通过，也不得借适配免验必需语义；若无法保持所需覆盖，应补充变体或回到支持范围决策。

空 Scan 是否允许完成并纳入正常封存文件、无 Scan 的文件是否允许封存及相应接口行为统一登记在 DATA_SPEC 的 D-05/D-10，见 [LIF-01](DATA_SPEC.md#lif-01)。可以构造初始化或参考空容器/空 Scan 样例，但须单独说明候选规则，不能混为既定产品行为；产品决定前不编写“必须允许”或“必须拒绝”的断言。

损坏/故障样例必须生成在新的专用实验目录，不能改写真实采集文件或现存基准结果。本计划不授权实际设备操作、破坏性磁盘故障或付费测试。

### 2.1 异构单晶样例 H

三条流、两个 Frame，固定长度和 dtype。以下数值是独立期望，不是设备默认值；样例尚未生成。

| 流 | dtype / 长度 | Frame 0 | Frame 1 |
|---|---|---|---|
| W0 | u8 / 4 | `[0,127,128,255]` | `[1,126,129,254]` |
| W1 | u16 / 3 | `[0,256,65535]` | `[1,257,65534]` |
| W2 | i32 / 5 | `[-2147483648,-1,0,65536,2147483647]` | `[-2147483647,-2,1,65537,2147483646]` |

Frame 0/1 使用抽象位置 P0/P1，不规定坐标编码。目标为异构、符号、位宽、数据身份和无隐式转换。事件/接收输出的具体夹具标识及事件数量留待编写用例时说明，不是本轮固定的产品字段。

共同样本请求 `[3,4)` 对 W0/W2 合法、对 W1 越界。独立预期仅要求 W1 明确越界，不能静默截断、补零或伪装整个请求成功；请求级拒绝还是逐项错误结果待 D-10，不预写具体异常或返回容器断言。

有序样本清单变体：Frame 0、W0、Sample `[3,1,3]` 的独立预期为 `[255,127,255]`，样本身份依次为 `s=3、1、3`，Frame/流来源和槽位状态不变。相同清单对 W1 越界，不能去重、排序或截断后伪装成功；追踪 READ-02 / U-09 / UC-12，不冻结结果容器或切片语法。

### 2.2 常规 PA 样例 P

两个 Frame、三个声束、每波形八点、测试 dtype u16：

```text
W[n,b,s] = 1000*n + 100*b + s
```

每帧仅有一个 P_n。固定几何 G、法则 L0/L1/L2 各定义一次；束 b 能追溯到正确事件、接收输出及 L_b。本参考样例采用一组法则对应一个保存声束，不泛化为设备假设。P/G/L 是关联标记，不冒充真实几何模型。具体事件/流编号、定义序列化在后续 test-only 夹具中说明，本次不选定。

Frame 1、束顺序 `[2,0,2]`、样本 `[1,4)`：

```text
b2 → [1201,1202,1203]，Frame 1、P1、G、L2
b0 → [1001,1002,1003]，Frame 1、P1、G、L0
b2 → [1201,1202,1203]，Frame 1、P1、G、L2
```

检查引用而不计算束坐标；增加 P0=P1 变体，两个 Frame 不合并。不执行定位也可原始读取，派生位置不能替换 P_n。

UC-06/07 的位置变体可用 test-only A/B 编码器描述，固定在 Scan 内，每帧一对值，全部声束共享。另以一类帧级附加记录保存可区分的理论坐标标记，按同一 Frame 关联，读取不得替换原始位置；不做坐标变换。只验证已确定的关联方向，该记录的缺值规则未决定前不预写断言（D-01）。跨 Scan 使用不同位置描述的变体追踪 UC-17，不修改 W 的既有数值期望。

### 2.3 FMC 样例 F

两个 Frame、三个 Tx、三个 Rx、八样本，测试 dtype u16：

```text
X[n,i,j,s] = 1000*n + 100*i + 10*j + s
```

I/J 为同一选定三阵元集合，π 声明全部九个有序收发对与流的对应。流的物理/目录顺序可与 π 的矩阵顺序不同，以验证读取不从排列猜 Tx/Rx。具体 π 排列、事件/流命名留待用例编写。预期按公式和手列值确定，不从被测读取器导出。

#### FMC 映射拒绝反例（UC-09 变体）

各反例从合法 F 定义单独改变一项，保留其他映射、样本及解释。身份类反例使用集合外的值（Tx9、Rx9），以免同时造成别名；“测量身份”指流所关联的（发射事件 Tx，接收输出 Rx）对。别名反例必然同时违反其中一个对的身份一致性，独立检查器报告别名或身份不一致之一即可，但不得接受。以下验证 [FMC-01](DATA_SPEC.md#fmc-01) / U-06 的结构与关联约束，并保护 [FMC-02](DATA_SPEC.md#fmc-02) / U-07 的矩阵/流等价关系；仍全部 NOT_RUN，不另设执行账本或错误码。

| 单项变更 | 独立拒绝预期 |
|---|---|
| 保持完整 I×J 声明，删除 `(2,1)` 的 π 映射 | 报告声明域覆盖不完整；不得缩小矩阵、补零或借互易对补齐 |
| 将 `(0,2)` 和 `(2,0)` 映射到同一逻辑流 | 报告不同有序对的测量身份别名冲突；不得以互易性接受 |
| 将 `(1,2)` 映射到不存在的流 | 报告悬空流引用；不得从目录位置选择替代流 |
| 保持 π 指向的流存在，但使 `(2,1)` 对应流的事件 Tx 身份变为集合外的 Tx9 | 报告映射与事件发射身份不一致；不能仅凭 shape/dtype 接受 |
| 保持 π 指向的流存在，但使 `(2,1)` 对应流的接收输出身份变为集合外的 Rx9 | 报告映射与接收输出身份不一致；不能仅凭硬件通道或目录顺序接受 |

上述是固定定义错误，不是“映射完整但某个槽位的有效性位为 0”。后者继续由 UC-15 验证；不得把映射错误降格为无效位及零填充。反例可在初始化校验或独立只读检查时核对，具体 API 和错误容器留待 D-07/D-09/D-10；不要求 SDK 接受错误定义以生成文件。

#### 正确选择的独立期望

Frame 0、Tx `[2,0]`、Rx `[1,2]`、样本 `[2,5)`：

```text
             Rx1               Rx2
Tx2     [212,213,214]     [222,223,224]
Tx0     [ 12, 13, 14]     [ 22, 23, 24]
```

配对 `[(2,1),(0,2)]` 仅返回 `[212,213,214]`、`[22,23,24]`，不展开四格。

Frame 0、配对 `[(2,1)]`、Sample `[3,1,3]` 的独立预期为 `[213,211,213]`，保留该收发对身份与样本顺序/重复项；作为 UC-12 的矩阵/流视图对照变体，不规定外层结果容器。

给定逐对样本选择表及独立结果：

```text
Q = [[1,4,2],       A[i,j] = X[0,i,j,Q[i,j]]
     [0,3,6],
     [5,2,7]]

A = [[  1, 14, 22],
     [100,113,126],
     [205,212,227]]
```

只验证非均匀选样，不计算传播时间，不测试 TFM 图像质量或逐像素磁盘 I/O。以上期望只适用于基础 F；UC-15 变体下的对应值见该节。跨组异构 FMC 变体需单独说明各组类型、长度和采样解释；再加 shape/dtype 相同而时间解释不同的变体，防止误报共同时间轴。

#### UC-05 的混合有效性素材

H′ 与 H 相同，只把 Frame 0 的 W0 写为 `valid=0` 并省略其输入。Frame 0、流清单 `[W2,W0,W2]` 的独立预期为：W2 `[-2147483648,-1,0,65536,2147483647]`（i32，位 1）、W0 `[0,0,0,0]`（u8 零填充，位 0）、W2 同第一项（位 1）；三项均关联 P0 及各自的事件/接收输出。H 的 2.1 预期只适用于基础 H。

#### UC-14 的两种读取交付与缓冲素材

以 P 的 Frame 0、1 作为 B=2 的 Batch，样本数为 `2×3×8=48` 个 u16（96 字节的波形量，不含元信息）。独立预期仍按 2.2 公式：Frame 0/束 0 为 `[0,1,2,3,4,5,6,7]`，Frame 1/束 2 为 `[1200,1201,1202,1203,1204,1205,1206,1207]`；其余值由同一已列公式核对，位置分别关联 P0/P1。分析结果与 Batch 结果逐身份比较，不预设最终物理排列或函数签名。

对相同选择分别通过 poll 和 push 读取，并核对分析/Batch 结果：

- poll 在借用期内与独立期望比对；按 BUF-01 的借用结束条件（同一 Reader 下一次样本读取开始，含失败与参数被拒绝；或 Reader 关闭），旧视图到期；目录/元信息/容量查询不使其到期；另一 Reader 的读取不影响它。不得在用例中解引用已到期裸指针来检查是否被覆写；不要求地址固定或每次必然变化。可通过生命周期记录或受检包装核对失效，不冻结生产检测机制。
- push 使用调用者目标，核对关闭 Reader 后内容仍可使用、对其他缓冲读取不影响它；复用同一目标可以覆盖旧内容。跨调用比较需先复制 poll 结果或使用独立 push 缓冲，不能把借用视图误当快照。
- 容量不足/溢出须明确失败，不越界或返回截断 Frame；SDK 管理的 poll 缓冲及有效性位图也计入内存预算。按 STA-01 核对无效零填充及位图关联，不写死具体打包/返回容器。真实 GPU 上传不在此用例内，不由指针回读宣称 GPU 解压、mmap 或零拷贝。

#### UC-15 的单一有效性与零填充素材

在独立的 F 变体中，仅修改 Frame 0 的以下三个槽位，其余样本沿用 2.3 公式、有效性位均为 1；不改变基础 F 及已有子矩阵预期：

| Tx/Rx | 写入有效性位及输入 | 读取独立预期 |
|---|---|---|
| `(0,0)` | `valid=1`，提供八个 u16 零样本 | 八个 0，位为 1，是真实有效的全 0 波形 |
| `(0,1)` | `valid=0`，省略波形输入 | 八个 u16 零填充值，位为 0，不是真实零回波 |
| `(0,2)` | `valid=1`，提供 `[20,21,22,23,24,25,26,27]` | 原样返回，位为 1，不另作业务合法性判断 |

对这三个收发对按上述顺序读取，波形为两条全 0 及一条已列非零波形，对应逻辑有效性序列为 `[1,0,1]`；这不是冻结的位图字节值或位序。增加 `(0,1)` 在无效位下提供 `[900,901,902,903,904,905,906,907]` 的变体，读取仍为八个 0、位为 0，不要求保留被忽略的输入内容；开启严格模式时，同一输入使整个调用被拒绝。写调用缺少位图、位图长度与槽位数不符或与流身份对不上时，整个调用被拒绝，提交前缀不变（ADR-0003）。

本变体改变了基础 F 中依赖这些槽位的期望：子矩阵中 `(Tx0,Rx1)` 的 `[2,5)` 为 `[0,0,0]`（位 0），`(Tx0,Rx2)` 仍为 `[22,23,24]`（位 1）；Q 结果的 `A[0,0]=0`（位 1）、`A[0,1]=0`（位 0），`A[0,2]=22` 不变；配对 `[(2,1),(0,2)]` 与 `(2,1)` 的 `[3,1,3]` 结果不变。

分别用矩阵/流/单波形、分析/Batch、poll/push 对照；乱序和重复选择的位图随槽位同步重排或重复。有效全 0 不改成无效，无效槽位不跳过、不仅因其无效而拒绝稠密交付。独立构造 `valid=1` 却缺少波形或长度/dtype 错误、位图关联缺失、结构损坏及解码失败反例，均须明确失败，不伪装成零填充成功；写入结构拒绝不改变前缀及历史。未提交尾部即使默认位为 0 也不暴露。

本节只补充后续断言素材，尚未生成或执行；波形有效性不替代 POS-01 的位置接收政策及 D-01 的状态表示，也不验证真实设备采集或算法正确性。

### 2.5 多 Scan 工件样例 W

W 是独立于 H/P/F 的工件容器语义素材，全部采用单晶类别，不通过该样例解除同文件混存限制。四个 Scan 顺序创建，各有两个 Frame（n=0、1）和一条局部名称均为 k0 的流。每个 Scan 的固定事件/输出引用独立。所有波形均标记 `valid=1`；位置可重复，不作为身份。

W 只验证容器及独立 Scan，不选择 Scan 映射模型。A/B 可作为两次分块扫描、C/D 可作为复扫/精扫的业务背景，但这不是文件内用途字段、区域定义或来源引用断言。每个 Scan 的帧位置采用可核对的 test-only 描述，仅验证 Scan 内绑定，不赋予共同工件坐标或跨 Scan 映射。

| Scan | Scan 内帧位置关联标记 | k0 dtype / 长度 | Frame 0 / Frame 1 样本 |
|---|---|---|---|
| A | P_A0 / P_A1 | u16 / 3 | `[10,11,12]` / `[13,14,15]` |
| B | P_B0 / P_B1 | u16 / 3 | `[20,21,22]` / `[23,24,25]` |
| C | P_C0 / P_C1 | u16 / 3 | `[30,31,32]` / `[33,34,35]` |
| D | P_D0 / P_D1 | u8 / 4 | `[40,41,42,43]` / `[44,45,46,47]` |

独立预期：

- A/B/C/D 各自 N=2，而不是某个 Scan 的 N=8；跨 Scan 重复的 n=0、k0 不冲突。读取 `(A,0,k0)` 与 `(D,0,k0)` 分别得到 `[10,11,12]`（u16）和 `[40,41,42,43]`（u8），不隐式补齐或转换。
- 显式按 B、A、D 组合独立请求时，结果仍保留这些 Scan 来源，不改变 A/B/C/D 的内部 Frame 顺序。Scan 枚举默认排序未定，不从测试命名推导 API 排序规则。
- 绑定读取返回对应 Scan/Frame 的位置标记；即使不同 Scan 的位置描述值重复，也不合并记录或推导其空间关系。
- 四份原始结果始终可独立回读；C/D 的复扫/精扫业务背景不使旧结果被筛除或覆盖，也不证明完整覆盖。
- 分别构造重复 Scan 身份和错误跨 Scan 固定定义引用反例，报告已确定的身份/作用域错误。Scan 间来源图、自引用/环、坐标变换及不可用状态的正反例撤回，等待 D-11，不把它们当作当前格式校验要求。
- 请求不存在的 Scan 时明确失败，不回退到第一个或最新 Scan；尝试在该单晶文件加入阵列 Scan，或另构 PA/FMC 同文件组合反例时，按 DOC-01 的旧 Core profile 类别限制报告不支持，不据此决定产品混合范围。
- 正常序列为 A 完成后创建 B，依次完成 C/D，再封存文件。尝试向已完成 A 追加、在 B 活动时创建或向另一 Scan 追加、封存文件后新增 E 均拒绝（LIF-01：不隐式完成活动 Scan），不改写既有记录。

恢复变体在新的实验文件中模拟创建下一 Scan 或追加期间中断；验证文件目录及每个 Scan 的范围，未验证对象和关联单独报告，不将可读子集称为全文件正常。物理文件损坏可能影响已完成 Scan，不能预写“先前 Scan 必然完好”的断言。生命周期/故障执行沿用 T-12/T-15，实际物理故障不由小样例证明。M1 只覆盖 UC-19 的正常流程和逻辑拒绝，故障/恢复变体留在 M3/T-15；报告须分开标明子范围，不能把 M1 的通过扩展为恢复已通过。

本素材只形成 UC-17/19 的后续断言依据，尚未生成或执行；工件/Scan 身份及 Scan 内位置/定义使用明确的 test-only 编码。UC-18 保留为 BLOCKED，占位而无预设映射断言。不能通过 test-only 区域、来源图或坐标变换提前决定 D-11；不新增生产字段、空间查询、自动拼接或结果替代 API。

T-14 按 IO-01 区分读取模型：push 调用中解码/I/O 错误后，以哨兵内容逐字节核对调用者目标及关联内容未变；poll 错误后不发布本次有效结果，先前借用也不因失败恢复有效，不检查或解引用到期指针的旧内容。写错误后核对 N 无新增提交、Writer 进入失败态，并经带失败标记封存后的正常读取或恢复读取核对此前成功样本/状态/位置/元信息及校验值不变。原因/错误码另验，不要求文件物理布局复原；覆盖失败清理再次失败，不能只检查返回码。T-15 的崩溃恢复与 Flush 路径另验，不要求崩溃批次事务。产品实现尚无，T 项全部仍 NOT_RUN；M1 test-only 实验的部分机制证据见实验报告。

## 5. 检查器的实施边界

建议实现独立只读检查器，按“识别 → 结构 → 关联 → 可选深度”分层。深度检查使用有限批次，不能全量加载位置或波形。

检查器不直接复用写入器的全部内部校验函数，避免同一种缺陷同时出现在生产者和验证者。初期可使用同一种语言，但期望值和必要规则判断应独立；第二种语言/工具用于后续互通验证，不是本轮实施任务。

检查器输出至少指出失败规则、对象/记录范围、采用的参考编码、检查层次以及未检查项。尚不实现时，不用示意报告冒充实际 PASS。

后续最小工具的职责建议（不作为本次设计整合必须选定的实现架构）：

| 部分 | 未来职责 | 不作为本阶段承诺 |
|---|---|---|
| 样例说明/生成器 | H/P/F 固定引用、明确 π、W 多 Scan 独立身份、test-only 编码及独立期望数据 | 真实 RF、最终产品字段、真实几何或待定 Scan 映射模型 |
| 最小写入工具 | 固定定义一次保存、同步单 Frame/批次提交、显式有效性位图、无效零填充、结构校验、提交记录与校验值、Flush 及关闭 | 完整 SDK |
| 最小读取工具 | 分析/Batch 交付、poll 借用与 push 复制；帧内流/束/FMC 及位置/元信息关联 | update、帧内分块、位置查询、性能阈值、GPU 上传或解压 |

M1 的 test-only 原型、探针与独立核对脚本在 `experiments/m1/`，不向 archive 追加 SDK。新样例及结果保存在新的实验输出位置，不覆盖历史文件。先在明确 test-only 编码下取得最小端到端存取、独立核对与关键机制证据，再闭合正式编码/API；原生库以 C ABI 为唯一稳定边界（API-01），实现倾向 C/C++，Python/.NET Framework 4.8 是优先支持目标，具体绑定及函数签名仍待 D-10/D-12。后续分别验证声明的平台/消费端存取和资源生命周期，单一环境通过不外推全平台；本阶段不做部署验证。

## 6. 性能与 GPU 专项

性能实验配置必须与文件语义分离。连续批量写、Frame/Batch/A-Scan 读取是候选负载；优化优先级与尺寸/比例/指标均须按 ACCESS-01/D-03 的实际用途确认，不把旧 Frame 优先约定当产品永久结论。本阶段只维护设计，不执行以下未来实验或调优；现有 benchmark 不作为验收基线：

1. 保留无压缩对照；先固定输入与输出要求，再比较 SPLIT/CTS，必要时加入 TCS。
2. 分别测试固定 Frame 轴长度与固定 chunk 字节预算，记录部分 chunk 更新和批量/flush 交互；异构结果不可转换后冒充原始数据对照。
3. 分开描述 OS 热缓存、HDF5 chunk 热缓存和受控低命中读取；不将逻辑 GiB/s 称为磁盘带宽。
4. 使用真实波形及不可压缩压力输入；记录 CPU、内存、阻塞时间、物理 I/O 和文件大小。
5. 保存请求序列、原始计时、执行顺序、脚本哈希、实际库/filter/线程与存储环境；没有目标门槛时只作测量，不宣布生产验收通过。

Batch 指针交付与 GPU 上传/解压分开验收；前者可在无 GPU 时核对内容、布局及缓冲生命周期。未来 GPU 解压实验先验证完整编码链，再比较传输、解码和下游处理端到端代价。普通主机解压后的 H2D 不是 GPU 解压证据。

故障测试只覆盖进程中断；断电与操作系统崩溃不在范围（ADR-0008），进程中断的结果也不外推到它们。SDK 不自动周期刷新；调用者的 Flush 频率与未 Flush 数据的损失范围只作观察记录，不预设时间门槛，也不削弱 WRT-03 的成功后条件。

### Core 初版验收门禁

本门禁保留为原始 Core 路径的验收出口，不等于 BUS-01～MEAS-01 的完整产品验收；声明三种保留、快照、代表访问或基础取值时，还须覆盖对应 UC-20～26 及其正式合同。M3 不是只运行一次大文件实验。验收前须按正式 profile、API 和支持矩阵列明适用规则/用例、目标环境、预定资源/性能门槛及明确排除的可选能力；不能根据已测结果临时降低门槛。现有必需 Core 能力不能仅通过修改适用清单免验，范围变化须先修订 DESIGN/DATA_SPEC。

| 验收面 | 通过所需证据 | 复用追踪 |
|---|---|---|
| 数据及关联 | H/P/F/W 或按第 2 节建立的 profile 适配变体的独立期望；异构保真、有效全零/无效填充、选择保序重复、PA/FMC 与多 Scan 身份正确 | 适用 UC、T-02～T-11/T-21/T-23，记录变体覆盖，排除已替代 T-08 |
| 输入与容量拒绝 | 非法批次修改前拒绝，前缀/extent/历史不变；支持上限和整数溢出明确失败 | T-03/T-13/T-19 |
| I/O 与调用结果 | 真实 HDF5 路径下 push 目标不变、poll 无部分结果、写失败旧数据受保护；绑定错误不混淆提交结果/重试 | T-14、UC-14、3.1 |
| Flush/生命周期/恢复 | 已决定的成功后条件、关闭/封存及错误状态兑现；只读恢复区分声明范围、可信范围、失败与未检查项 | T-12/T-14/T-15 |
| 格式互通与解码 | 正式说明足以独立读取；必要身份/引用/版本/filter 可解释，未知必要能力明确拒绝 | T-01/T-16/T-17/T-21/T-22 |
| 各语言绑定 | 每个声明组合分别构建、双向存取与互读；借用失效、派生视图、GC/关闭、缓冲保活及异常释放有证据 | T-02/T-06/T-14/T-22、UC-14；D-12 支持矩阵 |
| 规模与负载 | 超 100 GB 且工作集超 RAM；完整峰值预算达标；连续写及按已选优先级组织的 Frame/Batch/A-Scan 达到预定指标 | T-18/T-19；D-02/D-03 |
| 可复核交付 | Spec/实现/样例修订、环境、独立期望、原始结果、最小调用示例与已知限制对应一致 | VAL-01 及各执行记录，不要求部署打包 |

适用范围内的 FAIL、NOT_RUN、BLOCKED 或 UNSUPPORTED 均不能计为完整初版通过；已知限制不能掩盖必需能力失败。UC-18 当前仍 BLOCKED，若首发不声明 Scan 映射，应在适用清单中明确不纳入且不计为 PASS；若声明则先完成 D-11 及相应验证。T-20/M4 的可选 GPU 同理，不阻塞无该声明的 CPU Core。

M0 的文档收束、M1 的临时工具可运行、M2 的必要编码互通分别是不同证据，均不能代替本门禁。后续路线图可在该阶段划分上补充工作量、责任与时间，不预先给尚无依据的工期或性能承诺。

### 后续用例编写的输入边界

- 从 DATA_SPEC 的逻辑规则和本文定义的独立预期形成断言，不能从历史路径、状态数字或临时实现反推需求。
- 能由 H/P/F/W 数值、身份、固定引用及有效性/关联语义核对的内容可直接作为逻辑断言依据；具体异常类、结果 shape、位图打包等必须先记录 test-only 选择或等待相应 D 项，不冒充已确定契约。
- test-only 说明须关联 Spec 修订并与产品编码分开；对尚未支持的语义如实报告，不通过改变原始预期让用例通过。
- 未定义的范围与接口行为继续由 D 项管理，不通过增加测试断言隐式确定。
