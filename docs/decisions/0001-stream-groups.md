# ADR-0001：引入同构流组，统一帧级附加记录

- 状态：已采纳（2026-10-24，Spec 0.3-draft）；适用范围由 [ADR-0011](0011-ultrasound-business-boundary.md) 限定为原始波形 Core，并由 [ADR-0016](0016-tiered-core-mode-schemas-and-immutable-seal.md) 降为原始波形物理引擎可选参考抽象（对外改为分扫描类型独立 Schema）：决定 3 的类别限制只描述旧 Core profile（混合范围见 D-13），决定 4 中“原始帧位置必需”改按现行 POS-01（允许无空间位置的记录）
- 规则落点：[逻辑模型](../DATA_SPEC.md#logical-model)、[WAV-01](../DATA_SPEC.md#wav-01)、[PAR-01](../DATA_SPEC.md#par-01)、[POS-02](../DATA_SPEC.md#pos-02)、[PA-01](../DATA_SPEC.md#pa-01)、[FMC-01](../DATA_SPEC.md#fmc-01)、[MAP-01](../DATA_SPEC.md#map-01)
- 仍未决定：同文件/同 Scan 的混合解释（D-13）、HMC/PWI/Sparse 与跨流组矩阵（D-14）
- 补充：[ADR-0009](0009-review-contract-clarifications.md) 把首版 Tx×Rx 矩阵限于单个流组

## 背景

0.2 的粒度是逐条波形流。128 阵元 FMC 有 16384 条流，每条一份固定定义；Batch 布局（D-10）、位图打包（D-08）与 chunk 形状（D-04）都要分别回答"异构怎么办"；单晶/PA/FMC 的解释挂在文件或 Scan 层，同一 Scan 内无法表达"PA + TOFD"这类多组采集。帧级的时间戳、来源 ID 与额外坐标也分散在 D-01/D-02 的不同条目里。

## 决定

1. Scan 与流之间增加**流组** `g`：组内所有流的 dtype、样本数 `S_g`、样本表示与采样间隔一致，逐流差异（起始延迟、事件、接收输出、Tx/Rx 等）以组内**流表**保存。异构只发生在组与组之间；任何单条特殊流都可以独占一个组（`K_g = 1`），表达能力不减少。
2. 流身份仍在 Scan 内唯一（`k`），并静态属于唯一一个组，在组内有固定序号 `q`。逻辑身份 `(Scan,n,k)` 不变。
3. 通道组、PA 声束集、Tx×Rx 矩阵是**组的解释**，不再是文件或 Scan 的单一模式。首版的类别限制（单晶与阵列不混存、PA 与 FMC 不同文件）继续有效，是否放开由 D-13 决定。
4. 时间戳、设备来源 ID、额外坐标等统一为**帧级附加记录**：Scan 内固定描述（类型/版本/字段/单位/来源），每帧一行，与 Frame 在同一提交单元写入。原始帧位置是其中必需的一项（POS-01）；其余各项的必要性与缺值表示仍属 D-01。

## 理由与证据

- 现有开放格式都以"组"为单位共享时间轴与长度：MFMC v2.0.0 的 sequence 定义为"除探头位置外全部采集参数固定"，A 扫轴 `MFMC_DATA [N_T,N_A,N_F]` 要求公共时间轴，每条 A 扫引用发射/接收法则；Evident NDE 4.4 的 group 是"一个或多个探头 + 一种采集策略"，官方样例在一个文件内保存 2 个 PA 探头与 1 对 TOFD。
- 商用仪器普遍多组同时采集（OmniScan X4 最多 8 个 TOFD/PA 组；TOPAZ64 可同时进行两路 FMC、PA 与 TOFD）。这些事实只说明组的普遍性，不自动放开首版类别限制。
- 一个组自然对应一个 `[N,K_g,S_g]` 数据集、一个 `[N,K_g]` 位图与一张流表；Batch 就是每组一个稠密缓冲；FMC 矩阵视图是对组按 π 重排。

## 后果

- PAR-01 的"流专属设置每条流保存一次"改为"按组以流表保存"，避免逐流对象。
- MAP-01 的参考映射以组为物理单元；chunk 尺寸可按组选择。
- PA 声束数改用符号 `N_b`，`B` 只表示 Batch 帧数。
- 原逐流异构用例（H、异构 FMC）改为跨组异构，独立期望值不变。
