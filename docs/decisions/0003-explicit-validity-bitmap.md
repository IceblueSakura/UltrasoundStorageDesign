# ADR-0003：写入必须提交完整有效性位图；样本按数值语义交付

- 状态：已采纳（2026-10-24，Spec 0.3-draft）
- 规则落点：[STA-01](../DATA_SPEC.md#sta-01)、[WAV-02](../DATA_SPEC.md#wav-02)、[WRT-01](../DATA_SPEC.md#wrt-01)
- 仍未决定：位图在接口与文件中的打包和位序（D-08）

## 背景

0.2 规定有效性位默认为 0，`valid=0` 槽位提供的样本被忽略。两条规则叠加后，调用方漏传或少传位图时，整段数据会被零填充，而调用照样返回成功；WRT-01 要求校验"位图关联"，UC-15 又把"未设置的位"等同于显式无效，两位实现者会做出不同的选择。位图如果靠 fill value 实现，"缺行"与"全部无效"也无法区分。另外，"无隐式转换"没有说明保值的字节序转换算不算转换。

## 决定

1. 每次写调用必须为调用内每个 Frame 的每个槽位显式提交有效位；位图缺失、长度不符或与组/流身份对不上，属于结构错误，整个调用被拒绝。
2. "默认值 0"只描述未写入的存储初值，不是写接口的默认行为，也不能掩盖已提交范围内的缺行。已提交行能否被检测，由提交记录与校验和保证（ADR-0002）。
3. 提供可选的严格模式：`valid=0` 的槽位提供了非零样本时报错。默认关闭；关闭时这类样本按 STA-01 被忽略并零填充。
4. 样本按数值语义交付：文件内的字节序是存储细节，API 交付调用平台原生字节序的数值，同一数值保持不变；改变数值或位宽的转换仍然禁止。

## 理由

漏传位图造成的静默零填充无法事后发现，代价远大于调用方多传一个参数。显式位图也让"真实全 0"与"无效零填充"在输入端就能区分。

## 后果

- UC-15 增加"位图缺失或长度不符则整个调用被拒绝、前缀不变"的反例；"默认未设置的位"不再是写接口行为。
- 便捷接口（例如"本批全部有效"）可以由绑定提供，但它也属于显式声明。
