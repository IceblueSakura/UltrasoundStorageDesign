# ADR-0009：评审补充的三项契约

- 状态：已采纳（2026-10-25，用户确认）
- 规则落点：[FMC-01](../DATA_SPEC.md#fmc-01)、[CORE-01](../DATA_SPEC.md#core-01)、[LIF-01](../DATA_SPEC.md#lif-01)；D-14
- 细化：[ADR-0001](0001-stream-groups.md)、[ADR-0004](0004-concurrency-and-borrow-scope.md)、[ADR-0002](0002-durability-and-failure.md)

## 背景

复核 `0.3-draft` 时发现三处规则各有两种读法。当时先按下述读法写入 DATA_SPEC，并请用户确认；用户已确认。

## 决定

1. **Tx×Rx 矩阵限于单个流组。** 首版一个 Tx×Rx 矩阵的全部收发对都在同一个流组内；跨组（异构）矩阵的解释归属与声明方式并入 D-14。
2. **SDK 检测并拒绝同一文件上的 Writer 与 Reader。** 文件被 Writer 打开期间，无论来自同一进程还是其他进程，打开该文件的 Reader 都须被 SDK 拒绝。这是 SDK 的行为，不只是调用约定。
3. **失败态时活动的 Scan 保持未完成。** Writer 进入失败态时仍在活动的 Scan，带失败标记封存后仍是未完成状态；读取方看到它的已提交范围与失败标记。带失败标记封存同样以等价 Flush 交付已提交范围。

## 理由与证据

1. 流组内 dtype、样本数与采样解释一致（ADR-0001），单组矩阵总能满足 FMC-02 的稠密 `[Tx,Rx,Sample]` 视图。跨组矩阵还须先回答由哪个组声明 I、J、π，以及异构收发对怎样交付。目前没有需要跨组矩阵的已知场景，与 HMC/PWI/Sparse 一并决定代价最小。
2. HDF5 文件锁覆盖不了这条规则：
   - 同一进程内，对已以写方式打开的文件再做只读打开时，HDF5 直接复用已打开的文件（`H5Fint.c:1934-1953`），文件锁不起作用。
   - 环境变量 `HDF5_USE_FILE_LOCKING` 可以关闭文件锁，且优先于 fapl 设置（`H5Fint.c:97-102`）。

   M1 中，Writer 打开期间另一进程的打开被 HDF5 文件锁拒绝，但这只覆盖跨进程且未关闭文件锁的情况（[实验报告](../../experiments/m1/REPORT.md)）。
3. “完成”表示 Scan 的存储记录正常闭合（LIF-01）。失败态下无法确认预定的帧都已写入，标记为完成会让读取方误以为扫描正常结束。M1 的写失败实验中，带失败标记封存后该 Scan 仍为 active，72 个已提交帧可读，失败标记可见。

## 后果

- D-14 包含跨流组矩阵；FMC 样例只使用单组矩阵。
- 实现须自带检测机制，同时覆盖进程内与跨进程，不能依赖可被关闭的 HDF5 文件锁；具体机制属实现，跨平台部分随 D-12 取证。T-24 须覆盖同进程打开与关闭 HDF5 文件锁两种情况。
- D-10/D-15 的状态表须包含“失败态时活动的 Scan”。
