# ADR-0010：公开 API 的稳定原则

- 状态：已采纳（2026-10-25，用户认可）；实现语言、静态自包含分发、首版 `.NET` 绑定、三套版本解耦与 `1.0` `abidiff` 门禁已由 [ADR-0020](0020-implementation-stack-bindings-and-versioning.md) 补齐
- 规则落点：[API-01](../DATA_SPEC.md#api-01)、[SDK_CONTRACT.md](../SDK_CONTRACT.md)；D-10、D-12
- 仍未决定：具体 C11 函数签名与错误码枚举（D-10）、精确 OS/编译器最低版本矩阵（D-12）

## 背景

用户确定本阶段以公开 API 的稳定性为重点（ADR-0008），并认可它包括两层：调用语义稳定，即失败语义、借用规则等已定行为不随实现改变；接口演进兼容，即以后增加能力时，不改动已有签名和既有调用的含义。消费端包括 C/C++、Python 与 Windows .NET Framework 4.8（D-12），本阶段只在 Linux 上验证。

## 决定

1. **C ABI 是原生库唯一的稳定边界。** 对象以不透明句柄表示；公开头文件不出现 HDF5、C++ 标准库或异常类型，C++ 异常不穿过该边界。C++ 便利层（若提供）是头文件内的薄封装，不另成稳定边界。
2. **64 位长度与显式缓冲。** 长度、偏移、计数与帧号一律使用 64 位整数；调用者缓冲以“指针＋字节长度”描述。
3. **可扩展参数与预留标志。** 选项与描述结构体以自身大小（或版本号）开头，新字段只追加，SDK 按调用者声明的大小读取，未提供的字段取默认值。可能演进的调用带 `flags` 或选项参数，未识别的标志位明确报错，不静默忽略。
4. **稳定的错误结果。** 错误码数值一经发布不再复用或改变含义，并归入稳定的分类；写入类调用另外报告提交状态（已提交、未提交或未知）；错误消息文本不属于稳定契约。

## 理由

- C++ ABI 随编译器与标准库变化（MSVC 与 GCC 互不兼容）；P/Invoke 只能调用 C 导出函数，ctypes/cffi 也是如此。HDF5 类型出现在公开头文件里，会把 HDF5 的版本与构建选项变成 SDK 接口的一部分。
- R-09 要求帧轴覆盖 u64 范围，单个 Batch 也可能超过 2 GiB；.NET Framework 的托管数组上限约 2 GiB，更大的数据只能经非托管内存交付（D-12）。“指针＋长度”能同时承载非托管内存、Python 缓冲协议与 C/C++ 数组，SDK 也能据此检查容量（BUF-01）。
- 已知的演进方向都需要新增参数，例如 Flush 的设备同步（ADR-0008）、可能的内存分配方式（角度 15，暂缓）、新 codec。以大小开头的结构体与预留标志让这些扩展不必修改签名，旧调用者也不必重新编译；未识别的标志位报错，可以防止旧版本库静默忽略新语义。
- IO-01 与绑定层失败（D-10/D-12）要求调用者能区分已提交、未提交与未知。错误码与分类稳定，调用者才能按分类处理，而不必解析消息文本。

## 后果

- DATA_SPEC 新增 API-01；D-12 的“原生语言/ABI”收窄为实现语言与绑定方式；D-10 在此原则下确定错误码清单、分类与提交状态的表示。
- 角度 16 只保留版本与兼容规则；角度 13 的“原生边界”候选关闭，改为绑定的构建方式。
- 本记录不冻结任何函数签名，也不表示已有实现。
