# ADR-0014：统一指定代表选择函数与快照实际来源分离

- 状态：已采纳业务边界（2026-11-17）；部分被 [ADR-0016](0016-tiered-core-mode-schemas-and-immutable-seal.md) 调整（多回波代表选择移出 Core 归独立可选扩展层；原始文件 Write-Once 不可变，快照历史来源不变原则保留），选择函数与配置机制继续待定。
- 规则落点：[ACCESS-01](../DATA_SPEC.md#access-01)、[SNAP-01](../DATA_SPEC.md#snap-01)、D-16/D-17。
- 来源：UMS 整体设计审阅后的用户交互确认；用户要求先调整现有决策与规划，再确认下一步设计方向。
- 替代范围：ADR-0012 的“最新有效／到达先后”方向及原 ACCESS-01 的固定内建规则表述；同类有效候选、不以无效波形兜底等未冲突边界保留。

## 背景与决定

同一位置可能关联多组数据。用户要求顶层 API 对此无感，通过统一指定的函数处理选择，而底层 API 能获取全部已保留波形及来源。因此不再预选最新值、最大值或到达顺序，也不要求每次普通访问都展开候选或传入选择规则。

全局变量等是指定函数方式的举例，不是已冻结的实现要求。当前设计关注访问分层及数据关系，函数细节、配置作用域、签名、注册和变更机制均留待对应合同，不建立通用策略框架。

用户同时确认：点击已保存 C 扫快照的点，默认查看该数值实际关联的来源波形；来源未保留时提示不可用，不取同位置的另一条波形替代。因此按位置选择当前代表，与追溯历史快照实际来源是不同目的。UMS 定义默认查看行为，SDK 提供关联与访问能力，选择函数变化不能反向改变已有快照的来源。

## 后果与未决范围

- 顶层便利访问不丢失底层完整性；相同数据、函数及选择条件下结果一致，原始事实及有效性不变。
- 快照来源不依赖当前选择重新推断；不据此要求仅特征成果保存原波形，也不恢复逐批次在线计算参数历史。
- 多来源计算结果的关联组织、快照分组及替换粒度仍待 D-16；具体选择函数及配置合同仍待 D-17。不由单来源例子冻结一数值一波形的普遍模型。
- 规划验证访问分层、选择一致性、来源保持及未保留状态；未决算法不得由测试默认值先行定案。
- 本次仅同步设计与规划，未实现接口、修改或运行旧代码、实验、测试及 benchmark，不据旧证据宣称新增能力已验证。
