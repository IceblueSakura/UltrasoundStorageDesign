# ADR-0015：开源 SDK 承担跨系统的扫描数据交付

- 状态：已采纳业务边界（2026-11-19）；跨文件组织另行决策，具体合同与实现继续待定。
- 规则落点：[BUS-01](../DATA_SPEC.md#bus-01)、[REL-01](../DATA_SPEC.md#rel-01)、[SCAN-01](../DATA_SPEC.md#scan-01)、D-11、D-19；需求 [R-20](../DESIGN.md#r-20)。
- 来源：UMS 模块划分讨论中的用户确认（2026-11-19）。

## 背景

UMS 划分模块时讨论了“正式数据分发”的归属。此前 SDK 已定位为独立维护并开源的超声数据规范存取库，但使用者范围只隐含为 UMS。用户明确：SDK 也应承担部分分发功能，开源 SDK 须让其他系统能完整读取和创建扫描数据。

## 决定

1. **三类使用者。** SDK 面向：UMS 自身的保存与重开；其他扫描系统通过 SDK 创建扫描数据；其他系统集成及外部数据分析通过 SDK 完整读取已保存的扫描数据。
2. **跨系统交付归 SDK，执行期进程内分发归调用方。** SDK 承担以文件为载体的跨系统数据交付。扫描执行期间把采集数据同时交给计算、保存与显示的进程内分发，由 UMS 等调用方负责；SDK 不提供该分发、上位机内存池或消费者寿命管理。
3. **与调用方概念解耦。** 写入与读取合同不依赖 UMS 的 Run、工件、Workflow 或业务数据库；文件中保存的超声数据仅凭本规范与 SDK 即可解释。
4. **完整读取。** 读取覆盖文件中保存的全部超声内容：原始波形、必要解释信息、位置及其状态、数据关系和 C 扫快照。ACCESS-01 的重点访问场景只决定优化重点，不限定外部读者可取得的内容。
5. **单写者，只读已封存文件。** 保持一个文件一个 Writer；读取面向已封存文件及 LIF-02 的显式恢复视图，不支持采集中读取增长文件。
6. **暂不规划跨文件扫描。** 本版数据关系在单个文件内解析。需要跨文件的需求，例如复检指向另一份已封存文件中的原扫描，留待后续 dataset/group/多文件组织决策（D-19）。

## 理由

- 开源数据规范的价值在于其他系统能独立写入和读取；若读写合同依赖 UMS 概念，外部使用者无法解释数据。
- 执行期分发与具体设备、计算和显示的寿命紧密相关，属于采集系统的职责；纳入 SDK 会违背 BUS-01 不承载设备与任务流程的边界，并使 SDK 失去功能单一的约束。
- 单写者与封存后读取已是既有约束（ADR-0004/0009、LIF-01），外部使用不需要放宽。
- 跨文件组织涉及数据集、组与多文件的整体模型，用户将另行规划；提前定义单项引用协议会预先约束该决策。

## 后果与未决项

- BUS-01 增加使用者范围与跨系统交付边界；REL-01 与 SCAN-01 注明跨文件关系待 D-19。
- REL-01 的复检关系需求不变；原扫描位于同一文件时按 D-11 细化，位于其他文件时随 D-19 一并决定。
- UMS 打开其他系统创建的扫描数据属于 UMS 应用功能，当前不需要且优先级很低；它不改变 SDK 对任何合规文件提供读取的要求。
- 新增要求“文件内超声数据仅凭 SDK 可解释”与 D-07（正式格式及独立读取）、D-09（必要解释信息）相关，具体证据随这两项闭合。
