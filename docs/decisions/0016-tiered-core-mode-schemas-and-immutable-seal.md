# ADR-0016：两层 SDK 架构、分扫描类型独立 Schema 与 Write-Once 不可变封存

- 状态：已采纳模型与边界决定（2026-11-27）；首版范围、业务模型细化、物理引擎与工程合同已由 [ADR-0017](0017-core-v1-scope-and-domain-model.md)～[ADR-0020](0020-implementation-stack-bindings-and-versioning.md) 定型，具体 wire 编码与 C11 签名在 M2 落地。
- 规则落点：[DOC-01](../DATA_SPEC.md#doc-01)、[CORE-01](../DATA_SPEC.md#core-01)、[BUS-01](../DATA_SPEC.md#bus-01)、[RET-01](../DATA_SPEC.md#ret-01)、[REL-01](../DATA_SPEC.md#rel-01)、[SNAP-01](../DATA_SPEC.md#snap-01)、[ACCESS-01](../DATA_SPEC.md#access-01)、[MEAS-01](../DATA_SPEC.md#meas-01)、[SCAN-01/02](../DATA_SPEC.md#scan-01)、[ID-01](../DATA_SPEC.md#id-01)、[LIF-01](../DATA_SPEC.md#lif-01)、D-01/D-07/D-11/D-15（关闭）/D-16/D-17/D-18；需求 [R-01](../DESIGN.md#r-01)、[R-12](../DESIGN.md#r-12)、[R-17](../DESIGN.md#r-17)、[R-18](../DESIGN.md#r-18)、[R-19](../DESIGN.md#r-19)。
- 来源：用户对 SDK 产品边界与模型待决策问题 Q1–Q7 的统一裁决（2026-11-27）。

## 背景

此前草案将“基础窗口取值（MEAS-01）”、“代表波形选择函数（D-17）”以及“封存后原地热替换原始大文件中的 C 扫快照（Q6）”等职责纳入 SDK Core，同时通过单一抽象模型（`EventDefinition + WaveformStream + StreamGroup`）承载单晶、相控阵、仅特征与混合扫描，并预设了不依赖 SDK 即可由外部工具（如 `h5py`）直接按路径理解内部数据的包袱。上述负担在 Q1–Q7 整理中暴露出职责耦合与原地修改崩溃风险。

用户于 2026-11-27 明确了 SDK 的核心定位与边界，并一次性裁决了 Q1–Q7 全部模型问题。

## 决定

1. **两层 SDK 架构：Core + 独立可选扩展层。**
   - **SDK Core**：极薄公共容器外壳 + 共享底层物理 I/O 引擎（分块、压缩、逐块校验、Flush 崩溃保护、`LIF-02` 恢复）+ 按扫描类型独立清晰的 Schema + Write-Once 封存只读 + 原生高效寻址（触发序号 / 声束 / 通道 / 样本窗口，以及可选离散单元列 `CellCoord[Frame]`）。
   - **独立可选扩展层（只消费 Core 只读 API，不进入 Core 文件格式与写入路径）**：
     - **选峰扩展**：原 MEAS-01 窗口内峰峰值、前沿位置/时间与幅值提取等基础取值能力；
     - **3D 空间索引与多回波选择扩展**：基于 Core 原始 3D 坐标按需构建独立旁路空间索引，按 `(x, y, z)` 查出 `0~N` 条候选波形并执行可插拔的多回波代表选择策略（替代原 Core 内置代表选择函数 D-17）。
2. **自描述边界澄清。** 自描述指“仅凭文件与 SDK 即可完整解释数据并按触发序号、3D 空间坐标、声束号等参数访问所需内容，不依赖 UMS 主系统或业务数据库”；不再约束外部第三方工具（如 `h5py`）不经 SDK 裸翻内部路径，物理布局可彻底服务于读写效率。
3. **分扫描类型独立 Schema（调整 ADR-0001）。** 底层共享同一套物理 I/O 引擎与公共积木（`SignalDescriptor`、帧位置及同步等级、`VendorExtension`、可选 Write-Once 伴生快照）；对外按扫描类型定义各自独立、贴合其物理维度的 Schema（首版聚焦单晶与相控阵，后续按需扩展 FMC 与仅特征采集）。原 `EventDefinition + WaveformStream + StreamGroup` 模型降为物理引擎可选参考抽象，不再作为强制统一对外模型。
4. **闭合 Q1–Q7 全部模型问题：**
   - **Q2（中立交付容器，修订 ID-01 / SCAN-01）**：SDK 为每份文件分配不变的文件实例 UUID，Scan、区域、伴生快照各自携带稳定 ID；工件身份与 Run 退为可选带类型元数据，不再强制必填。
   - **Q3（区域与关系拆分，拆分 D-11）**：区域（`Region`）作为文件内独立实体由 Scan 引用（可表达“已声明未采集”的空区域及多 Scan 归属同一区域）；跨文件复检关系并入 D-19（定案前由 UMS 持有）；Run 到 Scan 的映射留在调用方。
   - **Q1（可选离散单元列 `CellCoord[Frame]`）**：Core 支持写入方可选声明离散单元整型列 `CellCoord[Frame]`（无规则布局时省略），支撑无伴生快照的纯全波文件按格查回 `0~N` 条波形，SDK 不做浮点坐标分箱；3D 空间索引归独立扩展层/旁路索引。
   - **Q4（缺口与结束状态）**：Scan 显式声明结束状态（正常完成 / 主动提前结束 / 故障中止及原因），配合未执行空区域实体共同表达部分成果与缺口；原始波形槽位仍保持单一有效位（STA-01）。
   - **Q5 & Q6（Write-Once 封存只读与快照边界，修订 SNAP-01 / LIF-01）**：原始文件封存后彻底不可变（Write-Once）——① 允许封存前 Write-Once 写入一次采集期伴生 C 扫快照（加速重开浏览，保留实际来源）；② 封存后禁止原地改写或热替换原始文件内的快照，离线重算产生的新增/替换派生快照一律写入旁路派生文件或另存新目标；③ 仅特征采集走独立不可变 Schema，封存后不可被重算覆盖。
   - **Q7（关闭 D-15）**：段内暂停留在同一 Scan 内；首版不支持封存或干净关闭后再重开追加原始波形，关闭 D-15。

## 理由

- 剥离选峰与 3D 空间索引/多回波选择到只读扩展层，既满足外部独立分析需要，又避免把算法判据、C ABI 回调注册或建树耗时拖入 Core 写入与文件格式。
- 取消 `h5py` 裸读约束并改用分扫描类型独立 Schema，能直接以最贴合单晶、相控阵等物理结构的布局平衡灵活性与读写效率。
- 原始文件 Write-Once 封存只读彻底消除了已封存大文件原地修改快照带来的崩溃损坏、读写互斥锁与采集记录被误覆盖风险。

## 后果与未决项

- `ADR-0001` 的同构流组模型降为原始波形物理层可选参考抽象；`ADR-0011`、`ADR-0012`、`ADR-0014` 中关于“Core 内置代表选择/基础取值”及“封存后原地替换原文件快照”的部分由本决定调整，其余已采纳边界保持有效。
- D-15 已关闭；D-16 收窄为 Write-Once 伴生快照与旁路派生快照协议；D-17、D-18 移出 Core 归独立可选扩展层；D-11 聚焦文件内 Region 实体与引用作用域，跨文件复检归 D-19。
