# ADR-0019：列式位置编码、位图与编码链 Profile 及 Core 读写合同

- 状态：部分被 [ADR-0021](0021-hdf5-simplification-wal-push-only-and-ndt-fixes.md) 修订（2026-11-28）：帧元合并大块解耦并新增 `CellCoord` 排序索引、仅保留 `stored_xxh3`、砍去 C ABI `poll` 与纯选择层、离散帧清单延至 v0.2、明示 `push` `staging_budget`。
- 规则落点：[WAV-01](../DATA_SPEC.md#wav-01)、[WAV-02](../DATA_SPEC.md#wav-02)、[STA-01](../DATA_SPEC.md#sta-01)、[POS-01/02](../DATA_SPEC.md#pos-01)、[READ-02/03](../DATA_SPEC.md#read-02)、[CMP-01](../DATA_SPEC.md#cmp-01)、[SDK_CONTRACT.md](../SDK_CONTRACT.md)。
- 来源：用户在 `ADR-0017`/`ADR-0018` 之后对 P1 数据编码与 Core 读写合同的统一拍板（2026-11-27）。

## 背景

在物理引擎与业务模型收口后，位置缺失表达、位图 C ABI 传递方式、首发 `dtype`、逐块校验算法、内置压缩链以及 Batch 帧选择语法直接决定 C11 头文件设计与 HDF5 wire 格式，需要在进入 M2 之前明确选型。

## 决定

1. **位置三态、同步等级、`CellCoord` 与帧级附加记录采用固定列式 Schema + 显式状态位（闭合 `D-01` 模型）。**
   - `Scan` 固定定义静态声明位置模式：`None`（纯时序无空间位置）或具名位置结构（原始编码器计数 / 笛卡尔 / 姿态等，含单位与参考系）以及 Scan 级默认同步可靠性等级（若逐帧可变，允许附带帧级同步等级列）。
   - 启用位置时，每帧携带显式 `pos_valid` 状态位（`1=有效, 0=未知/采集失败`，无效时位置槽位零填充，不靠浮点 `NaN` 推断无效，避免破坏整数编码器原始值）。
   - 可选离散单元列 `CellCoord[Frame]` 为定长整型列（`int32[1..3]`）并配帧级有效/无归属标记（合法表达转场/跳点帧无网格归属），SDK 不做浮点分箱。
   - 其他帧级附加记录在 `Scan` 初始化时声明列清单，按列声明 `required` 或 `nullable`（带显式 valid 位），同 Frame 同一提交单元写入；首版禁止晚到补写。
2. **有效性位图、严格模式与越界/空选择合同（闭合 `D-08` 与 `D-10` 错误边界）。**
   - 存储层与 C ABI 统一采用 **packed bitset**（每帧每流组 `ceil(K_g / 8)` 字节，**LSB-first** 位序，高尾部位强制清零并在写入与读取校验），避免 8× 内存带宽放大并与未来 GPU bitmask 对齐；高级语言绑定（如 `.NET`）按需提供转 `bool` 的便利视图。
   - **严格模式**（`valid=0` 槽位输入非零样本时拒绝整批写调用，[ADR-0003](0003-explicit-validity-bitmap.md)）按 **Writer / Scan 创建选项**配置（默认关闭，关闭时自动零填充）。
   - 异构多流请求发生局部样本/流越界，以及空选择请求（如 `B = 0` 或空流列表），一律**整体拒绝**并返回明确错误码（不返回部分成功结果），与 [IO-01](../DATA_SPEC.md#io-01) 强原子语义一致。
3. **首发支持 `dtype` 与逐块校验算法（收口 `D-02`/`D-07`）。**
   - 首发 `dtype` 集合：**`{i8, u8, i16, u16, i32, u32, f32}`**。整数按原生数值语义无损保真；`f32` 按 IEEE-754 **逐位无损保真**（不做 `NaN` payload 规范化或 `-0.0` 改写）。首版显式拒绝 `f64` 与复数类型，待后续 Profile 扩展时补充。
   - 物理块存储字节与解码后字节校验和统一采用 **`XXH3-64`**（64 位强抗碰撞、纯 SIMD >20 GB/s、无专有 CPU 指令依赖），彻底消除无压缩静默错值并把两阶段读校验成本降至可忽略水平。
4. **精简现代无损压缩编码链（收口 `D-04`/`D-07`/`CMP-01`）。**
   - 首版内置且仅支持三条标准编码链：**`none`**、**`shuffle + zstd`（默认，低压缩级别如 level 1–3）**、**`shuffle + lz4`（高吞吐实时采集可选）**；不再内置 `deflate`（[ADR-0016](0016-tiered-core-mode-schemas-and-immutable-seal.md) 已解除外部 `h5py` 裸读约束，缩小维护与验证矩阵）。
   - 全部压缩块按标准 HDF5 注册 filter ID（`H5Z_FILTER_SHUFFLE`、`32015` Zstd、`32004` LZ4）声明于数据集 filter 链，由 SDK 静态内置对应解码器，同时为未来 M4 的 GPU `nvCOMP`（原生支持 Zstd/LZ4）铺平路径。
5. **Core Batch 读取、跨组交付与块几何/容量查询合同（收口 `D-10` 与角度 15）。**
   - Batch 帧选择同时支持 **连续区间 `(start, count)`** 与 **离散帧索引清单 `[n_0, n_1, ...]`**（保序保重复；SDK 内部按物理块合并去重读盘后再散射回目标顺序，直接加速 D 扫跨行切片与 `CellCoord` 查回的离散帧集）。
   - 跨流组交付采用 **每流组独立稠密缓冲**（不强行拼成单一大缓冲加偏移表）。
   - 提供**不使 `poll` 借用失效**的块几何与字节容量查询 API（返回 `F_chunk`、`K_chunk`、单帧/指定 Batch 的样本、位图与帧记录字节数），直接服务上位机预分配内存池（如 UMS `Batch-of-SoA`）对齐 `push` 读取。

## 理由

- 显式 `pos_valid` + 列式 `required/nullable` 兼顾原始整数编码器与列式压缩效率，杜绝浮点哨兵值滥用。
- `XXH3-64` + `shuffle+zstd`/`shuffle+lz4` 在 CPU 侧比 `CRC32 + deflate1` 具备数倍吞吐与压缩优势，且零障碍衔接未来 GPU 解压。
- 离散帧清单内置按块合并解码，消除了 D 扫和 `CellCoord` 命中多点时调用方循环单帧读取带来的重复解压开销。

## 后果与未决项

- 原 `DECISION_DIRECTIONS.md` 中角度 3、4、7、8、15 的工程选型全部闭合，正式进入 [SDK_CONTRACT.md](../SDK_CONTRACT.md)。
- 仍待补齐的事实与细化项：真实 UMS 设备最大 Frame 规模与全链路峰值内存预算（`D-02`）、C11 具体结构体与错误码清单（`D-10`），以及 HDF5 精确路径/属性编码规范（`D-07`）。
